### 2.1 能力边界清单（全册硬约束，逐条写清，不得写反）

1. **定位**：Suricata 是 **IDS / IPS / NSM**（入侵检测 / 入侵防御 / 网络安全监控）引擎，
   **不是防火墙、不做 IP 转发、不做路由**。内联阻断依靠 **NFQUEUE / AF_PACKET 桥接的 verdict**
   （见 `src/source-nfq.c`、`src/runmode-nfq.c`、`src/source-af-packet.c`），
   由内核 / 桥接对端决定是否放行；IDS 旁路模式只告警不丢弃。
2. **runmode**：多线程运行模式分 **workers / autofp / single**（见 `src/runmodes.c`、`src/runmode-*.c`），
   流亲和（flow affinity）、RSS / fanout 负载均衡与队列分配共同决定扩展性，
   不得把「加线程」写成必然线性提速（原理见 06-13）。
3. **可见性**：只对**自身解码并重组到的流量**做检测；**TLS 等加密载荷不可见**，
   能拿到的是握手元数据、证书、SNI、JA3 等（见 `src/output-json-tls.c`、`rust/src/ja4.rs`，
   具体字段需对照实际版本核验），不得宣称能读到 HTTPS 明文正文。
4. **规则与输出**：规则语法**兼容 Snort 但有自有扩展**（见 `src/detect-parse.c`、
   `src/detect-engine-register.c`），**不能宣称 100% 兼容**；**EVE JSON 是主要输出**
   （`src/output-json*.c`），fast.log / stats.log / pcap-log 等为辅助输出。
5. **Hyperscan**：是**可选 MPM 加速**（`src/util-mpm-hs.c`，构建开关见 `configure.ac`，
   选项名需对照实际版本核验），**缺失时回退 AC 等其他多模式匹配实现**
   （`src/util-mpm-ac*.c`），不得写成必需依赖或唯一实现。
6. **Rust**：`rust/` 与 Cargo 是**构建的一部分**（`rust/Cargo.toml.in`、`rust/cbindgen.toml`、
   `rust/src/`、`rust/Makefile.am`），大量应用层解析器与 EVE 构造在 Rust 侧，
   不得把 Suricata 写成纯 C 项目。
7. **抓包后端**：AF_PACKET / DPDK / PF_RING / Netmap / pcap 的**能力与环境要求差异大**
   （见 `src/source-*.c`、`src/runmode-*.c`）；**DPDK 需独占网卡、大页与 EAL 参数**，
   Netmap / AF_XDP 有内核与驱动要求，pcap 多用于离线或低速率；
   PF_RING 在当前 main 快照是否仍为受支持后端、对应源文件与启用方式，
   **需对照 `configure.ac` 与 `src/source-*.c` 实际版本核验**，不得编造 `source-pfring.c`。
8. **suricata-update**：与内核主程序是**分仓 / 独立工具**（独立仓库与独立发版；
   本快照内虽含 `suricata-update/` 目录，工具本体仍独立），
   负责规则集下载与合并，不参与 `src/` 主程序编译，不得写成主程序的子命令或内建模块。
9. **性能**：任何吞吐、pps、丢包率、内存占用数字一律标注「**需在目标机型实测**」，
   **不给绝对值**；基准方法见 08-01，调优见 08-02。

## 5. 配图语法（会被编译成 Word 可编辑形状 + .drawio 源文件）

每个图块用下面这种 DSL，**不要用 mermaid、不要插入图片、不要画 ASCII 图**：

```text
:::figure id=06-01-01 | name=包处理流水线四阶段与输出落点 | dir=TD
node n1 "抓包后端<br/>source-*.c" blue
node n2 "解码与流重组<br/>decode / stream-tcp" teal
node n3 "应用解析与检测<br/>app-layer / detect" purple
node n4 "EVE JSON 落盘<br/>output-json" green
edge n1 -> n2 "Packet 入队"
edge n2 -> n3 "重组后的流"
edge n3 -> n4 "告警与事件"
:::
```

规则：
- `node <id> "<文字>" <色调>`，色调只能是 blue / teal / amber / purple / gray / red / green。
- `edge <from> -> <to> "<标签>"`；`dashed` 表示辅助 / 回查关系，写在标签**之前**；标签可省略。
- 节点文字用**双引号**包裹，内部不要出现双引号；可用 `<br/>` 换行。
- **单行显示宽度 ≤ 38**（中文按 2、英文按 1 计），超长必须用 `<br/>` 折成多行；不要把整句话塞进一个节点。
- 每张图节点数 **≤ 10**、边数 **≤ 12**；信息多就拆成两张图，不要堆一张。
- 节点 id 只用字母数字下划线，且块内唯一；**每个节点都必须至少连一条边**（禁止孤立节点）。
- **禁止** subgraph / classDef / style / 链接语法。
- 首行 `:::figure ...` 与末行 `:::` 必须各占一行。
- `id` 全局唯一，格式固定 `<篇章号>-<两位序号>`，如 `07-05-01`；00 总纲的图为 `00-01-01`。
- 正文引用图时写「图 07-05-01 …」，**必须与图 id 完全一致**（图题、正文引用、`.drawio` 文件名三者同源）。
- 每篇至少 1 张图；每册图数不少于篇数，关键篇可 2 张。
- 图块之前要有引导句（「…的处理链路见图 06-01-01」）。
- 色调语义在本套资料内统一：`blue` 输入 / 接口、`teal` 解码与流、`amber` 规则与编译产物、
  `purple` 检测引擎、`green` 输出与运行时、`red` 故障 / 瓶颈、`gray` 辅助与外部依赖。
