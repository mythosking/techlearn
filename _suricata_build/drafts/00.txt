## 1. 结构设计与评审结论

本套资料沿用 VPP / DPDK / OpenVPN / wireguard-windows / Hyperscan 五套资料集已验证的组织逻辑：
**按维度分册 → 唯一权威源去重 → 三类骨架 → `文件号-篇号` 编号 → 工具书前置于原理 → 运维收尾**。
针对 Suricata 作为「带抓包、解码、流重组、应用层解析、检测与输出全链路的 IDS/IPS/NSM 引擎」的特点，做了五处调整。

| 决策 | 理由 | 落地方式 |
|---|---|---|
| 03 册定为「集成与部署」 | Suricata 是常驻进程，配置、规则集、日志管道与 IPS 内联决定它能否跑起来 | 03 全册按 C 实战型写：首次 IDS → yaml 主干 → 规则集 → EVE 管道 → IPS 内联 → 容器与高可用 |
| 04 册定为「参数与 API 手册」 | 本项目的「配置」全部体现为 configure 选项、suricata.yaml 段、规则关键字与命令行/RPC | 04 成为构建选项、yaml 参数、规则关键字、命令与返回码的唯一权威源 |
| 05 册前置于 06 | `Packet` / `Flow` / `Signature` / `DetectEngineCtx` 是理解检测与输出流水线的前置知识 | 05 定位「工具书·随查」，不参与线性阅读主线 |
| 06 册增加到 14 篇 | 核心复杂度集中在包处理流水线：抓包 → 解码 → 流重组 → 应用解析 → 规则编译 → 检测 → 输出 → IPS → runmode | 06 用 6 篇讲流水线各段、4 篇讲检测与状态、4 篇讲输出/内联/线程/扩展 |
| 07 册按 `src/` 真实目录设 13 篇 | 模块边界与源码目录一一对应，避免出现「按概念编模块」的虚设章节 | 每篇对应一个真实目录族，给文件清单与关键入口 |

评审中明确排除的做法：

| 级别 | 曾经的风险 | 本套的处理 |
|---|---|---|
| 结构 | 按功能平铺 65 篇、无权威源，导致 yaml 参数与规则关键字在多个文件重复 | 04 / 05 / 06 / 07 / 08 各定唯一权威源，其余册交叉引用 |
| 骨架 | 手册型章节套论述型骨架，出现空泛「背景与动机」 | 分 A 论述 / B 手册字典 / C 实战三类骨架 |
| 边界 | 把 Suricata 写成防火墙、或宣称能读 TLS 加密载荷明文 | 01-01、06-12、08-05 三处明确 IDS/IPS/NSM 定位、不做转发、加密载荷不可见 |
| 规则 | 宣称与 Snort 100% 兼容，或把 suricata-update 写成主程序内建命令 | 01-02、04-05 写明语法兼容但有扩展；07-11 写明规则工具独立发版 |
| 抓包 | 把 DPDK 写成可与普通网卡即插即用、不提独占网卡 | 02-04、06-02 写明后端环境差异、DPDK 独占网卡与大页要求 |
| 性能与版本 | 给绝对吞吐数字，或编造具体版本号 | 08 全册标注「需在目标机型实测」；版本统一写「上游 main 快照（2026-11 抓取）」 |

## 2. 唯一权威源与去重规则

本套资料按内容性质划归唯一权威源，各册的写法约束如下表所示。

| 内容 | 唯一权威源 | 其余册的写法 |
|---|---|---|
| configure 选项、suricata.yaml 全部段、规则关键字、命令行与 suricatasc RPC、返回码 | **04 全册** | 只给本场景最小必要调用，写「完整参数见 04-xx」 |
| 结构体逐字段（Packet / Flow / Signature / DetectEngineCtx 等） | **05 全册** | 只点名 + 真实源码路径 +「（字段见 05-xx）」 |
| 机制、状态机与调用链（抓包后端、解码与隧道、流与重组、应用解析、规则编译、MPM、检测、EVE、IPS、runmode） | **06 全册** | 讲「做什么」不讲「怎么实现」，写「原理见 06-xx」 |
| 模块能力与特性（按 `src/` 目录划分的 13 个模块） | **07 全册** | 写「模块见 07-xx」 |
| 运维场景组合、基准方法、诊断树、案例库、加固、上线清单、输出判读 | **08 全册** | 其余册不展开运维步骤 |

05 覆盖 `Packet` / `Flow` / `FlowBucket` / `Signature` / `SigMatch` / `DetectEngineCtx` / `ThreadVars` / `TmModule` / `LogFileCtx` / `SCInstance` / `ConfNode` 等结构体族；07 覆盖的 13 个模块见第 4 节文件名清单与第 8 节全量大纲。

强制约束：

1. 06 / 07 / 08 全册禁止出现完整结构体字段表，改为 `（字段见 05-xx）`。
2. 07 全册每篇代码段最多 3–5 个本模块最典型的调用 / 命令，其余写「完整 API 见 04-xx」。
3. 08 全册禁止重列参数清单，只讲「在什么场景组合哪些参数、如何判读输出」。
4. 04 全册禁止讲模块内部原理与结构体字段；05 全册禁止展开机制流程。
5. 交叉引用统一写法：`（字段见 05-xx ｜ 参数见 04-xx ｜ 原理见 06-xx ｜ 模块见 07-xx）`。

## 6. 三类骨架模板

**A 论述型（7 节）**
背景与动机 → 核心概念 → 关键数据结构与源码位置（**引用 05，不重列字段**）→ 关键流程与调用链 → 配置/命令/代码实例（**引用 04，不重列参数**）→ 注意事项、陷阱与最佳实践 → 小结与延伸阅读。

**B 手册字典型（7 节）**
本篇定位与覆盖范围 → 索引与全参数表 → 逐项详解 → 典型示例 → 速查表 → 版本差异 → 常见误用与调试。
05 字段表统一列：`字段 | 类型 | 含义 | 源码位置 | 读写时机 | 关联函数与流程 | 版本差异`。

**C 实战型（6 节）**
目标与拓扑 → 前置条件与环境 → 分步操作 → **验证方法与预期结果** → 常见失败与排错 → 小结。
每篇必须给「预期输出 + 判读要点」，不是只给命令。

## 8. 全量大纲（65 篇）

### 01 基础与概述（4 篇，A 型）

**01-01 Suricata 是什么：IDS/IPS/NSM 定位、能力矩阵与适用边界**
从 `src/suricata.c` 主入口与 `suricata.yaml.in` 默认配置讲清 IDS / IPS / NSM 三种角色；能力矩阵（能告警、能 drop、能输出 EVE、能协议解析；不做转发、不是防火墙、不做路由）；内联 drop 依赖 `src/source-nfq.c` 的 NFQUEUE 与 AF_PACKET 桥接 verdict；与 Hyperscan 这类纯匹配库、与防火墙的边界；何时不该用 Suricata。

**01-02 与 Snort 2/3、Zeek、商业 IPS 的引擎对比**
规则语法兼容 Snort 但有自有扩展（`src/detect-parse.c`、`src/detect-engine-register.c`），不能宣称 100% 兼容；与 Zeek 的「日志与脚本 vs 规则告警」分工；多线程 runmode（workers / autofp / single，见 `src/runmodes.c`）；EVE JSON 为主要输出（`src/output-json*.c`）；四类引擎的选型决策表。

**01-03 整体架构：抓包 → 解码 → 流与应用解析 → 检测 → 输出**
按 `src/source-*.c`（AF_PACKET / DPDK / Netmap / pcap）→ `src/decode.c` → `src/flow.c`、`src/stream-tcp-reassemble.c` → `src/app-layer-parser.c` → `src/detect-engine*.c` → `src/output-json*.c` 串起流水线；`src/tm-threads.h`、`src/tm-queues.h` 的线程与队列；配置入口 `suricata.yaml.in`；全链路分层图。

**01-04 版本基准、许可、生态与资料使用约定**
统一写「上游 main 快照（2026-11 抓取）」，具体版本号以 `configure.ac`、`ChangeLog` 为准但不写绝对值；GPLv2 许可（`COPYING`）；OISF 生态、`suricata-update/` 独立工具、`rust/` 与 Cargo 是构建一部分；本套资料的编号、去重、交叉引用与「需对照实际版本核验」写法。

### 02 编译与构建（5 篇，A/C 型）

**02-01 源码获取、仓库目录结构与依赖矩阵**
真实仓库根为 `upstream_src/suricata/suricata-main/`（归档多一层 `suricata-main/`）；顶层 `configure.ac`、`Makefile.am`、`suricata.yaml.in`、`autogen.sh`、`ChangeLog`、`COPYING`；`src/`、`rust/`、`doc/userguide/`、`etc/`、`rules/`、`lua/`、`plugins/`、`python/`、`ebpf/`、`qa/` 职责；依赖矩阵以 `configure.ac` 的 `AC_CHECK_LIB` / `PKG_CHECK_MODULES` 为准，具体库名与版本下限需对照实际版本核验。

**02-02 构建系统全解：configure 选项与构建变体**
`./autogen.sh && ./configure && make && make install` 链路；`configure.ac` 中 `AC_ARG_ENABLE` / `AC_ARG_WITH` 定义的选项（AF_PACKET、DPDK、NFQUEUE、Hyperscan、Lua、debug、unittests 等族，具体选项名需对照实际版本核验）；`src/Makefile.am` 的装配；三种典型变体（生产 IDS、IPS 内联、调试带单测）与产物形态。

**02-03 从零构建实战：Linux 编译、测试与安装**
装依赖 → `./autogen.sh` → `./configure` → `make -j` → `make check` / `suricata -T` 规则自检 → `make install`；用 `suricata --build-info` 与 `suricata -T` 验证；`LD_LIBRARY_PATH` 与 `ldconfig`；`etc/` 下 `classification.config`、`reference.config` 落位；常见失败（libyaml 缺、Rust/Cargo 版本、cbindgen 缺、Hyperscan 头缺失）与排错。

**02-04 Rust 组件与抓包后端（AF_PACKET/DPDK/PF_RING/Netmap/pcap）构建**
`rust/Cargo.toml.in`、`rust/Cargo.lock.in`、`rust/cbindgen.toml`、`rust/src/`、`rust/Makefile.am` 与 make 期 Rust 静态库；`src/source-af-packet.c`、`src/source-dpdk.c`、`src/source-netmap.c`、`src/source-pcap.c`、`src/source-nfq.c` 各自启用条件；DPDK 需独占网卡、大页与 EAL 参数，PF_RING / Netmap 需内核模块与专用驱动，pcap 仅作离线或低速率；PF_RING 支持状态需对照实际版本核验。

**02-05 调试构建、Sanitizer、单元测试与 CI 产物形态**
`configure.ac` 的 debug / unittests 开关、`src/runmode-unittests.c`、`src/tests/`、`src/tests/fuzz/`；ASan / UBSan 与 `CFLAGS` 组合；`suricata -u` 跑单测、`suricata -T` 验规则；`qa/`、`suricata-verify`、`.github/workflows/` 的 CI 产物；`make dist` 与 `bundle.txt`；调试构建的性能代价，不可用作生产基准。

### 03 集成与部署（6 篇，C 型）

**03-01 最小可用部署：第一次 IDS 运行与规则加载**
`suricata -c suricata.yaml -i <iface>` 或 `suricata -r <pcap>`；先用 `suricata -T` 验规则；`rules/` 与 `default-rule-path`；`src/detect-engine-loader.c` 的规则加载入口；`fast.log`、`eve.json` 首条告警与 `stats.log`；逐行判读 `suricata.log` 的加载错误；常见失败（网卡名错、权限不足、YAML 缩进）。

### 08 运维、性能基准与排障（6 篇，A/C 型）

**08-01 性能基准方法与实测**
目标是可复现吞吐数字；用真实或脱敏 pcap 与 `suricata -r`，或在线 AF_PACKET / DPDK；`stats.log` 与 `eve.json` 的 stats 事件（capture、decoder、detect、tcp.reassembly_memuse 等计数项需对照实际版本核验）；`suricatasc dump-counters`；绑核、RSS 队列、threads 与 detect-thread-ratio 的 A/B 对照；所有性能数字一律标注「需在目标机型实测」，不给绝对值。

**08-02 性能调优：线程、RSS、内存与规则集**
`threading.cpu-affinity`、`af-packet.threads` / cluster-type、runmode（workers / autofp，见 `src/runmodes.c`）、RSS 队列与对称哈希；`stream.reassembly.memcap`、`flow.memcap`、`max-pending-packets`（键名需对照实际版本核验）；规则集规模与 `fast_pattern` / `mpm-algo` / Hyperscan（`src/util-mpm-hs.c`）；profiling；常见「越调越慢」误操作与内存占用模型。

**08-03 常见故障分类与诊断决策树**
按「启动失败 / 规则加载失败 / 无告警 / 误报过多 / 吞吐低 / 丢包 / 内存涨 / 崩溃」组织；证据来源（`suricata.log`、`suricata -T`、`suricata --build-info`、`--dump-config`、`stats.log`、`eve.json`、`suricatasc dump-counters`）；决策树与判定顺序；对应 `src/` 下源码路径（函数名需对照实际版本核验）；与 04-08 排错速查的交叉引用。

**08-04 故障案例库：从规则加载失败到吞吐骤降**
六个完整案例，每例含现象、复现、证据、根因（指到源码 / 配置）、修复、验证：① `suricata -T` 报规则语法错（`src/detect-parse.c`）② 加载报未知关键字（`src/detect-engine-register.c`）③ 在线跑通但 `eve.json` 无 alert（网卡 / 权限 / `vars` 的 HOME_NET）④ IPS 不 drop（NFQUEUE 队列号 / 动作 / `stream.inline` / fail-open）⑤ Hyperscan 未启用回退 AC 导致吞吐变化（`src/util-mpm-hs.c`、`configure.ac`）⑥ 上线吞吐骤降（绑核 / RSS / cluster-type / autofp 队列）。

**08-05 安全加固：不可信规则、权限与资源耗尽**
