## 2. 深度要求

- 每篇 **3000+ 中文字**（严格口径：排除代码块、表格行、图块 DSL 后的中文字符）。**每篇都要实打实写完**，最后一篇和第一篇一样厚实。
- 严禁出现「（略）」「待补充」「同上」「参见前文不再赘述」等占位；严禁代码块里出现裸 `...` 省略行。
- 每篇必须含：真实源码路径（`src/openvpn/`、`src/plugins/`、`src/compat/`、`sample/`、`doc/`、`tests/` 等）、关键函数/调用链、配置或命令实例、至少一个表格、至少一节「陷阱与最佳实践」或「常见误用与调试」。
- 每篇至少 **2 个代码块**，其中至少一组是「配置/命令/代码 + 典型输出 + 150 字以上中文判读说明」（逐行解释关键字段、正常值范围、异常特征）。
- 版本基准 **OpenVPN 2.6.x / 2.7(master) / ovpn-dco**。不确定的配置指令名、字段名、函数签名、命令行参数、版本号 **不要编造**，写「需对照实际版本核验」并给出可定位的源码/头文件路径（如 `src/openvpn/options.c`、`src/openvpn/ssl.h`）。

## 5. 配图语法（会被编译成 Word 可编辑形状 + .drawio 源文件）

每个图块用下面这种 DSL，**不要用 mermaid、不要插入图片、不要画 ASCII 图**：

```
:::figure id=06-03-01 | name=tun 读写与内外层封装链路 | dir=TD
node n1 "应用进程" blue
node n2 "tun 字符设备" teal
node n3 "openvpn 用户态" amber
node n4 "加密数据通道" purple
edge n1 -> n2 "原始 IP 包"
edge n2 -> n3 "read(tunfd)"
edge n3 -> n4 "封装加密"
edge n4 -> n1 dashed "回查"
:::
```

规则：
- `node <id> "<文字>" <色调>`，色调只能是 blue / teal / amber / purple / gray / red / green。
- `edge <from> -> <to> "<标签>"`；`dashed` 表示辅助/回查关系，写在标签**之前**；标签可省略。
- 节点文字用**双引号**包裹，内部不要出现双引号；可用 `<br/>` 换行。
- **单行显示宽度 ≤ 38**（中文按 2、英文按 1 计），超长必须用 `<br/>` 折成多行；不要把整句话塞进一个节点。
- 每张图节点数 **≤ 10**、边数 **≤ 12**；信息多就拆成两张图，不要堆一张。
- 节点 id 只用字母数字下划线，且块内唯一；**每个节点都必须至少连一条边**（禁止孤立节点）。
- **禁止** subgraph / classDef / style / 链接语法。
- 首行 `:::figure ...` 与末行 `:::` 必须各占一行。
- `id` 全局唯一，格式固定 `<篇章号>-<两位序号>`，如 `07-05-01`。
- 正文引用图时写「图 07-05-01 …」，**必须与图 id 完全一致**（图题、正文引用、`.drawio` 文件名三者同源）。
- 每篇至少 1 张图；每册图数不少于篇数，关键篇可 2 张。
- 图块之前要有引导句（「如下图所示」「…的处理链路见图 06-03-01」）。

## 6. 表格与代码块格式（VPP/DPDK 审阅阶段固化的硬性规则）

- 表格单元格 **≤ 90 字符**。长指令串不要塞进表格：单元格写语义化简述 +「见下方配置示例」，把完整清单移到表后一个代码块里。
- 表格单元格里出现 shell 管道符或语法「或」（`|`）时，**必须写成转义的 `\|`**，否则会被解析成列分隔导致整表错列。
- 表格之前要有引导句（「如下表所示」「参数对照见下表」）。
- 每个代码块**必须带语言标注**，开始行如 ` ```bash ` / ` ```text ` / ` ```c ` / ` ```ini ` / ` ```conf ` / ` ```json ` / ` ```yaml ` / ` ```tree `，结束行是裸 ` ``` `，各自独占一行。禁止无标注代码块。
- 典型输出放在 ` ```text ` 块里，并写明「示例输出，具体格式需对照实际版本核验」。
- 允许用 `> ` 提示框、`-` 无序列表、`1.` 有序列表。

## 7. 分批写入策略（内容很大，务必分块）

- 第 1 次 Write：文件头 + 前 1–2 篇，以**唯一哨兵行** `<!--NEXT-->` 结尾。
- 之后每次用 Edit 把 `<!--NEXT-->` 替换为「后续 1–2 篇 + 新的 `<!--NEXT-->`」。
- 最后一批写完后，再 Edit **删除末尾哨兵**，文件内 `<!--NEXT-->` 残留数必须为 0。
- 每批必须真实成文；一次 Edit 可写 2 篇以控制调用次数。
