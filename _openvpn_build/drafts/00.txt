## 1. 结构设计与评审结论

本套资料沿用 VPP / DPDK 资料集已经验证过的组织逻辑：**按维度分册 → 唯一权威源去重 → 三类骨架 → `文件号-篇号` 编号 → 工具书前置于原理 → 运维收尾**。针对 OpenVPN 自身特点做了三处调整：

| 决策 | 理由 | 落地方式 |
|---|---|---|
| 04 册定为「配置与命令行」并含 management interface | OpenVPN 的「配置」不是 VPP 的 `startup.conf` + `vppctl`，也不是 DPDK 的 EAL 参数；它是**一份 `.conf` 指令集 + 同构的 `--` 命令行参数 + management socket 运行时命令 + 脚本钩子环境变量**四者叠加 | 04 成为配置与命令唯一权威源，按功能族穷举并给全参数表 |
| 02 册独立讲 autoconf / DCO 构建 | 社区版以 `configure`/`make` 为主，且 `ovpn-dco` 内核模块、Windows 交叉编译、LZO/LZ4/PKCS#11 开关自成体系 | 02-02 用 C 实战型给完整分步构建，02-05 单讲 DCO |
| 05 册前置于 06 | 与 VPP / DPDK 一致：`context` / `options` / `tls_multi` / `frame` 是理解事件循环、TLS 握手与数据通道封装的前置知识 | 05 定位「工具书·随查」，不参与线性阅读主线 |

「先搭起来 → 再懂协议与源码 → 再按模块用起来 → 最后运维」这条主线同样成立。评审中明确排除的做法：

| 级别 | 曾经的风险 | 本套的处理 |
|---|---|---|
| 结构 | 按功能平铺 62 篇、无权威源，导致配置/字段/机制在多个文件重复 | 04 / 05 / 06 / 07 各定唯一权威源，其余册交叉引用 |
| 骨架 | 手册型章节套论述型骨架，出现空泛「背景与动机」 | 分 A 论述 / B 手册字典 / C 实战三类骨架 |
| 编号 | 全局连续号在插删后全盘失效 | 改 `文件号-篇号`，插删只影响本册 |
| 工具书 | 字段详解混在线性阅读链路里，打断主线 | 05 独立成册并标注「随查」，可跳过 |
| 边界 | 把 Access Server 商业特性（如集群、Web UI、LDAP 集成）写成社区版能力 | 01-04 明确边界，全册只讲社区版 `src/openvpn/` |

## 2. 唯一权威源与去重规则

| 内容 | 唯一权威源 | 其余册的写法 |
|---|---|---|
| 全部配置指令、`--` 命令行参数、management 命令、脚本钩子与环境变量、PKI 工具命令 | **04 全册** | 只给本场景最小必要配置，写「完整指令族见 04-xx」 |
| 结构体逐字段定义（`context`、`options`、`tls_multi`、`key_state`、`buffer`、`frame`、`link_socket`、`multi_context` 等） | **05 全册** | 只点名 + 给真实源码路径 +「（字段见 05-xx）」 |
| 机制、状态机与调用链（初始化、事件循环、可靠层、TLS 握手、密钥派生、封装、路由推送、DCO） | **06 全册** | 讲「做什么」不讲「怎么实现」，写「原理见 06-xx」 |
| 模块能力与特性、典型用法与组网 | **07 全册** | 写「模块见 07-xx」 |

强制约束：

1. 06 / 07 / 08 全册禁止出现完整结构体字段表，改为 `（字段见 05-xx）`。
2. 07 全册每篇配置段最多 3–5 条本模块最典型的指令，其余写「完整指令族见 04-xx」。
3. 08 全册禁止重列指令 / 命令清单，只讲「在什么场景组合哪些命令、如何判读输出」。
4. 04 全册禁止讲模块内部原理与结构体字段；05 全册禁止展开机制流程。
5. 交叉引用统一写法：`（字段见 05-xx ｜ 指令见 04-xx ｜ 原理见 06-xx ｜ 模块见 07-xx）`。

## 6. 三类骨架模板

**A 论述型（7 节）**
背景与动机 → 核心概念 → 关键数据结构与源码位置（**引用 05，不重列字段**）→ 关键流程与调用链 → 配置/命令/代码实例（**引用 04，不重列指令**）→ 注意事项、陷阱与最佳实践 → 小结与延伸阅读。

**B 手册字典型（7 节）**
本篇定位与覆盖范围 → 索引与全参数表 → 逐项详解 → 典型示例 → 速查表 → 版本差异 → 常见误用与调试。
05 字段表统一列：`字段 | 类型 | 含义 | 头文件/位置 | 读写时机 | 关联函数与流程 | 版本差异`。

**C 实战型（6 节）**
目标与拓扑 → 前置条件与环境 → 分步操作 → **验证方法与预期结果** → 常见失败与排错 → 小结。
每篇必须给「预期输出 + 判读要点」，不是只给命令。

## 7. 配图、表格与示例约定

### 7.1 配图

- 配图一律是 **Word 原生 DrawingML 形状组**：每个框、箭头、标签都是独立子形状，可在 Word 里单击选中、改字、拖动、换色；DOCX 内 **零位图**。
- 每张图同时产出一份同名 `.drawio` 源文件，可用 draw.io 打开继续编辑或导出 SVG/PNG。
- 图号即图 id（`06-03-01`），**正文引用、图题、`.drawio` 文件名三者同源**。
- 图块之前必须有引导句；节点文字单行显示宽度 ≤38，超长用 `<br/>` 折行；每图节点 ≤10、边 ≤12，无孤立节点。

### 7.2 表格

- 表头跨页自动重复、行禁止跨页拆分、列宽按内容长度自适应。
- 单元格 ≤90 字符；长命令串移到表后代码块，单元格写「见下方配置示例」。
- 单元格内的 shell 管道或语法「或」（`|`）必须转义为 `\|`，否则整表错列。
- 表格之前必须有引导句。

### 7.3 示例

- 每个代码块带语言标注（`conf` / `bash` / `text` / `c` / `ini` / `yaml` / `json` / `tree`），DOCX 里渲染成可见的示例类型标签。
- 典型输出统一放 `text` 块，并注明「示例输出，具体格式需对照实际版本核验」。
- 每篇至少一组「配置/命令 + 典型输出 + 150 字以上中文判读说明」，讲清关键字段含义、正常值范围与异常特征。
- 禁止裸 `...` 省略行与任何占位词。
