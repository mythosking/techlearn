## 1. 结构设计与评审结论

本套资料沿用 VPP 资料集已经验证过的组织逻辑：**按维度分册 → 唯一权威源去重 → 三类骨架 → `文件号-篇号` 编号 → 工具书前置于原理 → 运维收尾**。针对 DPDK 自身特点做了三处调整：

| 决策 | 理由 | 落地方式 |
|---|---|---|
| 04 册定为「EAL 参数与工具命令行」 | DPDK 不像 VPP 有 `startup.conf` 与 `vppctl`，其「配置」主要体现为 EAL 命令行参数、devargs 与 testpmd / `dpdk-*` 工具 | 04 成为参数与命令唯一权威源，覆盖 EAL、testpmd、procinfo、pdump、telemetry、devbind |
| 02 册独立讲 meson 构建 | DPDK 自 20.11 起全面转向 meson/ninja，构建选项、驱动开关、交叉编译自成体系，值得单独成册 | 02 除 02-02 用 C 实战型外，其余为 A 论述型 |
| 05 册前置于 06 | 与 VPP 一致：`rte_mbuf` / mempool / ethdev 等结构体是理解 PMD 收发包、描述符环、rte_flow 的前置知识 | 05 定位「工具书·随查」，不参与线性阅读主线 |

「先跑起来 → 再懂内核 → 再按库与驱动用起来 → 最后运维」这条主线对 DPDK 同样成立。评审中明确排除的做法：

| 级别 | 曾经的风险 | 本套的处理 |
|---|---|---|
| P1 | 同一批结构体 / EAL 参数在 02、03、05、06、07、08 反复讲 | 建立唯一权威源，其余册只引用不重列 |
| P1 | 全部篇目套一套 7 段式骨架，字段字典与命令速查被迫注水 | 骨架分 A 论述 / B 手册字典 / C 实战三类 |
| P2 | 全局连续编号，插一篇就要全量重排 | 编号改 `文件号-篇号`，抗插删 |
| P2 | 工具书混进线性阅读链路 | 04/05 明确标注「随查」，阅读路径允许跳过 |
| P3 | 缺性能基准方法学、故障案例库、版本迁移 | 08 册补齐 08-01 / 08-04 / 08-05 |

## 2. 唯一权威源与去重规则

| 内容 | 唯一权威源 | 其他册的写法 |
|---|---|---|
| EAL 参数、testpmd 与 `dpdk-*` 工具命令全集 | 04 全册 | 「完整参数见 04-xx」，只给最小必要命令 |
| 结构体逐字段定义 | 05 全册 | 「（字段见 05-xx）」，禁止出现完整字段表 |
| 机制、调度、调用链 | 06 全册 | 「原理见 06-xx」，不展开内部流程 |
| 库 / 驱动模块功能与组网 | 07 全册 | 「模块见 07-xx」，不重列功能清单 |
| 场景化命令组合与输出判读 | 08 全册 | 不重列命令清单，只讲组合与判读 |

- 07 每篇配置段最多 3–5 条最典型命令，其余写「完整命令族见 04-xx」。
- 02 / 03 只给最小必要命令，不得重列 EAL 参数全集。
- 05 只讲字段含义、内存布局、生命周期、关联函数入口，不展开机制流程。
- 交叉引用统一写法：`（字段见 05-xx ｜ 命令见 04-xx ｜ 原理见 06-xx ｜ 模块见 07-xx）`

## 6. 三类骨架模板

**A 论述型**（01、02 除 02-02、06、07、08-02/03/05/06）
背景与动机 → 核心概念 → 关键数据结构与源码位置（**引用 05，不重列字段**）→ 关键流程与调用链（配图）→ 配置 / 命令 / 代码实例（**引用 04**）→ 陷阱与最佳实践 → 小结与延伸阅读。

**B 手册字典型**（04、05）
本篇定位与覆盖范围 → 索引与全参数表 → 逐项详解 → 典型示例 → 速查表 → 版本差异 → 常见误用与调试。不写「背景与动机」「调用链」，以完整参数/字段表为主体。

**C 实战型**（03、02-02、08-01、08-04）
目标与拓扑（配拓扑图）→ 前置条件与环境 → 分步操作 → **验证方法与预期结果** → 常见失败与排错 → 小结。每步都要给可复制的命令与预期输出。

## 7. 配图、表格与示例约定

### 7.1 配图
- 每张图都是 DOCX 内的 **Word 原生形状组**：单击选中整组、再点一次可单独改字、拖动、换色；不是图片。
- 图题、正文引用、`.drawio` 文件名统一使用图 id（如 `图 06-04-01`）。
- 节点文字单行显示宽度 ≤38（中文按 2 计），过长用 `<br/>` 折行；每张图节点 ≤10、边 ≤12。
- `figures/` 下同名 `.drawio` 可用 draw.io 直接打开编辑，与 Word 内形状一一对应。

### 7.2 表格
- 全部为 Word 原生表格，表头跨页重复、行不拆页、按列内容长度自适应列宽。
- 表格单元格 ≤90 字符；长命令串移到表后代码块，单元格写「见下方命令示例」。
- 单元格内出现 shell 管道或语法「或」时写成转义的 `\|`，避免错列。

### 7.3 示例
- 每个代码块带可见类型标签（命令示例 · Shell / 代码片段 · C / 配置片段 / 输出示例 / 目录结构）。
- 每组完整示例 = 命令或代码 + ` ```text ` 典型输出 + 中文判读说明（关键字段含义、正常范围、异常特征）。
- 不确定的输出格式写明「示例输出，具体格式需对照实际版本核验」。

### 06_技术原理.docx（12 篇｜A 型｜机制与调用链唯一权威源）

- **06-01** EAL 初始化与 lcore 线程模型 —— `rte_eal_init` 主流程、主/从 lcore、线程亲和与 `rte_lcore_id`。
- **06-02** 大页内存布局：memseg / memzone / IOVA —— 物理连续与 VA 连续、IOVA=VA / PA 模式、映射与预留调用链。
- **06-03** mempool 与 mbuf 生命周期 —— 对象池创建、per-lcore cache、`rte_pktmbuf_alloc` → 释放、`refcnt` 与分片链。
- **06-04** PMD 轮询收发包调用链 —— `rte_eth_rx_burst` / `rte_eth_tx_burst` 到驱动 `rx_pkt_burst` 的函数链与批量语义。
- **06-05** 描述符环、DD 位与 DMA 一致性 —— 描述符回填、尾寄存器更新、内存屏障与 cache 一致性边界。
- **06-06** RSS / Flow Director / `rte_flow` 规则下发 —— 哈希与队列映射、规则编译到硬件、卸载协商流程。
- **06-07** 无锁 ring 与内存序 —— 单/多生产者消费者、CAS、acquire/release 屏障、伪共享与 cache line 对齐。
- **06-08** Cache 预取、批处理与 SIMD 向量化 —— 批量收益来源、预取距离、向量指令在查表与校验和中的应用。

## 9. 构建与校验流程

内容源与交付物分离：所有修改只发生在 `_dpdk_build/drafts/*.txt`，再由脚本统一编译，避免直接改 DOCX 破坏 DrawingML 形状组。

| 步骤 | 命令 / 脚本 | 作用 |
|---|---|---|
| 1 | `python audit_content.py` | 逐篇审计图 / 表 / 示例 / 编号 / 图号引用 |
| 2 | `python fix_content.py --apply` | 确定性修复：代码块语言标注、节点长文字折行 |
| 3 | `python build_all.py` | 生成 9 个 DOCX 与全部 `.drawio` |
| 4 | `python verify_all.py` | 篇数、编号、字数、形状组、位图、drawio 数量校验 |
| 5 | `python final_verify.py` | 交付终检 |
| 6 | Word COM / draw.io CLI | 真机验证形状组可编辑、零位图、图源可打开 |
