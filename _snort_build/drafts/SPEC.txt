### 2.1 能力边界清单（全册硬约束，逐条写清，不得写反）

1. **全新实现 / Lua 配置**：Snort 3 是从 Snort 2 **重写的全新实现**（C++ 主体、插件化），
   配置为 Lua（`lua/snort.lua`、`lua/snort_defaults.lua`），**不兼容 Snort 2 的 `snort.conf`
   与插件 ABI**；`tools/snort2lua/` 只是格式转换辅助工具，不等于配置可直接沿用。
2. **抓包依赖独立 libdaq / DAQ3**：抓包不内置，依赖**独立的 libdaq / DAQ3**；
   `src/packet_io/sfdaq*.cc`、`sfdaq_config.cc`、`sfdaq_module.cc`、`daqs/` 是适配层，
   **DAQ module 决定抓包与内联能力**（具体 module 名需对照实际版本核验），
   不得写成「Snort 自带抓包、与 DAQ 无关」。
3. **内联 IPS 不是防火墙**：内联 IPS 的 drop / block 通过 **DAQ verdict 反馈**
   （`src/actions/act_drop.cc`、`act_block.cc`、`act_reject.cc`、`src/packet_io/active.cc`），
   Snort 本身**不是防火墙、不做 IP 转发、不做路由**；IDS 旁路模式只告警不丢弃。
4. **Hyperscan 是可选加速**：Hyperscan 是**可选 search_engine 加速**
   （`src/search_engines/hyperscan.cc`，构建开关见 `CMakeLists.txt`，选项名需对照实际版本核验），
   **缺失时回退其他多模式匹配实现**（`src/search_engines/ac_bnfa.cc`、`ac_full.cc`、
   `acsmx2.cc`、`bnfa_search.cc`），不得写成必需依赖或唯一实现。
5. **加密载荷不可见**：**加密流量载荷不可见**，能拿到的是握手元数据、证书等
   （字段名需对照实际版本核验），应用识别依赖 **inspector / binder / wizard**
   （`src/network_inspectors/binder/`、`src/service_inspectors/wizard/`、
   `src/network_inspectors/appid/`、`src/service_inspectors/ssl/`），
   不得宣称能读到 HTTPS 明文正文。
6. **线程 / 进程模型以实际版本为准**：多线程 / 进程模型与资源隔离
   （`src/main/analyzer.cc`、`swapper.cc`、`process.cc`、`numa.cc`）以实际版本为准，
   不确定的一律标注「需对照实际版本核验」，**禁止断言「默认 N 线程」**。
7. **许可**：**GPLv2 许可**（顶层 `COPYING` / `LICENSE`）；**Talos 规则集有独立许可约束**

8. **性能**：任何吞吐、pps、丢包率、内存占用数字一律标注「**需在目标机型实测**」，

```text
:::figure id=06-02-01 | name=DAQ3 收包与 verdict 回传链路 | dir=TD
node n1 "DAQ module<br/>收包" blue
node n2 "Packet 解码<br/>codecs" teal
node n3 "inspectors<br/>与检测" purple
node n4 "DAQ verdict<br/>回传" red
edge n1 -> n2 "消息入队"
edge n2 -> n3 "重组后的流"
edge n3 -> n4 "drop / pass"
edge n1 -> n4 dashed "旁路模式"
:::
```

规则：
- `node <id> "<文字>" <色调>`，色调只能是 blue / teal / amber / purple / gray / red / green。
- `edge <from> -> <to> "<标签>"`；`dashed` 表示辅助 / 回查关系，写在标签**之前**；标签可省略。
- 节点文字用**双引号**包裹，内部不要出现双引号；可用 `<br/>` 换行。
- **单行显示宽度 ≤ 38**（中文按 2、英文按 1 计），超长必须用 `<br/>` 折成多行；不要把整句话塞进一个节点。
- 每张图节点数 **≤ 10**、边数 **≤ 12**；信息多就拆成两张图，不要堆一张。
- 节点 id 只用字母数字下划线，且块内唯一；**每个节点都必须至少连一条边**（禁止孤立节点）。
- **禁止** subgraph / classDef / style / 链接语法。
- 首行 `:::figure ...` 与末行 `:::` 必须各占一行。
- `id` 全局唯一，格式固定 `<篇章号>-<两位序号>`，如 `07-05-01`；00 总纲的图为 `00-01-01`。
- 正文引用图时写「图 07-05-01 …」，**必须与图 id 完全一致**（图题、正文引用、`.drawio` 文件名三者同源）。
- 每篇至少 1 张图；每册图数不少于篇数，关键篇可 2 张。
- 图块之前要有引导句（「…的处理链路见图 06-02-01」）。
- 色调语义在本套资料内统一：`blue` 输入 / 接口、`teal` 解码与流、`amber` 规则与编译产物、
  `purple` 检测引擎、`green` 输出与运行时、`red` 故障 / 瓶颈、`gray` 辅助与外部依赖。
