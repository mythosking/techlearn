## 1. 结构设计与评审结论

本套资料沿用 VPP / DPDK / OpenVPN / wireguard-windows / Hyperscan / Suricata 六套资料集已验证的组织逻辑：
**按维度分册 → 唯一权威源去重 → 三类骨架 → `文件号-篇号` 编号 → 工具书前置于原理 → 运维收尾**。
针对 Snort 3 作为「从 Snort 2 重写、Lua 配置、依赖独立 DAQ3 抓包、插件化 inspector / detection / logger 全链路引擎」的特点，做了五处调整。

| 决策 | 理由 | 落地方式 |
|---|---|---|
| 03 册定为「集成与部署」 | Snort 3 是常驻进程，`snort.lua` 配置、DAQ module、规则集、输出管道与内联 verdict 共同决定它能否跑起来 | 03 全册按 C 实战型写：首次 IDS → Lua 主干 → 规则集 → 输出管道 → 内联 IPS → 多实例与容器 |
| 04 册定为「参数与 API 手册」 | 本项目的「配置」全部体现为 CMake 选项、`snort.lua` 段、DAQ 与 inspector 参数、规则关键字、命令行 / Lua 配置 API / shell 控制 | 04 成为构建选项、Lua 参数、规则关键字、命令与返回码的唯一权威源 |
| 05 册前置于 06 | `Packet` / `DecodeData` / `Flow` / `SnortConfig` / `Inspector` / `DetectionEngine` 是理解检测与输出流水线的前置知识 | 05 定位「工具书·随查」，不参与线性阅读主线 |
| 06 册增加到 14 篇 | 核心复杂度集中在包处理流水线：DAQ3 收包 → 解码 → binder/wizard → 流重组 → 规则编译 → MPSE → 检测 → 输出 → 内联 → 线程 → 插件 | 06 用 6 篇讲流水线各段、4 篇讲检测与状态、4 篇讲输出 / 内联 / 线程 / 扩展 |
| 07 册按 `src/` 真实目录设 13 篇 | 模块边界与源码目录一一对应，避免出现「按概念编模块」的虚设章节 | 每篇对应一个真实目录族，给文件清单与关键入口 |

评审中明确排除的做法：

| 级别 | 曾经的风险 | 本套的处理 |
|---|---|---|
| 结构 | 按功能平铺 65 篇、无权威源，导致 Lua 参数与规则关键字在多个文件重复 | 04 / 05 / 06 / 07 / 08 各定唯一权威源，其余册交叉引用 |
| 骨架 | 手册型章节套论述型骨架，出现空泛「背景与动机」 | 分 A 论述 / B 手册字典 / C 实战三类骨架 |
| 边界 | 把 Snort 3 写成防火墙、或宣称能读加密载荷明文 | 01-01、06-12、08-05 三处明确 IDS/IPS 定位、不做转发、加密载荷不可见 |
| 配置 | 宣称兼容 Snort 2 的 `snort.conf` 与插件 ABI | 01-01、01-02、04-02 写明 Lua 配置全新实现、`tools/snort2lua/` 仅为转换辅助 |
| 抓包 | 写成 Snort 自带抓包、与 DAQ 无关，或宣称某 DAQ module 即插即用 | 02-04、06-02 写明抓包依赖独立 libdaq / DAQ3、module 决定抓包与内联能力 |
| 性能与版本 | 给绝对吞吐数字，或编造具体版本号、断言「默认 N 线程」 | 08 全册标注「需在目标机型实测」；版本统一写「上游 master 快照（2026-11 抓取）」；线程模型一律标注核验 |

## 2. 唯一权威源与去重规则

| 运维场景组合、基准方法、诊断树、案例库、加固、上线清单、输出判读 | **08 全册** | 其余册不展开运维步骤 |

05 覆盖 `Packet` / `DecodeData` / `Flow` / `SnortConfig` / `Inspector` / `Module` / `Rule` / `DetectionEngine` / `IpsAction` / `Cursor` / `RuleOption` / `PatternMatcher` / `MPSE` / `DAQ_PktHdr` / `Verdict` / `Event` / `Logger` / `Session` 等结构体族；07 覆盖的 13 个模块见第 4 节文件名清单与第 8 节全量大纲。

1. 06 / 07 / 08 全册禁止出现完整结构体字段表，改为 `（字段见 05-xx）`。

3. 08 全册禁止重列参数清单，只讲「在什么场景组合哪些参数、如何判读输出」。
4. 04 全册禁止讲模块内部原理与结构体字段；05 全册禁止展开机制流程。
5. 交叉引用统一写法：`（字段见 05-xx ｜ 参数见 04-xx ｜ 原理见 06-xx ｜ 模块见 07-xx）`。

## 8. 全量大纲（65 篇）

### 01 基础与概述（4 篇，A 型）

**01-01 Snort 3 是什么：重写动机、能力矩阵与适用边界**
从 `src/main.cc` 与 `lua/snort.lua` 讲清 Snort 3 是相对 Snort 2 的 C++ 重写、改用 Lua 配置；能力矩阵（能 IDS 告警、能内联 drop、能输出 `alert_json` / `unified2`、能按 inspector 解析协议；不做转发、不是防火墙）；与纯匹配库、与防火墙的边界；`tools/snort2lua/` 佐证配置不兼容 `snort.conf`。何时不该用 Snort 3。

**01-02 与 Snort 2 / Suricata / Zeek 的引擎对比**
`lua/snort.lua` 与 Snort 2 `snort.conf` 的代际差异、`tools/snort2lua/` 的转换定位；规则关键字在 `src/ips_options/`、`src/parser/parse_rule.cc` 与 Snort 2 有差异、不能宣称完全兼容；抓包依赖独立 libdaq（`src/packet_io/sfdaq*.cc`）而非自带；与 Suricata 的多线程 / EVE、Zeek 的日志脚本分工；四类引擎选型决策表。

**01-03 整体架构：DAQ → 解码 → inspectors → detection → loggers**
按 `src/packet_io/sfdaq.cc`（DAQ3 收包）→ `src/codecs/` 与 `src/protocols/packet.cc`（解码）→ `src/network_inspectors/`、`src/service_inspectors/`（binder / wizard / inspector）→ `src/detection/detection_engine.cc`（检测）→ `src/loggers/alert_json.cc`、`unified2.cc`（输出）串起流水线；`src/framework/` 的 Inspector / Module / Codec / Logger 插件抽象；`src/managers/` 的模块装配；配置入口 `lua/snort.lua`；全链路分层图。

**01-04 版本基准、许可、生态与资料使用约定**
统一写「上游 master 快照（2026-11 抓取）」，具体版本号以 `CMakeLists.txt`、`ChangeLog` 为准但不写绝对值；`COPYING` / `LICENSE` 的 GPLv2 许可、`lua/talos.lua` 与 Talos 规则集的独立许可约束；`doc/`（user / reference / devel / upgrade）与官方生态；本套资料的编号、去重、交叉引用与「需对照实际版本核验」写法。

### 02 编译与构建（5 篇，A/C 型）

**02-01 源码获取、仓库目录结构与依赖矩阵**
真实仓库根为 `upstream_src/snort3/snort3-master/`（归档多一层 `snort3-master/`）；顶层 `CMakeLists.txt`、`configure_cmake.sh`、`config.cmake.h.in`、`snort.pc.in`、`cmake/`；`src/` 各子目录（framework、network_inspectors、service_inspectors、detection、ips_options、search_engines、stream、packet_io、loggers、main、managers、flow 等）职责；`lua/`、`doc/`、`tools/`、`daqs/`；依赖矩阵以 `CMakeLists.txt` 与 `configure_cmake.sh` 的 `find_package` / `pkg_check_modules` 为准（含 libdaq、LuaJIT、Hyperscan、pcap 等，具体项需对照实际版本核验）。

**02-02 CMake 构建配置与构建变体全解**
`./configure_cmake.sh` → `cmake` → `make` → `make install` 链路；`CMakeLists.txt` 与 `cmake/` 下的选项（静态 / 动态、Hyperscan、DAQ、LuaJIT、debug、单元测试等族，具体选项名需对照实际版本核验）；`config.cmake.h.in` 的编译期开关；三种典型变体（生产 IDS、内联 IPS、调试带单测）与产物形态。

**02-03 从零构建实战：Linux 编译、测试与安装**
装依赖（libdaq、LuaJIT、pcap、Hyperscan 等）→ `./configure_cmake.sh --prefix=...` → `cmake --build` → `ctest` → `make install`；用 `snort -V`、`snort --help`、`snort -c lua/snort.lua -T`（配置自检，具体选项需对照实际版本核验）验证；`LD_LIBRARY_PATH` 与 `ldconfig`；`lua/snort_defaults.lua` 落位；常见失败（libdaq 缺失、LuaJIT 版本、Hyperscan 头缺失）与排错。

**02-04 libdaq / DAQ3 与插件、扩展构建**
libdaq / DAQ3 是独立依赖，`src/packet_io/sfdaq.cc`、`sfdaq_config.cc`、`sfdaq_module.cc` 与 `sfdaq_static_modules.h.in` 是适配层；`daqs/` 下 `daq_file.c`、`daq_hext.c` 等示例 module；DAQ module（afpacket、nfq、pcap 等）决定抓包与内联能力（具体 module 名需对照实际版本核验）；`src/framework/` 插件 ABI、`src/managers/plugin_manager.cc` 加载与 SO 规则、`tools/snort2lua/` 辅助工具构建。

**02-05 调试构建、Sanitizer、单元测试与静态分析**
`CMakeLists.txt` 的 debug / 单测开关、`src/` 各目录 `test/` 子目录、`src/framework/test/`；ASan / UBSan 与 `CMAKE_CXX_FLAGS` 组合；`.clang-tidy` 与 `crusty.cfg`（顶层静态分析配置）；`ctest` 跑单测；调试构建的性能代价，不可用作生产基准；CI 产物形态需对照实际版本核验。

**08-01 性能基准方法与实测**

**08-02 性能调优：线程、规则集、内存与 DAQ**
