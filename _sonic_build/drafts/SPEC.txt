### 2.1 能力边界清单（全册硬约束，逐条写清，不得写反）

1. **定位**：SONiC 是**白盒交换机网络操作系统（NOS）**，控制面在各容器进程
   （`orchagent` / `syncd` / 各 `*mgrd` / `bgpd` / `teamd` 等），数据面在 **ASIC**，
   控制面经 **SAI** 下发到 ASIC 转发芯片；`config` / `show` 只改配置与读状态。
   **除虚拟交换机 `vs`（`platform/vs/`）外不做软件转发**，不得把 SONiC 写成通用软件路由器 / 主机协议栈。
2. **不是单一仓库**：本快照只有 `sonic-buildimage` 主仓 + 7 个子仓（见 0.1），
   只是 SONiC 全生态的一部分。**FRR / FRRouting 源码、Linux 内核、各厂商 SAI 实现、
   `sonic-swss-common` 等均不在本快照**，涉及这些部分时一律明确写
   「**不在本快照，需对照实际版本核验**」，不得编造其文件、字段或版本。
3. **Redis 数据库分层**：配置与状态分布在 `CONFIG_DB` / `APPL_DB` / `ASIC_DB` /
   `STATE_DB` / `COUNTERS_DB` 等多个逻辑库（还有 `CHASSIS_APP_DB` 等按场景扩展）；
   **DB 编号与表字段须对照 `sonic-py-swsssdk`（`src/swsssdk/dbconnector.py` 的 `SonicDBConfig`）/
   `sonic-swss-common` 实际版本核验，禁止凭印象写编号**（不得写死「CONFIG_DB 是某号库」）。
4. **配置链路是异步流水线**：`CONFIG_DB` → 各 `*mgrd`（`cfgmgr/`）→ `APPL_DB` →
   `orchagent`（`orchagent/`）→ `ASIC_DB` → `syncd`（`sonic-sairedis/syncd/`）→ `SAI` → ASIC。
   **不是同步生效，`config` 命令返回成功不代表硬件已下发**；判读状态要查
   `APPL_DB` / `ASIC_DB` / `STATE_DB` 与 `show` 输出，不得写「配置即时生效」。
5. **SAI 是抽象接口**：`SAI/` 里的头文件定义统一 API，厂商实现多为**闭源且不在本仓库**；
   `orchagent` 通过 `ASIC_DB` 与 SAI 属性与 `syncd` 交互，**不直接操作硬件**，
   不得把 `orchagent` 写成直接读写寄存器 / 直接驱动芯片。
6. **CLI 边界**：`sonic-utilities` 的 `show` / `config` 主要**读写 `CONFIG_DB` 与各 DB**
   （经 `swsssdk` / ConfigDB 封装），**不直接编程 ASIC**；配置生效依赖第 4 条的流水线。
7. **warm reboot 与多 ASIC / chassis**：`warmrestart/`、多 ASIC 命名空间、
   chassis 支持（如 `chassisorch.cpp`、`files/image_config/config-chassisdb/`）**受平台与版本限制**，
   不同 HWSKU / 版本能力不同，一律写「受平台与版本限制，需对照实际版本核验」，
   不得宣称全平台无条件支持。
8. **镜像构建依赖**：构建依赖 **sonic-slave 容器**（`sonic-slave-*/`）与 **ONIE 安装器**
   （`onie-image.conf` / `installer/`），`make` 在 slave 容器内跑，产出 ONIE 安装包；
   **不能在普通主机裸 `make` 出可安装镜像**，不得写成「普通 x86 主机直接 make 即得镜像」。
9. **性能与容量**：收敛时间、配置下发时延、转发吞吐、表项容量等一切数字，
   一律标注「**需在目标机型实测**」，**不给绝对值**、不给跨机型通用数字（基准方法见 08-01，调优见 08-02）。

## 5. 配图语法（会被编译成 Word 可编辑形状 + .drawio 源文件）

每个图块用下面这种 DSL，**不要用 mermaid、不要插入图片、不要画 ASCII 图**：

```text
:::figure id=06-04-01 | name=配置下发异步流水线 | dir=TD
node n1 "CONFIG_DB" blue
node n2 "各 mgrd<br/>cfgmgr" teal
node n3 "APPL_DB" blue
node n4 "orchagent<br/>Orch 调度" purple
node n5 "ASIC_DB" amber
node n6 "syncd 与 SAI" green
edge n1 -> n2 "订阅变更"
edge n2 -> n3 "写入"
edge n3 -> n4 "消费"
edge n4 -> n5 "写入"
edge n5 -> n6 "调用链"
:::
```

规则：
- `node <id> "<文字>" <色调>`，色调只能是 blue / teal / amber / purple / gray / red / green。
- `edge <from> -> <to> "<标签>"`；`dashed` 表示辅助 / 回查关系，写在标签**之前**；标签可省略。
- 节点文字用**双引号**包裹，内部不要出现双引号；可用 `<br/>` 换行。
- **单行显示宽度 ≤ 38**（中文按 2、英文按 1 计），超长必须用 `<br/>` 折成多行；不要把整句话塞进一个节点。
- 每张图节点数 **≤ 10**、边数 **≤ 12**；信息多就拆成两张图，不要堆一张。
- 节点 id 只用字母数字下划线，且块内唯一；**每个节点都必须至少连一条边**（禁止孤立节点）。
- **禁止** subgraph / classDef / style / 链接语法。
- 首行以 `:::figure` 起头、末行以 `:::` 收尾，两行必须各占一行。
- `id` 全局唯一，格式固定 `<篇章号>-<两位序号>`，如 `07-05-01`；00 总纲的图为 `00-01-01`。
- 正文引用图时写「图 07-05-01 …」，**必须与图 id 完全一致**（图题、正文引用、`.drawio` 文件名三者同源）。
- 每篇至少 1 张图；每册图数不少于篇数，关键篇可 2 张。
- 图块之前要有引导句（「…的处理链路见图 06-04-01」）。
- 色调语义在本套资料内统一：`blue` 数据库 / 输入、`teal` 配置管理与 *mgrd、
  `amber` 编译产物 / ASIC_DB、`purple` orchagent / 控制面、`green` syncd / 运行时 / SAI、
  `red` 故障 / 硬件边界、`gray` 辅助与外部依赖。
