## 1. 结构设计与评审结论

本套资料沿用 VPP / DPDK / OpenVPN / wireguard-windows 四套资料集已验证的组织逻辑：**按维度分册 → 唯一权威源去重 → 三类骨架 → `文件号-篇号` 编号 → 工具书前置于原理 → 运维收尾**。针对 Hyperscan 作为「嵌入式匹配库」而非独立守护进程的特点，做了五处调整。

| 决策 | 理由 | 落地方式 |
|---|---|---|
| 03 册定为「集成与部署」而非「安装部署」 | Hyperscan 没有服务、没有配置文件、没有守护进程；它的「部署」是把库链进宿主程序、把数据库分发到节点、把 scratch 管到线程 | 03 全册按 C 实战型写：最小集成 → 链接 → 数据库分发 → 多线程 → 流式接入 → Chimera |
| 04 册定为「参数与 API 手册」 | 本项目的「配置」全部体现为 CMake 变量 + 编译标志 + 模式常量 + 扩展参数，命令全部体现为工具命令行 | 04 成为构建变量、编译标志、API 签名、工具参数、错误码的唯一权威源 |
| 05 册前置于 06 | 与前三套一致：`hs_database` / `hs_scratch` / `RoseEngine` / `NFA` 是理解引擎选型与运行时行为的前置知识 | 05 定位「工具书·随查」，不参与线性阅读主线 |
| 06 册增加到 14 篇 | Hyperscan 的核心复杂度集中在编译期：图构造 → Rose 分解 → 多引擎选型 → 字节码生成，任何一环跳过都会导致「会用 API 但看不懂行为」 | 06 用 6 篇讲编译期、4 篇讲引擎族、4 篇讲运行时与 Chimera |
| 07 册按 `src/` 真实目录设 13 篇 | 模块边界与源码目录一一对应，避免出现「按概念编模块」的虚设章节 | 每篇对应一个真实目录，给文件清单与关键类/函数 |

评审中明确排除的做法：

| 级别 | 曾经的风险 | 本套的处理 |
|---|---|---|
| 结构 | 按功能平铺 65 篇、无权威源，导致 API 与标志在多个文件重复 | 04 / 05 / 06 / 07 各定唯一权威源，其余册交叉引用 |
| 骨架 | 手册型章节套论述型骨架，出现空泛「背景与动机」 | 分 A 论述 / B 手册字典 / C 实战三类骨架 |
| 边界 | 把 Hyperscan 写成 DPI 产品，或宣称默认返回起止偏移 | 01、04、06 三处明确「只报结束偏移」「不做抓包与协议解析」 |
| 线程 | 把 scratch 当成可全局共享的缓存 | 03-04、05-03、08-02 三处强调 scratch 非线程安全与池化方式 |
| 引擎 | 宣称所有模式都能开 SOM、都能近似匹配 | 04-03、06-10 写明 SOM 与 `SINGLEMATCH`/`PREFILTER` 互斥、部分有界重复不可开 SOM |
| 版本 | 把 Vectorscan（ARM 分支）的能力当上游能力 | 01-02、03-06、07-13 标注二者 API 兼容但引擎矩阵不同 |

## 2. 唯一权威源与去重规则

| 内容 | 唯一权威源 | 其余册的写法 |
|---|---|---|
| 全部 CMake 变量、`HS_FLAG_*`、`HS_MODE_*`、`HS_EXT_FLAG_*`、全部 API 签名、工具命令行、错误码 | **04 全册** | 只给本场景最小必要调用，写「完整参数见 04-xx」 |
| 结构体逐字段定义（`hs_database`、`hs_scratch`、`hs_platform_info_t`、`hs_expr_info_t`、`hs_expr_ext_t`、`hs_compile_error_t`、`RoseEngine`、`RoseContext`、`NFA`、`LimExNFA`、`FDR`、`HWLM`、`NG`、Chimera 结构） | **05 全册** | 只点名 + 给真实源码路径 +「（字段见 05-xx）」 |
| 机制、状态机与调用链（解析、图构造、Rose 分解、引擎选型、加速器、SOM、流状态压缩、序列化、fat runtime、Chimera） | **06 全册** | 讲「做什么」不讲「怎么实现」，写「原理见 06-xx」 |
| 模块能力与特性、引擎族选型与典型用法 | **07 全册** | 写「模块见 07-xx」 |

强制约束：

1. 06 / 07 / 08 全册禁止出现完整结构体字段表，改为 `（字段见 05-xx）`。
2. 07 全册每篇代码段最多 3–5 个本模块最典型的 API 调用，其余写「完整 API 见 04-xx」。
3. 08 全册禁止重列参数清单，只讲「在什么场景组合哪些参数、如何判读输出」。
4. 04 全册禁止讲模块内部原理与结构体字段；05 全册禁止展开机制流程。
5. 交叉引用统一写法：`（字段见 05-xx ｜ 参数见 04-xx ｜ 原理见 06-xx ｜ 模块见 07-xx）`。

## 6. 三类骨架模板

**A 论述型（7 节）**
背景与动机 → 核心概念 → 关键数据结构与源码位置（**引用 05，不重列字段**）→ 关键流程与调用链 → 配置/命令/代码实例（**引用 04，不重列参数**）→ 注意事项、陷阱与最佳实践 → 小结与延伸阅读。

**B 手册字典型（7 节）**
本篇定位与覆盖范围 → 索引与全参数表 → 逐项详解 → 典型示例 → 速查表 → 版本差异 → 常见误用与调试。
05 字段表统一列：`字段 | 类型 | 含义 | 源码位置 | 读写时机 | 关联函数与流程 | 版本差异`。

**C 实战型（6 节）**
目标与拓扑 → 前置条件与环境 → 分步操作 → **验证方法与预期结果** → 常见失败与排错 → 小结。
每篇必须给「预期输出 + 判读要点」，不是只给命令。

## 8. 全量大纲（65 篇）

### 01 基础与概述（4 篇，A 型）

**01-01 Hyperscan 是什么：定位、能力矩阵与适用边界**
多正则匹配库的定义；「混合自动机」的含义；一次扫描同时匹配上万条模式的原理直觉；与「一条一条跑 PCRE」的成本对比；能力矩阵（能做/不能做）；三类典型宿主场景（IDS/IPS、DLP、WAF、日志过滤）；何时不该用 Hyperscan。

**01-02 与 PCRE / RE2 / Vectorscan / Chimera 的引擎对比**
回溯 vs 自动机 vs 混合；PCRE 的功能完整性与最坏情况复杂度；RE2 的线性时间与功能裁剪；Hyperscan 的「编译重、扫描轻、流式、无捕获」；Vectorscan 的 ARM 分支定位；Chimera = Hyperscan 预过滤 + PCRE 确认；选型决策表。

**01-03 整体架构：编译期流水线与运行时分派两层**
`parser` → `nfagraph` → `rose` → 字节码的编译期；`hs_scan` 进入 `dispatcher` 后按平台选择实现；`hs_database` / `hs_scratch` / `hs_stream` 三个运行期对象的职责；fat runtime 的意义；Chimera 在架构中的位置（见图 01-03-01）。

**01-04 版本基准、许可、生态与资料使用约定**
5.4.2 的版本来源与 CHANGELOG 关键变更（5.4.0 的 Sheng32/Sheng64/McSheng64 与 Fat Teddy、5.4.1 的十余个 bugfix、5.4.2 的 scratch 行为回退）；BSD 许可；Intel 商业版与开源版差异；Vectorscan 分支；本套资料的编号、去重、交叉引用与「需对照实际版本核验」写法。

### 02 编译与构建（5 篇）

**02-01 源码获取、仓库目录结构与依赖矩阵（A 型）**
仓库顶层布局；`src/` 十大子目录职责；`tools/`、`examples/`、`chimera/`、`doc/`、`unit/`；依赖矩阵（CMake、Ragel、Python 2.7、Boost 头、OpenSSL、libpcap）；各依赖的用途与缺失后果；编译器版本下限。

**02-02 CMake 配置项与构建变体全解（A 型）**
`BUILD_SHARED_LIBS` / `BUILD_STATIC_AND_SHARED` / `FAT_RUNTIME` / `BUILD_AVX512` / `BUILD_AVX512VBMI` / `OPTIMISE` / `DEBUG_OUTPUT` / `VALIDATE_PATTERN_INPUT` / `DUMP_SUPPORT` / `DISABLE_ASSERTS` / `BOOST_ROOT` / `CMAKE_BUILD_TYPE` 的组合语义；构建类型对断言与转储的影响；三种典型变体（生产静态、生产动态、调试可转储）。

**02-03 从零构建实战：Linux 上编译、测试与安装（C 型）**
从干净环境开始：装依赖 → `cmake` → `make -j` → `ctest` → `make install`；验证 `libhs` 与 `hscheck` 可用；`LD_LIBRARY_PATH` 与 `ldconfig`；常见失败（Ragel 缺失、Boost 找不到、OpenSSL 头缺失、Python 3 被误选）。

**02-04 Windows / MSVC、交叉编译与 Chimera 构建（A 型）**
MSVC 2017 与 `WINDOWS_ICC`；Windows 上的 Ragel 获取方式；`hs.def` / `hs_runtime.def` 导出控制；交叉编译到 ARM（Vectorscan 分支）；Chimera 需要 PCRE 与 `target_link_libraries(chimera hs pcre)`；产物清单与命名。

**02-05 fat runtime、AVX-512 变体与库形态选择（A 型）**
fat runtime 的机制（一份库、多份微架构实现、运行时分派）；`BUILD_AVX512` 与 `BUILD_AVX512VBMI` 的适用条件；`HS_CPU_FEATURES_*` 与 `hs_platform_info_t` 的关系；静态库/动态库/两者都要的权衡；数据库跨机器分发时的平台兼容性（`HS_DB_PLATFORM_ERROR`）。

### 03 集成与部署（6 篇，C 型）

**03-01 最小可用集成：编译一个数据库并扫描第一块数据**
目标：50 行以内跑通 `hs_compile` → `hs_alloc_scratch` → `hs_scan` → 释放；编译命令与链接参数；第一次扫描的预期输出；判读 `HS_SUCCESS` 与回调参数；常见错误（忘记 scratch、忘记释放、模式语法错）。

**03-02 库部署与链接：静态/动态、符号可见性与包管理**
`.so` / `.a` 的选择；`libhs.pc` 与 `pkg-config --cflags --libs libhs`；RPATH 与 `LD_LIBRARY_PATH`；静态链接时的 C++ 运行库依赖；容器镜像里最小化部署；版本升级时的 ABI 注意点。

**03-03 数据库的序列化、分发与加载**
`hs_serialize_database` → 落盘/下发 → `hs_deserialize_database`；为什么生产环境不该每次启动重编译；`hs_serialized_database_info` 与 `hs_database_info` 的用途；数据库与版本/平台的绑定；HMAC 校验失败的表现；分发目录与权限。

**03-04 多线程服务集成与 scratch 池化部署**
scratch 非线程安全的事实；每线程一份 vs 池化的取舍；`hs_clone_scratch` 的复制语义；`hs_alloc_scratch` 对多库反复调用直到 `HS_SUCCESS`；`HS_SCRATCH_IN_USE` 的成因与定位；线程数与吞吐的非线性关系。

**03-05 流式接入：TCP/文件流的分块与状态管理**
`hs_open_stream` → 多次 `hs_scan_stream` → `hs_close_stream`；块边界不影响匹配的保证；流状态大小 `hs_stream_size`；`hs_reset_stream` 复用、`hs_copy_stream` 分叉；`hs_compress_stream` / `hs_expand_stream` 做状态持久化；乱序/重放数据的后果。

**03-06 Chimera 部署与 PCRE 依赖落地**
Chimera 解决什么（需要捕获组与反向引用时）；`ch_compile` → `ch_alloc_scratch` → `ch_scan`；链接 `-lchimera -lhs -lpcre`；性能代价与适用比例；与纯 Hyperscan 的混合部署策略（先 Hyperscan 粗筛、命中后再 Chimera 确认）。

### 04 参数与 API 手册（8 篇，B 型）

**04-01 CMake 构建变量全集**
逐项列出 `CMakeLists.txt` 中所有 `option` / `CMAKE_DEPENDENT_OPTION`：名称、默认值、依赖条件、作用、取值建议、误配后果。

**04-02 编译标志 HS_FLAG_* 全集**

### 06 技术原理（14 篇，A 型）
