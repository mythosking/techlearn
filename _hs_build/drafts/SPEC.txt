## 2. 深度要求

- 每篇 **3000+ 中文字**（严格口径：排除代码块、表格行、图块 DSL 后的中文字符）。**每篇都要实打实写完**，最后一篇和第一篇一样厚实。
- 严禁出现「（略）」「待补充」「同上」「参见前文不再赘述」等占位；严禁代码块里出现裸 `...` 省略行。
- 每篇必须含：真实源码路径（如 `src/rose/rose_build.h`、`src/nfa/limex_native.c`、`src/hs_compile.h`）、关键函数/调用链、配置或代码实例、至少一个表格、至少一节「陷阱与最佳实践」或「常见误用与调试」。
- 每篇至少 **2 个代码块**，其中至少一组是「C 代码 / 命令 + 典型输出 + 150 字以上中文判读说明」（逐行解释关键字段、正常值范围、异常特征）。
- **版本基准**：Hyperscan **5.4.2**（`CMakeLists.txt` 的 `HS_MAJOR/MINOR/PATCH` 与 `CHANGELOG.md` 2023-04-19 条目）、Chimera 同版本、PCRE 8.41 及以上作为语法参照、CMake ≥ 2.8.11、Ragel 6.9、Python 2.7（构建期）、Boost 头文件 ≥ 1.57、OpenSSL libcrypto（数据库 HMAC 完整性）。凡不确定的字段名、函数签名、命令行参数、版本号，**不要编造**，写「需对照实际版本核验」并给出可定位的源码路径。
- **能力边界必须写清**（本套资料最容易写错的地方）：
  1. Hyperscan 是**编译 + 扫描库**，不是完整 DPI 产品：不做抓包、不做协议解析、不做流重组，`examples/pcapscan.cc` 只是示例。
  2. 默认只报告**匹配结束偏移**；要起始偏移必须开 `HS_FLAG_SOM_LEFTMOST`，且流式模式下受 SOM horizon 限制、超出返回 `HS_OFFSET_PAST_HORIZON`。SOM 与 `HS_FLAG_SINGLEMATCH`、`HS_FLAG_PREFILTER` **不能组合**，否则编译报错。
  3. 不支持：反向引用与捕获子表达式、任意零宽断言、子程序引用与递归、条件模式、回溯控制动词、`\C`、`\R`、`\K`（`doc/dev-reference/compilation.rst` 的 Unsupported Constructs）。
  4. **scratch 不是线程安全的**：一个并发扫描线程一份 scratch；`hs_alloc_scratch` 必须对「同时使用的最大数据库集合」反复调用直到 `HS_SUCCESS`。错误地跨线程共享会返回 `HS_SCRATCH_IN_USE` 或产生未定义行为。
  5. 数据库是**不可变**的，编译成本高、扫描成本低；生产环境应编译一次、序列化分发、`hs_deserialize_database` 加载，而不是每次启动重新编译。
  6. 流式模式要求数据按序、不可重放历史窗口之外的数据；`hs_reset_stream` / `hs_copy_stream` 才是重置与分叉的正确方式。
  7. 本仓库是 **Intel Hyperscan 开源版**；Vectorscan 是其 ARM 等平台的社区分支，二者 API 兼容但引擎支持矩阵不同，不要把 Vectorscan 的平台结论直接写成上游结论。

## 5. 配图语法（会被编译成 Word 可编辑形状 + .drawio 源文件）

每个图块用下面这种 DSL，**不要用 mermaid、不要插入图片、不要画 ASCII 图**：

```
:::figure id=06-04-01 | name=Rose 分解的四个角色与落库顺序 | dir=TD
node n1 "解析后的 NG 图" blue
node n2 "anchored 表" teal
node n3 "floating 表" amber
node n4 "suffix 表" purple
node n5 "RoseEngine 字节码" green
edge n1 -> n2 "锚定触发"
edge n1 -> n3 "无锚点模式"
edge n3 -> n4 "后缀确认"
edge n2 -> n5 "写入"
edge n4 -> n5 "写入"
:::
```

规则：
- `node <id> "<文字>" <色调>`，色调只能是 blue / teal / amber / purple / gray / red / green。
- `edge <from> -> <to> "<标签>"`；`dashed` 表示辅助/回查关系，写在标签**之前**；标签可省略。
- 节点文字用**双引号**包裹，内部不要出现双引号；可用 `<br/>` 换行。
- **单行显示宽度 ≤ 38**（中文按 2、英文按 1 计），超长必须用 `<br/>` 折成多行；不要把整句话塞进一个节点。
- 每张图节点数 **≤ 10**、边数 **≤ 12**；信息多就拆成两张图，不要堆一张。
- 节点 id 只用字母数字下划线，且块内唯一；**每个节点都必须至少连一条边**（禁止孤立节点）。
- **禁止** subgraph / classDef / style / 链接语法。
- 首行 `:::figure ...` 与末行 `:::` 必须各占一行。
- `id` 全局唯一，格式固定 `<篇章号>-<两位序号>`，如 `07-05-01`。
- 正文引用图时写「图 07-05-01 …」，**必须与图 id 完全一致**（图题、正文引用、`.drawio` 文件名三者同源）。
- 每篇至少 1 张图；每册图数不少于篇数，关键篇可 2 张。
- 图块之前要有引导句（「…的处理链路见图 06-04-01」）。

## 8. 分批写入策略（内容很大，务必分块）

- 第 1 次 Write：文件头 + 前 1–2 篇，以**唯一哨兵行** `<!--NEXT-->` 结尾。
- 之后每次用 Edit 把 `<!--NEXT-->` 替换为「后续 1–2 篇 + 新的 `<!--NEXT-->`」。
- 最后一批写完后，再 Edit **删除末尾哨兵**，文件内 `<!--NEXT-->` 残留数必须为 0。
- 每批必须真实成文；一次 Edit 可写 2 篇以控制调用次数。

## 9. 完成前自检

1. 篇数齐全、编号连续无缺无重。
2. 每篇严格中文 3000+ 字，无占位、后段不缩水。
3. 图块数量达标，每个 `:::figure` 语法合法、id 唯一、首末行完整、无孤立节点、节点文字单行 ≤38 宽。
4. 表格无错列、无 >90 字符单元格；代码块全部带语言标注且开始/结束行数相等。
5. 无 `<!--NEXT-->` 残留；正文图号引用都能对应到真实图 id。
6. 去重铁律未被破坏；没有把「只报结束偏移」写成「默认报起止偏移」，没有把 scratch 写成线程安全。
