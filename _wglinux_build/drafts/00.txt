# WireGuard Linux 技术资料 · 总目录与阅读指南（交付版）

> **项目**：WireGuard 的 Linux 内核实现（wireguard-linux 内核驱动 + wireguard-tools 用户态工具）技术资料全集
> **版本基准**：上游 stable 分支内核驱动快照（`drivers/net/wireguard/`、`include/uapi/linux/wireguard.h`、`lib/crypto/`）+ wireguard-tools 1.0.20260223；驱动版本头为 1.0.0。具体字段、函数签名、配置项一律以 `upstream_src/` 下源码为准，不确定的一律标注「需对照实际版本核验」
> **深度标准**：深度技术型，每篇 3200+ 纯叙述汉字（不含代码、表格、图块），含真实源码路径、关键数据结构、调用链、完整代码与输出判读
> **图示标准**：全部配图为 **Word 原生可编辑形状组**（DrawingML）；每张图另附同名 `.drawio` 源文件；DOCX 内零位图
> **交付形式**：**9 个 DOCX**（00 总纲 + 8 个维度册），共 **65 篇**；交付目录不含 Markdown 源文件、不含位图
> **编号规则**：`文件号-篇号`（如 `06-07`）；图号用 `文件号-篇号-图序号`（如 `06-07-01`），与正文引用、图题、`.drawio` 文件名四者一致
> **快照说明**：取材快照是内核驱动的切片，`netlink.c`、`peerlookup.c`、`generated/` 未随快照提供，`selftest/` 目录为空；凡涉及这些文件的内部实现，正文如实标注「需对照实际版本核验」，不臆造路径与取值

## 1. 结构设计与评审结论

本套资料沿用 VPP / DPDK / OpenVPN / wireguard-windows / Hyperscan / Suricata / Snort 3 / SONiC 八套资料集已验证的组织逻辑：
**按维度分册 → 唯一权威源去重 → 三类骨架 → `文件号-篇号` 编号 → 工具书前置于原理 → 运维收尾**。
针对 WireGuard Linux 作为「内核态 VPN 数据面 + netlink 配置面 + 用户态 wg 工具」的特点，做了五处调整。

| 决策 | 理由 | 落地方式 |
|---|---|---|
| 04 册定为「参数与 API 手册」 | 本项目的可配置面分散在 wg 命令行、wg-quick 配置键、ini 格式、netlink 属性与 uapi 常量、sysfs 与错误码 | 04 成为命令、参数、常量、错误码的唯一权威源，其余册只给最小必要片段 |
| 05 册前置于 06 | `wg_device` / `wg_peer` / `allowedips` / `noise_*` / `endpoint` 等结构是理解收发流水线的前置知识 | 05 定位「工具书·随查」，逐字段展开，不参与线性阅读主线 |
| 06 册增加到 14 篇 | 核心复杂度集中在协议与并发：Noise_IK 状态机、密钥轮换、收发路径、trie 查找、抗重放、cookie、限速、定时器、GSO/GRO、多核 RCU | 06 用 14 篇逐机制展开，是全册的机制权威源 |
| 07 册按真实源文件设 13 篇 | 模块边界与 `drivers/net/wireguard/` 下的 `.c` 文件一一对应，避免「按概念编模块」的虚设章节 | 每篇对应一个真实源文件（族），给对外函数清单与职责 |
| 08 册单列性能基准 | WireGuard 的性能由包长、队列、GSO、CPU 加密指令共同决定，且用户常被「线速」误导 | 08 给可复现测量方法，明确拒绝编造绝对吞吐数字 |

评审中明确排除的做法：

| 级别 | 曾经的风险 | 本套的处理 |
|---|---|---|
| 结构 | 把 wg 命令参数、netlink 属性在多册重复展开 | 04 为唯一权威源，其余册写「参数见 04-xx」 |
| 骨架 | 手册型章节套论述型骨架，出现空泛「背景与动机」 | 分 A 论述 / B 手册字典 / C 实战三类骨架 |
| 边界 | 把 WireGuard Linux 与其他实现（wireguard-go / wireguard-nt / VPP 插件）混为一谈 | 01-01、01-02 明确实现形态与性能差异，非本项目实现只作定性对照 |
| 事实 | 快照缺文件却编造 sysfs 属性、netlink 内部实现、selftest 日志 | 相关篇如实标注快照缺口，标注「需对照实际版本核验」 |
| 性能 | 给绝对吞吐数字、断言固定线程数 | 08 全册标注「需在目标机型实测」，不给承诺值 |
| 配置 | 把 wireguard-go 的用户态模型套到内核实现 | 全册以内核模块 + netlink 为准，用户态工具只作配置通道说明 |

## 2. 唯一权威源与去重规则

本套资料按内容性质划归唯一权威源，各册写法约束如下。

| 内容 | 唯一权威源 | 其余册的写法 |
|---|---|---|
| wg 命令、wg-quick 参数、ini 配置格式、netlink 命令与属性、uapi 常量、sysfs 接口、错误码 | **04 全册** | 只给本场景最小必要调用，写「参数见 04-xx」 |
| 结构体逐字段（`wg_device` / `wg_peer` / `allowedips` / `noise_*` / `endpoint` / `cookie` / `ratelimiter` / 队列 / 消息结构等） | **05 全册** | 只点名 + 真实源码路径 +「（字段见 05-xx）」 |
| 机制、状态机与调用链（握手、密钥轮换、收发、trie 查找、抗重放、cookie、限速、定时器、GSO/GRO、并发、netlink） | **06 全册** | 讲「做什么」不讲「怎么实现」，写「原理见 06-xx」 |
| 模块能力与特性（按 `drivers/net/wireguard/` 真实源文件划分的模块） | **07 全册** | 写「模块见 07-xx」 |
| 运维场景组合、基准方法、诊断树、案例库、加固、上线清单 | **08 全册** | 其余册不展开运维步骤 |

强制约束：

1. 06 / 07 / 08 全册禁止出现完整结构体字段表，改为 `（字段见 05-xx）`。
2. 07 全册每篇代码段最多 3–5 个本模块最典型的调用，其余写「完整 API 见 04-xx」。
3. 08 全册禁止重列参数清单，只讲「在什么场景组合哪些参数、如何判读输出」。
4. 04 全册禁止讲模块内部原理与结构体字段；05 全册禁止展开机制流程。
5. 交叉引用统一写法：`（字段见 05-xx ｜ 参数见 04-xx ｜ 原理见 06-xx ｜ 模块见 07-xx）`。

## 6. 三类骨架模板

**A 论述型（7 节）**
背景与动机 → 核心概念 → 关键数据结构与源码位置（**引用 05，不重列字段**）→ 关键流程与调用链 → 配置/命令/代码实例（**引用 04，不重列参数**）→ 注意事项、陷阱与最佳实践 → 小结与延伸阅读。

**B 手册字典型（7 节）**
本篇定位与覆盖范围 → 索引与全参数表 → 逐项详解 → 典型示例 → 速查表 → 版本差异 → 常见误用与调试。
05 字段表统一列：`字段 | 类型 | 含义 | 源码位置 | 读写时机 | 关联函数与流程 | 版本差异`。

**C 实战型（6 节）**
目标与拓扑 → 前置条件与环境 → 分步操作 → **验证方法与预期结果** → 常见失败与排错 → 小结。
每篇必须给「预期输出 + 判读要点」，不是只给命令。
