# 交换芯片技术资料 · Teralynx 10（98TX9180）功能、流水线与参数

## TL10-01 产品定位与应用场景

### 1. 一句话定位

Teralynx 10（料号 98TX9180）是 Marvell 面向云数据中心与 AI 集群的 51.2Tbps 全双工交换处理器，2023 年 3 月发布、2024 年 7 月进入规模量产。它采用 5nm 单片（monolithic）设计，集成 512 条 112G 长距（LR）SerDes，支持最高 512 端口 Radix。官方把它定位为"业界最低时延的可编程交换系列"，核心卖点是低且确定的时延、高 Radix、低功耗与线速可编程转发。

Teralynx 架构来自 Marvell 于 2021 年收购的 Innovium，是全新设计（clean-sheet）的产品线，与 Marvell 原有的 Prestera 企业交换芯片是两条独立路线。理解这个出身很重要：Teralynx 从一开始就以超大规模云数据中心为目标，而不是从企业交换芯片向上扩展，这解释了它为何在时延、遥测和可编程性上有独特设计。

### 2. 四类目标场景

官方列出的部署场景包括：

1. **云与通用数据中心网络**：公有云、私有云、混合云基础设施，ToR、leaf、spine 各层；
2. **AI/ML 训练与推理 fabric**：作为后端集群互联，承载 RoCEv2 无损流量；
3. **HPC 高性能计算互联**：低时延、确定性转发适合紧耦合计算；
4. **数据中心互联（DCI）与高端企业网**：借助隧道与多级 QoS 能力。

同一颗芯片通过可编程配置可用于不同位置——官方称单个设备可在 ToR、spine/leaf、edge 以及 AI 前端/后端集群之间切换角色，这是"一次投片、多种用途"的投资保护设计。

### 3. 三大架构积木

官方产品简介把 Teralynx 10 的能力归纳为三大 building blocks，这是理解整颗芯片的骨架：

1. **可编程且功能丰富的转发流水线**：以确定性低时延提供完整数据中心特性集，并通过可置换的弹性转发（permutable flex-forwarding）支持新协议；
2. **高可扩展 fabric**：低时延交换与缓冲架构，提供完整 QoS、流量管理和大包缓冲；
3. **Teralynx Flashlight 遥测与分析**：从零构建的遥测架构，提供实时、细粒度的网络可见性与可操作分析。

## TL10-02 功能特性全景

### 1. 官方功能清单

Marvell 官方产品简介列出的关键功能如下，逐项归类说明：

- **交换容量**：最高 51.2Tbps，配大缓冲；
- **SerDes**：最多 512 条 100G SerDes，支持 25G、50G、100G I/O 速率，强调经过验证的互操作性，并向后兼容 25G NRZ；
- **时延**：在直通（cut-through）与存储转发（store-and-forward）两种模式下都具备业界领先低时延；
- **遥测**：Flashlight 可见性与遥测，支持 P4 带内网络遥测（INT）及关键扩展；
- **可编程**：线速可置换弹性转发，支持通过软件升级适配新协议，无需重新流片；
- **转发**：全面 IP 转发，含拥塞感知路由；高度可扩展灵活的二层/三层表，支持 IPv4、IPv6 与混合网络；
- **隧道**：IP-in-IP、GRE、MPLS、VXLAN、Geneve；
- **QoS**：高级 QoS/流量管理特性集，含 DCB 与 RoCE；
- **时序**：PTP（IEEE 1588v2）与 SyncE 支持。

### 2. 可编程转发为什么重要

"线速可编程且对时延无影响"（latency-transparent programmability）是 Teralynx 10 反复强调的差异化点。传统交换 ASIC 的功能在流片时固化，遇到新协议或新遥测格式只能等下一代芯片。Teralynx 10 的做法是把转发流水线设计成可置换的——新协议可以通过软件升级加载，而不改变包处理容量与时延。

这个能力的现实价值在于 AI 网络的快速演进。Ultra Ethernet、在网计算、新型拥塞控制协议都在标准化过程中，若每次协议变化都要换芯片，运维成本不可接受。可编程流水线让同一硬件能跟随协议演进，这正是官方所说"保护投资、支持重新配置"的含义。

### 3. Flashlight 遥测的定位

Flashlight 不是附加的监控接口，而是从零设计的遥测架构。官方描述其提供"广泛的实时可见性与细粒度的可操作网络分析"，用于快速排查网络问题、提升网络韧性与在线时间。它支持 P4 INT 及关键扩展，能够做预测性分析、快速故障隔离和自动修复，目标是"自感知、自愈网络"。在 SONiC 环境中，Flashlight 的原生流遥测与微突发检测能力可以简化带内网络遥测的集成。

官方产品简介给出了几个典型整机形态，说明同一芯片如何覆盖不同速率需求：

- **51.2T 配置**：1U 机箱 32×1.6T（OSFP-XD），或 2U 机箱 64×800G（OSFP 或 QSFP-DD800）；

这些例子说明 Teralynx 10 支持端口速率的灵活切分：既可做满速 800G 主干，也可降到 400G、200G 以增加端口数。注意到 51.2T 与 25.6T 两类系统用的是同一颗芯片，只是启用的 SerDes 通道数与聚合方式不同——这是高 Radix 芯片的典型用法。

### 3. 时延数字的口径说明

官方新闻稿给出的时延是"低至 500ns"，合作方在系统测试中给出"满载 cut-through 约 560ns、全包长 sub-600ns"。这两个数字并不矛盾：前者是芯片在理想条件下的最优值，后者是整机满载与不同包长下的实测范围。选型时应索取针对具体配置（包长、是否开启深度缓冲与 VLAN 改写）的带载时延报告，不要用单一最优数字做决策。这一点与博通 Tomahawk 系列相同——所有厂商标称时延都是 cut-through 理想值，实际会随功能开启而漂移。

## TL10-04 数据包处理流水线

### 1. 官方框图揭示的结构

与博通不同，Marvell 官方产品简介公开了 Teralynx 10 的功能框图，这让我们可以较有把握地描述其流水线结构。框图显示的数据通路是：512 个以太网 MAC → PCS 与 FEC → 512 条 112G SerDes → 各类处理引擎 → 低时延 fabric → 大包缓冲 → 出口。处理引擎一侧包含低时延 fabric、大包缓冲、全面 QoS、自定义可编程、入口/出口策略、入口/出口监管器、稳健的 L2/L3 转发、全面隧道。控制侧则包括嵌入式 Arm 微控制器、安全控制、Flashlight 可见性与分析引擎、扩展遥测与高级分析，通过 PCIe 3.0 x4 与 2 个 1/10G 管理口连接。

### 2. 转发流水线的三段理解

把框图按转发路径整理，可以得到三段式的功能理解：

1. **入口段**：端口解码后进入入口策略与监管（ingress policy / policers），完成 L2/L3 转发决策与隧道处理。这一段的关键是"确定性低时延"——无论包长与功能组合，时延保持在窄范围内。
2. **交换与缓冲段**：低时延 fabric 把包送到目标，大包缓冲配合全面 QoS 处理拥塞。这是 microburst（微突发）吸收的主要位置。
3. **出口段**：出口策略与监管、重写后发送。

贯穿三段的是可置换弹性转发：协议相关的处理逻辑可通过软件加载，不需要改硬件。这与固定的 ASIC 流水线形成对比。

### 3. 转发配置示意与判读

下面用示意片段展示"同一芯片不同角色"的配置思路，用于理解可编程转发，不是真实 SDK 命令，字段名需对照实际 SDK 核验。

```text
# 示意配置：同一颗 Teralynx 10 的两种角色（非真实 SDK 命令）
profile leaf:
  ports = 64 x 800GbE
  forwarding = ipv4_ipv6 + vxlan
  qos = dcb + rocev2
profile spine:
  ports = 128 x 400GbE
  forwarding = ipv4_ipv6 + congestion_aware_routing
  telemetry = flashlight_int_enabled
```

对这段配置的判读：`leaf` profile 把芯片配成 64 个 800G 端口，转发特性侧重 VXLAN 与 RoCEv2，对应 AI 后端接入层；`spine` profile 降到 128 个 400G 端口，转发侧重拥塞感知路由，并开启 Flashlight INT 便于主干监控。两者容量都是 51.2Tbps，差异只在端口聚合与特性组合。这个例子印证了官方"同一设备可在多场景部署"的说法——硬件相同，角色由配置决定。需要强调，真实平台的配置涉及 SDK 表项、SAI 对象与 NOS 集成，远不止示意片段中的几行。

## TL10-05 Flashlight 遥测与分析

### 1. 设计目标

Flashlight 的设计目标是把网络从"出问题后排查"变成"实时可见、自动隔离、预测性修复"。官方强调细粒度的实时可见性与可操作分析，具体包括：流级别的遥测、微突发检测、逐端口队列深度上报、P4 带内网络遥测及扩展。这些数据用于快速故障隔离、预测性分析与自动修复。

微突发检测是其中最有价值的一项。在传统监控体系里，SNMP 计数器以秒级粒度轮询，而 AI 训练的微突发可能只持续几十微秒——等轮询到时，拥塞已经发生并造成丢包。Flashlight 在硬件里持续采样队列深度与丢弃事件，能在微秒尺度上捕捉瞬时拥塞，并上报给分析引擎。这把"事后从日志里找原因"变成"发生时即留痕"。

### 2. 遥测数据示例与判读

下面用示意的遥测输出展示 Flashlight 提供的数据粒度。这是格式示意，字段名需对照实际 SDK 与遥测接口核验。

```text
# 示意遥测输出：逐端口微突发与队列深度（非真实接口）
port   queue_depth_peak   microburst_us   drop_cnt   timestamp
0/1    18432              47             0          2026-11-20T14:03:11.882Z
0/2    20116              82             3          2026-11-20T14:03:11.884Z
0/3    2048               5              0          2026-11-20T14:03:11.885Z
```

对这段输出的判读：`queue_depth_peak` 是采样窗口内的队列深度峰值，`microburst_us` 是微突发持续时间，`drop_cnt` 是丢弃计数。端口 0/2 的队列峰值最高、微突发持续 82 微秒且已经出现 3 个丢包，是被定位的拥塞点；端口 0/1 峰值略低但同样出现近 47 微秒的突发，尚未丢包，属于预警状态；端口 0/3 深度与突发都正常。三条记录的时间戳集中在毫秒级窗口内，说明这是同一时刻的全网快照——正是这种细粒度、对齐的时序数据，让故障隔离从"猜哪个端口"变成"直接读出哪个端口"。若运行在 RoCEv2 无损网络，端口 0/2 的丢包足以触发 PFC 传播甚至训练任务停顿，因此 Flashlight 的价值不只是可观测，更是把可观测性转化为自动修复的输入。

### 3. 与 SONiC 生态的结合

Teralynx 10 通过开放 SDK 与 OCP SAI（交换抽象接口）提供原生 SONiC 支持。SAI 是白盒交换机软件栈的关键抽象层，让 NOS 不依赖具体芯片。官方称 Teralynx 全系列共享通用 SDK，与上一代 Teralynx 7 软件完全兼容，降低迁移成本。需要注意的是，第三方评估指出 Teralynx 的 SAI 成熟度仍在演进——大型云厂商已完成移植，但通用场景的 SAI 特性完备性需在具体 SKU 与分支版本上核验。这一点对选型很关键：若目标是 SONiC，务必确认所用 SAI 分支对具体芯片型号的特性支持是否齐全。

## TL10-06 生态、对比与小结

### 1. 与 Tomahawk 6 的定位差异

Teralynx 10 与 Tomahawk 6 并非同一代产品——前者 51.2T、2024 年量产，后者 102.4T、2026 年量产，差一代。真正同代对标的是 Teralynx 100（T100，102.4T、3nm、2026 年发布送样）。因此把 Teralynx 10 与 TH6 放在一起比较，要理解为"不同代际的市场定位差异"，而非同规格竞品。

| 维度 | Teralynx 10（本册） | Tomahawk 5（同代对标） | Teralynx 100（下一代） |
|---|---|---|---|
| 容量 | 51.2T | 51.2T | 102.4T |
| 制程 | 5nm 单片 | 5nm | 3nm 单片 |
| 量产时间 | 2024-07 | 2023 | 送样中 |
| 核心卖点 | 低时延 + Flashlight | 生态 + 大规模部署 | 低功耗第二供应 |
| 软件 | 开放 SDK + SAI + SONiC | 成熟 NPL + BroadView | 延续开放生态 |

注：Tomahawk 系列细节见配套文档 Tomahawk 6 分册。表中量产时间与参数为公开口径，功耗与时延未做第三方归一化。

### 2. 交叉引用与小结

1. **定位**：Teralynx 10 是 51.2T、5nm 单片交换芯片，2024 年量产，源自 Innovium 架构，面向云数据中心、AI fabric 与 HPC。
2. **参数**：512 条 112G LR SerDes，最高 512 端口 Radix，时延低至 500ns，功耗约 1W/100GbE。
3. **流水线**：官方公开功能框图，可描述为入口策略与监管、L2/L3 转发与隧道、低时延 fabric 与大缓冲、出口处理四段，可置换弹性转发贯穿其中。
4. **差异化**：低且确定的时延、Flashlight 细粒度遥测、线速可编程转发、开放 SDK 与 SONiC 生态。
5. **边界**：时延与功耗为厂商标称，SAI 成熟度需按具体 SKU 核验；与 TH6 非同代，同代对标是 Teralynx 100。
6. **结论**：Teralynx 10 的价值不在纸面参数领先，而在"低功耗 + 确定性时延 + 开放生态"组合，适合作为第二供应来源与功耗敏感场景的选择。
