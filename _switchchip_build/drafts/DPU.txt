# DPU 与 FPGA 超融合可编程平台：网络业务的芯片卸载

## DPU-01 先建立坐标系：什么是超融合可编程平台

服务器里 CPU 负责通用计算，但网络、存储、安全这些“基础设施任务”会消耗大量 CPU 周期。DPU（Data Processing Unit，数据处理器）就是把这些任务从 CPU 卸载下来的一类专业处理器：它是一块带多核 CPU、专用加速引擎和高速网络接口的卡，运行自己的操作系统，独立完成网络转发、存储虚拟化、安全策略等数据基础设施工作，让主机 CPU 专注于业务计算。FPGA 则提供更高灵活性的硬件可编程能力，用硬件描述语言定制数据通路，适合极致延迟或特殊算法的加速。

岗位描述里“利用 P4 可编程芯片、DPU、FPGA，研发超融合可编程平台，实现网关、边缘、在网计算等网络业务的芯片卸载”，核心是把三类可编程能力（P4 交换芯片、DPU、FPGA）整合到一个平台，让网络业务能按需选择最合适的承载方式：线速转发和简单处理交给 P4 芯片，复杂的协议栈和状态管理交给 DPU，极致延迟或特殊算法交给 FPGA。**超融合**的含义是把原本分散的网关、防火墙、负载均衡、存储等网元功能融合到统一平台，用软件定义，而不是堆叠一堆专用设备。

理解这个定位，要先破除一个误区：DPU 不是“更强的网卡”，也不是“替代 CPU”。它是把数据面基础设施下沉到离网络更近的位置，形成主机侧和网络侧之间的一个新计算层。这个层的位置特殊——它既在服务器里（能看到主机状态），又贴近网络（能线速处理报文），因此在端网融合、在网计算里扮演枢纽角色。

## DPU-02 DPU 架构：多核、加速引擎与数据通路

一块典型 DPU 包含几个部分：**多核 CPU 子系统**（常用 ARM 核，运行 Linux 或实时系统，处理控制面和复杂协议）、**网络接口**（高速以太网端口，如 100G/200G/400G）、**专用硬件加速引擎**（如 OVS 卸载、TLS/IPsec 加密、NVMe 存储、RDMA/VirtIO 卸载）、**片上内存与 DMA 引擎**（高效搬运数据）、以及**与主机的接口**（PCIe，向主机呈现为网卡或存储设备）。这些部件协同，让 DPU 能独立处理原本属于主机的数据面任务。

DPU 的软件栈通常分两层：DPU 上跑自己的控制面和系统软件，主机上跑业务和驱动，二者通过virtio、PCIe BAR 或专用通道通信。以网络卸载为例，主机的 OVS（开放虚拟交换机）数据通路被卸载到 DPU 的硬件加速引擎，OVS 控制面仍在主机或 DPU 上计算流表，流表下发到 DPU 硬件执行。这样虚拟交换的报文不必再绕主机 CPU，延迟下降、吞吐上升、CPU 占用大幅减少。

| DMA 引擎 | 高效数据搬运 | 零拷贝、内存访问 |
| PCIe 接口 | 连接主机 | 设备呈现与通信 |

## DPU-03 芯片卸载的核心思想：什么该卸载、怎么卸载

芯片卸载的本质是把“CPU 做起来慢且费资源、硬件做起来规整高效”的任务搬到专用硬件。判断一个任务该不该卸载，有几个标准：一是**计算规整**，如报文头解析、查表、加解密，硬件容易做；二是**数据量大**，卸载的收益足以覆盖搬运成本；三是**延迟敏感**，如虚拟交换、RDMA，硬件能显著降延迟；四是**状态可控**，状态规模在硬件能力内。反过来，逻辑复杂多变、分支多、状态巨大的任务，留在 CPU 更合适。

卸载的技术路径通常是：把数据通路的关键路径固化到硬件，控制面仍由软件计算并下发规则。以 OVS 卸载为例，流表的“慢路径”（首包、复杂匹配）在软件里处理，匹配结果以“快路径”规则写入硬件；后续同类报文直接命中硬件规则转发，不再上送软件。这种快慢路径分离是卸载的通用模式——软件保灵活性，硬件保性能，二者通过规则表衔接。

下表列出适合与不适合卸载的任务特征。

| 特征 | 适合卸载 | 适合留在 CPU |
|---|---|---|
| 计算形态 | 规整、可并行 | 复杂分支、多依赖 |
| 数据量 | 大 | 小 |
| 延迟要求 | 敏感 | 宽松 |
| 状态规模 | 可控 | 巨大 |
| 变化频率 | 稳定 | 频繁变化 |

下表列出常见卸载任务及其收益。

| 卸载任务 | 收益 | 典型实现 |
|---|---|---|
| 虚拟交换 | 降延迟、省 CPU | OVS 硬件卸载 |
| 加密解密 | 提吞吐 | TLS/IPsec 引擎 |
| 存储 | 省 CPU、提 IOPS | NVMe 卸载 |
| RDMA | 降延迟、零拷贝 | RoCE 卸载 |

## DPU-04 FPGA 加速：用硬件描述语言定制数据通路

FPGA（现场可编程门阵列）与 DPU、P4 芯片的差别在于编程范式：它用硬件描述语言（Verilog、VHDL）或高层综合工具描述电路结构，直接定义数据在硬件里怎么流动。这带来最高的灵活性和最低的延迟——你可以为某个算法设计专门的流水线，没有通用处理器的取指译码开销。代价是开发门槛高、周期长，且主频通常低于专用芯片，复杂控制逻辑用 FPGA 实现并不划算。

在网络场景，FPGA 适合做极致延迟的交易网络加速、特定协议的硬件解析、定制的加解密或压缩、以及需要精确时序的测量。DPU 里也常集成 FPGA 或可编程逻辑，作为通用核之外的加速补充。岗位里提到 FPGA，主要是看中它在“超融合可编程平台”里承担特殊加速角色——不是所有业务都适合 DPU 的通用架构，有些长尾需求要靠 FPGA 灵活实现。

下面是一段极简的 Verilog 片段，展示 FPGA 如何用一个时钟周期完成报文头字段的提取，体现硬件并行处理的思想。

```verilog
// 在时钟沿并行锁存报文头字段（示意）
module header_extract (
    input wire clk,
    input wire [7:0] data_in,
    output reg [15:0] ether_type,
    output reg valid
);
    reg [7:0] shift [0:1];
    always @(posedge clk) begin
        shift[1] <= shift[0];
        shift[0] <= data_in;
        ether_type <= {shift[0], data_in};
        valid <= (ether_type == 16'h0800);
    end
endmodule
```

对这段代码的判读：模块在每个时钟沿把输入字节移入移位寄存器，并拼成 16 位的以太网类型字段；当该字段等于 0x0800 时拉高 valid，表示这是 IPv4 报文。要点是这些操作在同一个时钟沿并行完成，没有软件逐条指令的开销，这正是 FPGA 低延迟的来源。真实设计要处理字节对齐、流水线时序和跨时钟域，这里只是示意硬件并行的思维方式。

下表对比 FPGA 与其他可编程平台。

| 维度 | FPGA | DPU | P4 芯片 |
|---|---|---|---|
| 编程方式 | 硬件描述语言 | 软件加 SDK | P4 语言 |
| 灵活性 | 极高 | 高 | 中高 |
| 延迟 | 极低且确定 | 低 | 低 |
| 开发周期 | 长 | 中 | 短中 |
| 主频 | 较低 | 高 | 专用 |
| 适合 | 特殊算法 | 通用卸载 | 线速转发 |

下表列出 FPGA 在网络加速中的典型应用。

| 应用 | 为什么用 FPGA |
|---|---|
| 金融交易网络 | 纳秒级确定性延迟 |
| 协议解析加速 | 自定义硬件解析逻辑 |
| 加解密压缩 | 定制流水线提吞吐 |
| 精密测量 | 精确时序打时间戳 |

FPGA 是工具箱里的“特种工具”，用得好能解决别人解决不了的问题，但用错场景会事倍功半。

## DPU-05 端网融合：DPU 在端网协同中的枢纽作用

端网融合指主机侧和网络侧打破边界、协同工作，让网络能感知应用需求、应用能利用网络能力。DPU 正处在这个融合点上：它位于服务器内，能看到虚拟机的网络行为、应用的通信模式；它又连接高速网络，能执行网络侧的策略和遥测。这种双重身份让它能做纯网络设备和纯主机软件都做不到的事。

一个典型例子是分布式负载均衡：传统方案靠中心负载均衡器，容易成为瓶颈；端网融合方案把负载均衡决策下沉到每台服务器的 DPU，DPU 根据本机的负载和网络状况做流量调度，控制面集中协调、数据面分布执行。另一个例子是细粒度遥测：DPU 可以在报文进出主机时打上精确时间戳和状态标记，网络侧 P4 芯片再补充转发路径信息，两端数据结合，得到端到端的全链路视图。这些都是岗位描述里“端网融合”的具体形态。

| 拥塞协同 | 端侧速率调整 | 网侧拥塞反馈 |

## DPU-06 超融合平台的软件栈：从驱动到编排

超融合平台的难点不只在硬件，更在软件栈。一个完整的平台需要几层软件：**设备驱动层**让主机识别并使用 DPU/FPGA；**数据面层**运行 OVS、虚拟交换、RDMA 等卸载数据通路；**控制面层**负责流表、策略、配置的计算和下发；**编排层**与 Kubernetes、云平台对接，实现业务的自动部署和弹性伸缩。这些层要协同工作，还要和已有的 SONiC、FRR 等网络软件栈互通。

对交换机软件工程师而言，最相关的是数据面与控制面之间的接口——如何把网络策略翻译成硬件可执行的规则，如何保证规则的一致性和热更新，如何观测硬件实际的执行状态。这些能力和前面写的 SAI、P4Runtime 是相通的：本质上都是“控制面描述意图、数据面高效执行、中间有标准接口”的架构思想。

下面是一段 OVS 卸载的配置示例，展示如何把虚拟交换数据通路卸载到硬件。

```text
# 在 DPU 上配置 OVS 硬件卸载（示意命令）
ovs-vsctl set Open_vSwitch . other_config:hw-offload=true
ovs-vsctl add-br br0
ovs-vsctl add-port br0 pf0
# 查看硬件卸载的流表
ovs-appctl dpctl/dump-flows -m type=offloaded
# 验证网卡侧 representor 与卸载状态
ethtool -k pf0 | grep hw-tc-offload
```

对这段命令的判读：第一条打开 OVS 的硬件卸载开关；接着创建网桥 br0 并把物理端口 pf0 加入；第三条查看已经卸载到硬件的流表，offloaded 标记表示这些流由硬件直接处理；最后用 ethtool 确认网卡的硬件卸载特性已开启。要点是卸载后报文不再经过主机 OVS 软件数据通路，而是在 DPU 硬件里匹配流表转发，只有未命中的首包才上送软件学习。

下表列出超融合平台软件栈的分层。

| 层次 | 主要组件 | 职责 |
|---|---|---|
| 驱动层 | PCIe 驱动、virtio | 设备识别与通信 |
| 数据面层 | OVS、RDMA、加密引擎 | 高性能数据通路 |
| 控制面层 | 流表计算、策略管理 | 决策与规则下发 |
| 编排层 | Kubernetes、云平台 | 业务部署与弹性 |

## DPU-07 典型业务卸载案例：网关、边缘与安全

把前面的能力落到具体业务，能更清楚看到超融合平台的价值。**网关卸载**：云上虚拟私有云的网关要处理大量东西向和南北向流量，传统集中网关是瓶颈；把网关数据面卸载到 DPU，每台服务器就近处理，控制面集中管理，既扩容又降延迟。**边缘卸载**：边缘节点资源有限、场景多样，DPU 可以在不占用主机 CPU 的前提下完成转发、安全、遥测，让边缘设备兼顾性能和功能。**安全卸载**：防火墙、DDoS 过滤、加密通信等安全任务放到 DPU 硬件，实现线速防护而不拖慢业务。

案例的共同模式是：把数据面的重复、规整、量大、延迟敏感的部分下沉到硬件，控制面保留在软件里灵活决策。这也解释了为什么岗位要“超融合”——把网关、边缘、安全这些原本分散的功能融合到一个可编程平台，用统一的硬件和软件栈承载，运维和迭代成本都下降。

下表把典型业务的卸载方案整理出来。

| 业务 | 传统形态 | 卸载方案 | 收益 |
|---|---|---|---|
| VPC 网关 | 集中网关设备 | DPU 分布式网关 | 扩容、降延迟 |
| 边缘节点 | 专用边缘设备 | DPU 多功能融合 | 省资源、灵部署 |
| 安全防护 | 专用防火墙 | DPU 硬件过滤 | 线速防护 |
| 存储 | 主机软件 IO | DPU NVMe 卸载 | 提 IOPS 省 CPU |

下表列出卸载方案的关键设计点。

| 设计点 | 说明 |
|---|---|
| 快慢路径划分 | 首包软件、后续硬件 |
| 规则一致性 | 软硬件表项保持同步 |
| 热更新 | 规则变更不中断转发 |
| 可观测性 | 硬件执行状态可见 |

## DPU-08 小结与在岗位中的位置

把这篇串起来：超融合可编程平台把 P4 芯片、DPU、FPGA 三种能力整合，让网络业务按需选择承载方式；DPU 用多核 ARM 加硬件加速引擎，把网络、存储、安全任务从主机 CPU 卸载；芯片卸载的关键判断是“规整、量大、延迟敏感、状态可控”，实现上采用软件慢路径加硬件快路径的模式；FPGA 提供极致灵活和延迟，适合特殊算法；端网融合让 DPU 成为连接主机侧与网络侧的枢纽；软件栈从驱动、数据面、控制面到编排，与现有网络软件栈协同。

回到岗位，这篇对应“利用 DPU、FPGA 研发超融合可编程平台、实现网络业务芯片卸载”这一条。下一篇给出在网计算、端网融合、RDMA 高性能网络的解决方案层级内容——按你的要求，只讲方案，不展开过深的底层原理。三篇 P4 相关的文档加上这篇，共同覆盖岗位里“P4 可编程 + 在网计算 + 端网融合 + 芯片卸载”的完整技术栈。
