# 交换芯片技术资料 · Tomahawk 6（BCM78910）功能、流水线与参数

## TH6-01 产品定位与应用场景

### 1. 一句话定位

Tomahawk 6（芯片型号 BCM78910 系列）是博通 StrataXGS 产品线的旗舰交换 ASIC，单芯片提供 **102.4 Tbps** 交换容量，于 2025 年 6 月发布、2026 年 3 月进入规模量产，是全球首款达到 102.4T 的单芯片以太网交换芯片。它采用台积电 3nm 工艺，主要面向 AI 训练与推理集群的 scale-up（纵向扩展）与 scale-out（横向扩展）网络，同时覆盖数据中心汇聚、Spine 与模块化机箱交换机。官方明确其生命周期状态为 Active（在售）。

从产品代际看，Tomahawk 系列保持了约两年带宽翻倍的节奏：Tomahawk 3 为 12.8T（2017 年）、Tomahawk 4 为 25.6T（2019 年）、Tomahawk 5 为 51.2T（2022 年发布、2023 年规模供货）、Tomahawk 6 为 102.4T（2025 年发布、2026 年量产）。理解这条节奏线很重要，因为它解释了为什么这款芯片的很多设计取舍都围绕"AI 集群"而非传统云网络——它诞生的时点正是大规模 GPU 集群把网络从后台连接资源变成算力瓶颈的阶段。

### 2. 三类核心应用

官方列出的应用场景可以归为三类，每一类对芯片的要求不同：

1. **AI scale-up 集群**：最多连接 512 个 XPU（加速器单元，泛指 GPU、TPU、NPU 等）。scale-up 指同一计算域内紧耦合的加速器互联，要求极低时延、无损传输与集合通信卸载。这个场景是 Tomahawk Ultra 与 Tomahawk 6 的交界处，Tomahawk 6 靠 512 端口的高 Radix 用单层交换即可连满 512 个 XPU。
2. **AI scale-out 集群**：超过 100 万个 XPU 的超大规模网络，官方称在 200Gbps/链路下用两层拓扑即可连接 10 万个以上 XPU。这个场景看重高 Radix 带来的扁平化——减少网络层数直接等于减少跳数、减少光模块与线缆数量、缩短任务完成时间。
3. **通用数据中心**：汇聚与 Spine 交换机、固定形态与模块化机箱交换机、云计算基础设施。这一层看重的是单芯片替代多芯片方案、StrataXGS 软件兼容带来的低迁移成本。

### 3. 高 Radix 为什么是核心卖点

"Radix"（端口基数）指单芯片支持的同等速率端口数量。Tomahawk 6 支持业界最高的 200GbE 端口数：单芯片 512 个。这个数字的意义在于网络拓扑的层数。传统三层 Clos 架构（接入—汇聚—核心）需要更多交换机、更多光链路和更多跳数；若单芯片能做 512 个 200G 端口，则可用两层甚至单层架构连接同等规模集群。

对 AI 训练而言，跳数减少的价值是直接的：all-reduce、all-gather 等集合通信在数千个加速器之间频繁同步，每一跳都增加时延和潜在拥塞点。网络时延下降会缩短任务完成时间，也就是降低单次训练的成本。下图把三类应用与高 Radix 的作用画在一起。

## TH6-02 功能特性全景

### 1. 官方列出的功能清单

博通官方产品页给出的特性可以逐条拆开，这些是文档后续各章的事实基础：

- **完整 L2/L3 线速处理能力**：在最大端口密度下以线速完成二层交换、三层路由与隧道封装，并支持单次通过的 VXLAN 路由与桥接（single-pass VxLAN routing and bridging）。
- **业界最先进的 102.4Tbps 包缓冲架构**：官方强调这不是单纯的缓冲容量，而是缓冲吞吐能力，目标是让 RoCEv2 等新型 RDMA 协议获得最低尾时延。
- **高级自适应路由与动态负载均衡**：针对 AI/ML 工作负载典型的"大流、低熵流"特征设计。
- **端到端拥塞控制**：支持端到端拥塞控制能力。
- **任意拓扑支持**：scale-up、Clos、rail-optimized、rail-only、torus 等。
- **硬件链路故障切换**：基于硬件的链路故障恢复，提升网络韧性并降低任务完成时间。
- **Ultra Ethernet 兼容**：符合超以太网联盟规范。
- **StrataXGS 软件兼容**：整个 StrataXGS 产品组合保持软件兼容，简化客户设计、缩短上市时间。

### 2. Cognitive Routing 2.0

在众多特性中，最值得单独理解的是 Cognitive Routing 2.0（认知路由 2.0）。它不是单一功能，而是一组面向 AI 流量的硬件机制集合，公开资料列出的组成包括：高级遥测、动态拥塞控制、快速故障检测与报文修剪（packet trimming）。

之所以需要这套机制，根源在于 AI 流量的统计特性。传统数据中心流量由成千上万个独立连接组成，标准 ECMP（等价多路径）哈希能较好地把它们分散到多条路径。但 AI 训练产生的是同步的"象流"——许多节点在同一时刻发送相似的数据模式。标准哈希在这种情况下会把多条象流映射到同一路径，导致部分路径过载、其他路径空闲。Cognitive Routing 2.0 的做法是实时监测拥塞，自动把流从热点路径引导开，并在链路故障时由硬件直接重路由，不等控制面收敛。

### 2. BCM78910 与 BCM78914 的关键差异

Tomahawk 6 系列内有两个主要子型号，二者总带宽相同，物理层实现路径不同。这个差异直接决定选型，必须讲清。

- **BCM78910**：集成 128 个 Peregrine 106.25G PAM4 SerDes 核心，等效提供 1024 条 100G 物理通道。Peregrine 是成熟技术，广泛应用于 400G/800G 生态，信号频率较低，PCB 走线与信号补偿要求相对温和，支持 3 至 4 米无源铜缆（DAC）传输。适合追求极高端口密度、希望沿用现有 100G 光电生态的超大规模云厂商，用于 Spine 与汇聚层。
- **BCM78914**：集成 64 个 Condor 212.5G PAM4 SerDes 核心，共 512 条物理通道，单通道带宽翻倍，因而能原生支持 1.6TbE 端口（由 8 条 200G 通道组成）。代价是铜缆可靠传输距离降到约 1 米，通常需配合有源电缆（AEC）、线性可插拔光模块（LPO）或 CPO 使用。适合超节点、scale-up 这类强调带宽密度、减少加速器节点间布线的场景。

下表把两者并列对照。

|---|---|---|
| SerDes 核心 | 128 × Peregrine | 64 × Condor |
| 单通道速率 | 106.25G PAM4 | 212.5G PAM4 |
| 物理通道数 | 1024 × 100G | 512 × 200G |
| 原生端口优势 | 512×200G / 128×800G | 64×1.6TbE |
| 无源铜缆距离 | 约 3 至 4 米 | 约 1 米 |

| 定位 | 超高密度 Spine 与汇聚 | 高带宽密度 scale-up |

### 3. 一个必须澄清的容量口径

交换 ASIC 厂商通常按端口名义速率之和定义芯片容量：64×800GbE 等于 51.2Tbps，而不是把收发双向重复计算成 102.4Tbps。因此不同资料中同一代芯片的容量若出现一倍差异，多数是口径不同而非事实错误。理解这一点，才能正确解读"Tomahawk 5 是 51.2T、Tomahawk 6 是 102.4T"这句话——它指的是端口名义速率之和翻倍，不是双向计数方式变了。

### 4. 端口配置示意与判读

下面用示意性的配置片段展示高 Radix 如何映射到整机端口。这不是任何真实 SDK 的命令，仅用于说明容量口径，字段名与语法需对照实际平台核验。

```text
# 示意配置：BCM78910 的两种典型整机端口映射（非真实 SDK 命令）
profile spine_200g:
  serdes_lanes = 1024 x 100G PAM4     # Peregrine
  ports = 512 x 200GbE                # 容量 512*200G = 102.4T
profile spine_800g:
  serdes_lanes = 1024 x 100G PAM4
  ports = 128 x 800GbE                # 容量 128*800G = 102.4T
```

对这段配置的判读：两个 profile 的 SerDes 通道数相同，都是 1024 条 100G 通道，差别只在端口聚合方式。第一个把 4 条 100G 通道聚合成一个 200GbE 端口，得到 512 个端口——这是最高 Radix 配置，适合扁平化 scale-out 拓扑；第二个把 8 条通道聚合成一个 800GbE 端口，得到 128 个端口，适合 800G 主干链路。两者的名义容量都是 102.4Tbps，印证了上一节的容量口径。选型时不要只看容量数字，而要看目标拓扑需要多少端口、每端口速率多少，再反推需要哪种聚合方式与 SerDes 子型号。

## TH6-04 数据包处理流水线

### 1. 公开信息的边界说明

必须先说明一个事实：博通没有公开 Tomahawk 6 逐阶段的微架构流水线细节（例如具体的解析阶段数量、表项查找级数和内部模块名称）。网络上流传的"流水线框图"多为第三方推测或基于 StrataXGS 早期产品的示意。因此本章采用两类信息：一是官方明确披露的能力点，二是基于 StrataXGS 架构通用模式的流程性描述，后者会明确标注为"工程理解"而非厂商规格。凡涉及具体寄存器、表项容量、阶段数量的数字，本文档一律不编造，需以博通官方数据手册与客户 NDA 资料为准。

### 2. 数据面的功能链路

从工程理解的角度，一个包在芯片内经过的功能链路可以概括为：端口接收与物理层解码 → 二层/三层解析与查表 → 缓冲与排队 → 拥塞判断与调度 → 出口重写与发送。Tomahawk 6 在这条通用链路上的强化点集中在三处：

1. **入口侧**：线速完成 L2/L3 转发决策与单次 VXLAN 封装/解封装，避免多次通过带来的时延与吞吐损失。
2. **缓冲侧**：102.4T 包缓冲架构保证在拥塞时仍能吸收微突发，不因缓冲吞吐不足而丢包。
3. **出口侧**：动态负载均衡与自适应路由决定实际出端口，硬件链路故障切换在故障发生时立即改道。

### 3. 报文处理动作示意

下面用伪代码描述一次转发决策涉及的动作序列，用于帮助理解各能力的先后关系。这不是可执行配置，也不对应任何真实 SDK 接口，字段名需对照实际 SDK 核验。

```text
# 工程理解伪代码：一个包在 Tomahawk 6 内的决策序列（非真实 SDK 接口）
pkt = ingress(port)
hdr = parse_l2_l3(pkt)              # 解析二层与三层头
if hdr.is_tunnel:
    hdr = single_pass_vxlan(hdr)    # 单次通过完成隧道路由与桥接
route = lookup_forward(hdr)         # 线速查表得到转发决策
enqueue(route.buffer_pool, pkt)     # 进入 102.4T 包缓冲
cong = measure_congestion(route)    # 遥测实时测量拥塞
if cong.hotspot_detected:
    route = adaptive_reroute(cong)  # 避开热点路径
if route.link_down:
    route = hw_failover(route)      # 硬件链路切换，不等控制面
egress(route.port, rewrite(pkt))
```

对这段伪代码的判读：真正体现 Tomahawk 6 差异化的不是解析或查表本身——这些是交换芯片的通用能力——而是 `measure_congestion`、`adaptive_reroute` 与 `hw_failover` 三步。它们对应 Cognitive Routing 2.0 的核心机制，全部在硬件中实时完成。对 AI 训练而言，一次链路故障若等待控制面收敛，可能造成毫秒级中断，足以让整个训练任务停顿；硬件切换把这个时间压缩到远低于控制面收敛的量级。需要强调，这段伪代码是理解辅助，不代表真实的处理阶段数量或 SDK 调用顺序。

## TH6-05 拥塞管理与 AI 网络特性

### 1. 为什么 AI 流量需要专门设计

AI 训练的通信模式与传统业务截然不同。all-reduce、all-gather 等集合操作会在同一时刻让数千个加速器向彼此发送大量数据，形成同步的、低熵的象流。低熵意味着流的数量少、模式相似，标准哈希难以分散；同步意味着多个流同时到达，形成微突发。RDMA（这里主要是 RoCEv2）对丢包和乱序极度敏感——单个丢包就可能让传输层重传，使训练任务停顿毫秒级。

Tomahawk 6 的应对是三管齐下：大吞吐包缓冲吸收微突发、动态负载均衡分散象流、端到端拥塞控制抑制源头发送。三者配合的目标是把尾时延压到最低，避免"个别包的延迟拖慢整个集群"。

### 2. CPO 选项：Tomahawk 6-Davisson

2025 年 10 月，博通发布了 Tomahawk 6-Davisson，是第三代采用共封装光学（CPO）技术的以太网交换芯片，也是业界首款达到 102.4Tbps 的 CPO 交换芯片。CPO 的做法是把光引擎与交换 ASIC 封装在一起，缩短信号在 PCB 上的电传输距离，从而降低 SerDes 与光模块功耗、提升高速链路稳定性。公开资料称其基于台积电 COUPE 技术的光学引擎异构集成，光互连功耗相比传统可插拔方案降低约 70%。

需要客观看待 CPO 的定位：它主要解决高端 Spine 与 scale-up 场景的功耗与密度问题，但仍面临良率、维修、激光器寿命与现场可替换性的挑战，因此短期内不会取代可插拔光模块，两者将长期共存。

下表把 Tomahawk 6 系列与同代主要竞品做定性对比，供选型时定位。

## TH6-06 软件生态与小结

### 1. StrataXGS 软件兼容的价值

博通官方强调，StrataXGS 产品组合保持软件兼容性。对客户而言，这意味着从上一代 Tomahawk 5 迁移到 Tomahawk 6 时，控制面软件、NOS 集成与运维工具链可以复用大部分，显著降低迁移成本。这一生态壁垒常被低估——交换芯片的竞争不只在硅片参数，更在 SDK、SAI、NOS 适配、光模块互操作和长期满载验证。一款芯片即便纸面参数领先，若软件生态不成熟，也难以转化为实际设计。

### 2. 交叉引用与小结

1. **定位**：Tomahawk 6 是 102.4T 单芯片旗舰，3nm 工艺，2026 年 3 月量产，面向 AI scale-up/scale-out 与通用数据中心。
2. **参数**：512 或 1024 条 PAM4 SerDes 通道，最高 512×200GbE 端口，容量按端口名义速率之和计算。
3. **型号差异**：BCM78910 用 Peregrine 106.25G SerDes 追求密度与生态兼容，BCM78914 用 Condor 212.5G SerDes 追求 1.6T 原生端口与带宽密度。
4. **流水线**：逐阶段微架构未公开，本文档按工程理解描述端口到端口的功能链路，强调入口单次 VXLAN、缓冲吞吐与出口硬件切换三处强化点。
5. **差异化**：Cognitive Routing 2.0 与 102.4T 包缓冲针对 AI 低熵象流与微突发设计，CPO 版本解决高端功耗与密度问题。
6. **边界**：所有性能数字为厂商标称，未做第三方归一化；具体寄存器、表项容量、阶段数量需以官方数据手册为准。
