## 2. 深度要求

- 每篇 **3000+ 中文字**（严格口径：排除代码块、表格行、图块 DSL 后的中文字符）。**每篇都要实打实写完**，最后一篇和第一篇一样厚实。
- 严禁出现「（略）」「待补充」「同上」「参见前文不再赘述」等占位；严禁代码块里出现裸 `...` 省略行。
- 每篇必须含：真实源码路径（如 `conf/parser.go`、`tunnel/service.go`、`driver/configuration_windows.go`）、关键函数/调用链、配置或命令实例、至少一个表格、至少一节「陷阱与最佳实践」或「常见误用与调试」。
- 每篇至少 **2 个代码块**，其中至少一组是「配置/命令/代码 + 典型输出 + 150 字以上中文判读说明」（逐行解释关键字段、正常值范围、异常特征）。
- **版本基准**：wireguard-windows master（仓库快照 2026-11 抓取，`version/version.go` 为版本来源）、WireGuardNT 1.1、Go 1.27.1（见 `Makefile` / `build.bat`）、WireGuard 协议（Noise_IKpsk2 / ChaCha20-Poly1305 / BLAKE2s / HKDF / Curve25519）、Windows 10 及以上（含 Windows Server 2019）与 amd64/x86/arm64 三种 MSI。凡不确定的字段名、函数签名、命令行参数、版本号，**不要编造**，写「需对照实际版本核验」并给出可定位的源码路径。
- **能力边界必须写清**：本仓库是 **Windows 官方客户端**，不是 Linux 内核实现、不是 wireguard-go 用户态数据面、不是服务端发行版；内核数据面由外部项目 WireGuardNT 提供，本仓库只负责 IOCTL 配置下发、适配器与网络配置。不要把 Linux `wg-quick` 的 `iptables` / `%i` / `SaveConfig` / `resolvconf` 语义写成 Windows 客户端能力；`DangerousScriptExecution` 未开启时 `PreUp`/`PostUp`/`PreDown`/`PostDown` 不执行，且 Windows 用环境变量 `WIREGUARD_TUNNEL_NAME` 而非 `%i`。

## 5. 配图语法（会被编译成 Word 可编辑形状 + .drawio 源文件）

每个图块用下面这种 DSL，**不要用 mermaid、不要插入图片、不要画 ASCII 图**：

```
:::figure id=06-06-01 | name=AllowedIPs 到 Windows 路由表的下发链路 | dir=TD
node n1 "conf.Config" blue
node n2 "Peer.AllowedIPs" teal
node n3 "winipcfg 路由写入" amber
node n4 "WireGuardNT 适配器" purple
edge n1 -> n2 "解析"
edge n2 -> n3 "去重合并"
edge n3 -> n4 "绑定 LUID"
edge n4 -> n1 dashed "状态回查"
:::
```

规则：
- `node <id> "<文字>" <色调>`，色调只能是 blue / teal / amber / purple / gray / red / green。
- `edge <from> -> <to> "<标签>"`；`dashed` 表示辅助/回查关系，写在标签**之前**；标签可省略。
- 节点文字用**双引号**包裹，内部不要出现双引号；可用 `<br/>` 换行。
- **单行显示宽度 ≤ 38**（中文按 2、英文按 1 计），超长必须用 `<br/>` 折成多行；不要把整句话塞进一个节点。
- 每张图节点数 **≤ 10**、边数 **≤ 12**；信息多就拆成两张图，不要堆一张。
- 节点 id 只用字母数字下划线，且块内唯一；**每个节点都必须至少连一条边**（禁止孤立节点）。
- **禁止** subgraph / classDef / style / 链接语法。
- 首行 `:::figure ...` 与末行 `:::` 必须各占一行。
- `id` 全局唯一，格式固定 `<篇章号>-<两位序号>`，如 `07-05-01`。
- 正文引用图时写「图 07-05-01 …」，**必须与图 id 完全一致**（图题、正文引用、`.drawio` 文件名三者同源）。
- 每篇至少 1 张图；每册图数不少于篇数，关键篇可 2 张。
- 图块之前要有引导句（「如下图所示」「…的处理链路见图 06-06-01」）。

| 类别 | 已核验事实 |
|---|---|
| 组件 | 一个内核驱动 WireGuardNT + 三个用户态部分：Tunnel Service、Manager Service、UI（`docs/attacksurface.md`） |
| 进程入口 | `main.go`：`/installmanagerservice`、`/uninstallmanagerservice`、`/managerservice`、`/installtunnelservice CONFIG_PATH`、`/uninstalltunnelservice TUNNEL_NAME`、`/tunnelservice CONFIG_PATH`、`/ui 4 个句柄`、`/dumplog [/tail]`、`/update`、`/removedriver`；无参数时尝试唤起 UI 或提权安装 manager 服务 |
| 服务名 | `WireGuardManager`；每条隧道 `WireGuardTunnel$<name>`（`docs/enterprise.md`、`manager/install.go`） |
| 配置存储 | `%ProgramFiles%\WireGuard\Data\Configurations\`；manager 监视新增 `.conf`，用 `CryptProtectData(bytes, "myconfname")` 加密为 `.conf.dpapi` 后删除明文；目录与文件 ACL 见 `docs/attacksurface.md` |
| 日志 | 共享环形日志，`wireguard /dumplog`、`wireguard /dumplog /tail`；源码 `ringlogger/`、`conf/path_windows.go` |
| 注册表 | `HKLM\Software\WireGuard\LimitedOperatorUI`（DWORD 1，Network Configuration Operators S-1-5-32-556 受限 UI）、`HKLM\Software\WireGuard\DangerousScriptExecution`（DWORD 1，以 LocalSystem 执行四个脚本键，用环境变量 `WIREGUARD_TUNNEL_NAME`）；卸载清理整个 `HKLM\Software\WireGuard`（`docs/adminregistry.md`） |
| 配置字段 | `[Interface]`：`PrivateKey`、`Address`、`ListenPort`、`MTU`、`DNS`（含搜索域）、`Table=off`、`PreUp`/`PostUp`/`PreDown`/`PostDown`；`[Peer]`：`PublicKey`、`PresharedKey`、`AllowedIPs`、`Endpoint`、`PersistentKeepalive`。以 `conf/config.go` 的 `Interface`/`Peer` 成员为准；`conf.Config` 另含 `Name`、`TrailingComments` |
| 运行时查询 | `wg show <name>` 可查接口、公钥、监听端口、peer、endpoint、allowed ips、latest handshake、transfer（`docs/enterprise.md` 给出真实输出样例） |

| kill-switch | 仅当「单 peer + 该 peer 含 /0 的 AllowedIP」时启用 WFP 规则：放行隧道服务自身 UDP、DNS 仅放行配置指定的 53 端口服务器、放行 loopback 与隧道内流量、放行 DHCPv4/v6 与 NDP，其余阻断；可用 `0.0.0.0/1 + 128.0.0.0/1`、`::/1 + 8000::/1` 规避；UI 编辑器有对应复选框（`docs/netquirk.md`） |
| 适配器 | 启动隧道时动态创建、停止时销毁；网络 GUID 由配置确定性派生（`tunnel/deterministicguid.go`、`docs/netquirk.md`） |
| 构建 | Windows：`build.bat`（64 位 Windows 10 / Server 2019 + Git for Windows），产物 `amd64\wireguard.exe` / `x86\wireguard.exe` / `arm64\wireguard.exe`；签名需根目录 `sign.bat`（`SigningProvider`、`TimestampServer`）；本地化 `set GoGenerate=yes`；Linux 交叉构建需 `mingw-w64` + `imagemagick`，`make` / `make deploy`（`DEPLOYMENT_HOST`、`DEPLOYMENT_PATH`）；`docs/buildrun.md`、`Makefile` |

| 更新链 | 服务端 `b2sum -l 256 *.msi > list` + `signify -S -e -s release.sec -m list` 产出 `list.sec`；客户端 TLS 下载并验 Ed25519 签名，找同架构更高版本 `wireguard-${arch}-${version}.msi`，下载到 `C:\Windows\Temp` 随机名，验 BLAKE2b-256，最后 `msiexec.exe /qb!- /i`（`docs/attacksurface.md`、`updater/`） |
| 企业部署 | MSI 可直接 GPO 分发，属性 `DO_NOT_LAUNCH` 抑制安装后启动；`wireguard /update` 可由计划任务每日触发；无适配器时 `wireguard /removedriver`（`docs/enterprise.md`） |
| 安装器 | `installer/` 下 WiX `wireguard.wxs`、`customactions.c`、fetcher；`quickinstall.bat` 可自制安装包 |
