# wireguard-windows 技术资料 · 总目录与阅读指南（交付版）

> **项目**：开源软件 wireguard-windows（WireGuard 官方 Windows 客户端）技术资料全集
> **版本基准**：上游仓库 master 快照（2026-11 抓取）、WireGuardNT 1.1、Go 1.27.1、Windows 10 / Server 2019 及以上、amd64 / x86 / arm64 三种 MSI；不确定的结构体字段、函数签名、开关、版本号一律标注「需对照实际版本核验」并给出 `upstream_src/` 下可定位的源码路径
> **深度标准**：深度技术型，每篇 3000+ 中文字（不含代码与表格），含真实源码路径、关键数据结构、调用链、完整配置示例与输出判读
> **图示标准**：全部配图为 **Word 原生可编辑形状组**（DrawingML）；每张图另附同名 `.drawio` 源文件，可用 draw.io 打开继续编辑；DOCX 内零位图
> **交付形式**：**9 个 DOCX**（00 总纲 + 8 个维度册），共 **62 篇**；交付目录不含 `.md` 文件
> **编号规则**：`文件号-篇号`（如 `06-06`）；图号用 `文件号-篇号-图序号`（如 `06-06-01`），与正文引用、图题、`.drawio` 文件名四者一致
> **当前状态**：已完稿交付 · 62 篇齐全 · 配图 / 表格 / 示例均按第 7 节约定编译
> **最后更新**：2026-11-11

## 1. 结构设计与评审结论

本套资料沿用 VPP / DPDK / OpenVPN 三套资料集已经验证过的组织逻辑：**按维度分册 → 唯一权威源去重 → 三类骨架 → `文件号-篇号` 编号 → 工具书前置于原理 → 运维收尾**。针对 wireguard-windows 自身特点做了四处调整，评审结论如下表所示。

| 决策 | 理由 | 落地方式 |
|---|---|---|
| 04 册定为「配置与命令行」并同时收录三类命令 | Windows 客户端的「配置」不是单一文件：它是 `.conf` 配置键 + `wireguard.exe` 的 `/` 开关 + `wg(8)` 运行时查询 + `sc` / PowerShell 服务管理 + 两个管理员注册表策略叠加 | 04 成为配置与命令唯一权威源，按功能族穷举并给全参数表 |
| 02 册把「构建」拆成 Windows 原生与 Linux 交叉两条链 | 上游同时提供 `build.bat` 与 `Makefile`，且依赖 Go 工具链自举、WireGuardNT DLL 资源嵌入、WiX 安装包与驱动签名，链路比一般 Go 项目长 | 02-02 用 C 实战型给 Windows 分步构建，02-03 讲 Makefile 目标与交叉编译，02-05 讲 MSI 与签名 |
| 05 册前置于 06 | 与前三套一致：`conf.Config` / `conf.Interface` / `conf.Peer` / `driver` IOCTL 结构是理解解析、适配器创建与路由下发的前置知识 | 05 定位「工具书·随查」，不参与线性阅读主线 |
| 06 册把「协议原理」与「Windows 集成原理」分开 | 内核数据面由外部项目 WireGuardNT 实现，本仓库只有 IOCTL 配置下发；若混写会让读者误以为本仓库包含 Noise 握手代码 | 06-04 单讲协议层并注明边界，06-05 起全部讲本仓库的用户态机制与 Windows API 集成 |

「先搭起来 → 再懂协议与源码 → 再按模块用起来 → 最后运维」这条主线同样成立。评审中明确排除的做法见下表。

| 级别 | 曾经的风险 | 本套的处理 |
|---|---|---|
| 结构 | 按功能平铺 62 篇、无权威源，导致配置 / 字段 / 机制在多个文件重复 | 04 / 05 / 06 / 07 各定唯一权威源，其余册交叉引用 |
| 骨架 | 手册型章节套论述型骨架，出现空泛「背景与动机」 | 分 A 论述 / B 手册字典 / C 实战三类骨架 |
| 编号 | 全局连续号在插删后全盘失效 | 改 `文件号-篇号`，插删只影响本册 |
| 边界 | 把 Linux `wg-quick` 的 `iptables`、`%i`、`resolvconf` 或 wireguard-go 的用户态数据面写成 Windows 客户端能力 | 全册标注能力边界，04 与 06 明确「需对照实际版本核验」的写法 |
| 工具书 | 字段详解混在线性阅读链路里，打断主线 | 05 独立成册并标注「随查」，可跳过 |
| 安全 | 把 `DangerousScriptExecution` 当成默认开启，或把 LocalSystem 执行脚本写成普通功能 | 03、04、08 三处强调默认不执行、开启条件与攻击面 |

## 2. 唯一权威源与去重规则

| 内容 | 唯一权威源 | 其余册的写法 |
|---|---|---|
| 全部配置键、`wireguard.exe` 开关、`wg(8)` 子命令、`sc` / PowerShell 运维命令、注册表策略 | **04 全册** | 只给本场景最小必要配置，写「完整配置见 04-xx」 |
| 结构体逐字段定义（`conf.Config`、`conf.Interface`、`conf.Peer`、`Endpoint`、`Key`、`Comments`、`driver` IOCTL 结构、`winipcfg` MIB 结构、`tunnelService`、`interfaceWatcher`、ringlogger / IPC 结构等） | **05 全册** | 只点名 + 给真实源码路径 +「（字段见 05-xx）」 |
| 机制、状态机与调用链（入口分派、配置解析、DPAPI、适配器创建、路由下发、MTU、DNS、WFP、IPC、更新校验） | **06 全册** | 讲「做什么」不讲「怎么实现」，写「原理见 06-xx」 |
| 模块能力与特性、典型用法与组网 | **07 全册** | 写「模块见 07-xx」 |

强制约束：

1. 06 / 07 / 08 全册禁止出现完整结构体字段表，改为 `（字段见 05-xx）`。
2. 07 全册每篇配置段最多 3–5 条本模块最典型的配置键，其余写「完整配置键见 04-xx」。
3. 08 全册禁止重列配置 / 命令清单，只讲「在什么场景组合哪些命令、如何判读输出」。
4. 04 全册禁止讲模块内部原理与结构体字段；05 全册禁止展开机制流程。
5. 交叉引用统一写法：`（字段见 05-xx ｜ 配置见 04-xx ｜ 原理见 06-xx ｜ 模块见 07-xx）`。

## 6. 三类骨架模板

**A 论述型（7 节）**
背景与动机 → 核心概念 → 关键数据结构与源码位置（**引用 05，不重列字段**）→ 关键流程与调用链 → 配置/命令/代码实例（**引用 04，不重列配置**）→ 注意事项、陷阱与最佳实践 → 小结与延伸阅读。

**B 手册字典型（7 节）**
本篇定位与覆盖范围 → 索引与全参数表 → 逐项详解 → 典型示例 → 速查表 → 版本差异 → 常见误用与调试。
05 字段表统一列：`字段 | 类型 | 含义 | 源码位置 | 读写时机 | 关联函数与流程 | 版本差异`。

**C 实战型（6 节）**
目标与拓扑 → 前置条件与环境 → 分步操作 → **验证方法与预期结果** → 常见失败与排错 → 小结。
每篇必须给「预期输出 + 判读要点」，不是只给命令。

## 7. 配图、表格与示例约定

### 7.1 配图

- 配图一律是 **Word 原生 DrawingML 形状组**：每个框、箭头、标签都是独立子形状，可在 Word 里单击选中、改字、拖动、换色；DOCX 内 **零位图**。
- 每张图同时产出一份同名 `.drawio` 源文件，可用 draw.io 打开继续编辑或导出 SVG/PNG。
- 图号即图 id（`06-06-01`），**正文引用、图题、`.drawio` 文件名三者同源**。
- 图块之前必须有引导句；节点文字单行显示宽度 ≤38，超长用 `<br/>` 折行；每图节点 ≤10、边 ≤12，无孤立节点。

### 7.2 表格

- 表头跨页自动重复、行禁止跨页拆分、列宽按内容长度自适应。
- 单元格 ≤90 字符；长命令串移到表后代码块，单元格写「见下方配置示例」。
- 单元格内的 shell 管道或语法「或」（`|`）必须转义为 `\|`，否则整表错列。
- 表格之前必须有引导句。

### 7.3 示例

- 每个代码块带语言标注（`conf` / `bash` / `text` / `go` / `ini` / `powershell` / `json` / `tree`），DOCX 里渲染成可见的示例类型标签。
- 典型输出统一放 `text` 块，并注明「示例输出，具体格式需对照实际版本核验」。
- 每篇至少一组「配置/命令 + 典型输出 + 150 字以上中文判读说明」，讲清关键字段含义、正常值范围与异常特征。
- 禁止裸 `...` 省略行与任何占位词。

## 9. 版本基准与事实核验约定

本套资料以本地 `upstream_src/` 中的上游仓库 master 快照为第一手依据，以 `docs/` 下五份官方文档为第二手依据。凡出现下列情形，正文一律写「需对照实际版本核验」并给出可定位的源码路径，不得凭印象补全：

- `conf/config.go` 中不存在、但其他平台 `wg-quick` 存在的配置键；
- `main.go` 的 `usage()` 未列出的命令行开关；
- 上游仓库内没有源码、属于 WireGuardNT 外部项目的内核实现细节；
- 具体版本号、驱动版本、Go 版本、MSI 文件名与下载 URL 的时效性数值。

这类标注不是内容缺口，而是把「版本相关事实」与「机制性结论」分离的编辑约定：机制、调用链、边界条件在本套资料中给全，具体数值请读者对照手上的上游版本复核。
