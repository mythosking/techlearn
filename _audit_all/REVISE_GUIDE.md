# VPP 资料集逐册修订指南

本文件是 01~08 各册修订任务的统一作业规范。执行前先读 `_vpp_build/drafts/SPEC.txt` 与 `drafts/00.txt`。

## 0. 工作范围

- 只修改 `_vpp_build/drafts/<册号>.txt`，不改其它册、不改脚本、不编译 DOCX（编译由主控统一执行）。
- 文件保持 UTF-8 无 BOM、LF 换行、首行 `# VPP 技术资料 · 0X 册名` 不变。

```bash

```

输出包含四段：每篇全文字数（<3200 标 `<< 需扩写`）、图块缺引导句/缺图号引用、表格缺引导句、超限图（节点>10 或 边>12）。

## 2. 四类修订

### 2.1 图块引导句与图号引用
- 每张 `:::figure id=NN-NN-NN` 之前必须**紧邻一个叙述段落**（不能是 `###` 标题、表格行、`:::` 结束符）。
- 该段必须出现「图 NN-NN-NN」，与紧随其后的图 id 完全一致。
- 有引导段但无图号：在段末句号前插入「（图 NN-NN-NN）」。
- 无引导段：补 1–2 句真正描述该图的话——说清图里画了哪几层、读者应按什么顺序看、与上下文的衔接点。禁止「如下图所示」「下图展示了相关流程」这类零信息句。

### 2.2 表格引导句
- 表头行之前最后一行必须是叙述句，不能是标题、上一张表的数据行、`:::`、空行后的标题。
- 缺失时补一句有信息量的话：点明这张表列了什么维度、各列怎么读、什么场景下查它。禁止连用「下表所示」「如下表」。

### 2.3 薄篇扩写（全文汉字 < 3200）
新增内容必须是实质技术内容，优先级：
1. 一组「典型配置 + 示例输出（```text 块，注明「示例输出，具体格式需对照实际版本核验」）+ 150 字以上逐行判读」；
2. 一段失败模式与边界条件（什么情况下不生效、误配会怎样、如何验证）；
3. 一段与相邻版本/相邻模块的差异与选型判据。

禁止：重复前文、排比注水、罗列同义句、把已有段落改写一遍充数。

### 2.4 超限图
节点 >10 或边 >12 的图，合并或删减次要节点/连线：
- 保持语义完整，主干路径不得缺失；
- 每个节点至少连一条边；
- 节点单行文字宽度 ≤38（中文按 2、英文按 1，超长用 `<br/>` 折行）；
- 图 id、name、dir 不变。

## 3. 硬约束

- 篇号、篇标题、篇数、图 id、图数量不得变；已有表格、代码块、示例不得删除（扩写只增不减）。
- 表格单元格 ≤90 字符，单元格内 `|` 写成 `\|`；代码块必须有语言标注，结束行是裸 ` ``` `。
- 技术事实以 VPP 23.06 / master 为准；不确定处写「需对照实际版本核验」并给出 `src/vlib/`、`src/vnet/`、`src/plugins/` 下的可定位路径，禁止编造函数名、参数名、默认值。
- 去重：不重列结构体字段全集（引用 05-xx）、不重列命令全集（引用 04-xx）、不重复展开调用链（引用 06-xx）。
- 不在正文写任何面向任务/流程的元话语（如「按要求补充」「本 Agent」「待补」）。
