# Squid 技术资料 · 05 关键数据结构与日志字段详解

## 05-01 数据结构总览与阅读方法

### 1. 本篇定位与覆盖范围

本篇是全册的工具书入口，讲清 Squid 核心对象的命名规律、内存管理与定位方法。后续各篇给出逐字段含义，本篇不展开任何机制流程（原理见 `06`）。

### 2. 核心对象总览

| 对象 | 职责 | 所在篇 |
|---|---|---|
| request_t / HttpRequest | 请求表示（方法、URL、头部） | 05-02 |
| ConnStateData | 客户端连接状态 | 05-02 |
| HttpHeader | 头部解析与存储 | 05-02 |
| StoreEntry | 缓存条目元数据 | 05-03 |
| MemObject | 缓存条目内存表示 | 05-03 |
| peer | 邻居缓存定义 | 05-04 |
| FwdState | 转发状态机 | 05-04 |
| Comm::Connection | 连接与描述符封装 | 05-04 |
| access.log 字段 | 日志记录格式 | 05-05 |

### 3. 阅读方法

- **命名规律**：Squid 大量使用首字母大写的驼峰式类名与下划线函数名，request_t 这类后缀表示类型别名。
- **头文件优先**：类定义通常在 .h，实现在 .cc；先读头文件字段，再看实现方法。
- **内存池**：Squid 用内存池（MemPool / memAlloc）管理大量小对象，字段之外关注分配与释放路径。
- **定位法**：在 src/ 下搜索类名或字段名，配合 grep 找引用点。

:::figure id=05-01-01 | name=核心对象关系总览 | dir=TD

图中节点速览：请求驱动 StoreEntry 查找与 FwdState 转发，邻居由 FwdState 选择。

### 4. 典型示例

```bash
cd squid-src
grep -rn "class StoreEntry" src/
grep -rn "struct request_t" src/
grep -rn "class ConnStateData" src/
```

### 5. 注意事项

字段名与类结构在版本间变化较大，本册给出的是稳定的概念骨架，精确字段列表需对照实际版本的头文件核验。

### 6. 小结

先建立对象地图，再逐篇深入。下一步 05-02 看请求与事务结构。

## 05-02 请求与事务结构

### 1. 本篇定位

覆盖请求表示、连接状态与头部结构。请求如何被解析与转发的机制见 `06-04`，本篇只讲字段含义。

### 2. request_t / HttpRequest 字段表

| 字段组 | 代表字段 | 含义 | 关联 |
|---|---|---|---|
| 请求行 | method | HTTP 方法（GET/POST/CONNECT） | 协议解析 |
| 请求行 | uri / url | 请求目标 URL | 缓存键生成 |
| 版本 | http_ver | HTTP 版本 | 响应构造 |
| 头部 | header | HttpHeader 对象 | 04-03 ACL 匹配 |
| 客户端 | client_addr | 客户端地址 | acl src 匹配 |
| 标志 | flags | 各类布尔标志位 | 转发决策 |

### 3. ConnStateData 字段表

| 字段组 | 含义 | 关联 |
|---|---|---|
| 连接描述符 | 与客户端的 socket 连接 | Comm 层 |
| 请求解析状态 | 当前正在读取的请求 | 协议解析 |
| 缓冲区 | 未解析的字节流 | 异步 I/O |
| 认证状态 | 用户身份信息 | 04-03 认证 |

### 4. HttpHeader 字段表

| 字段 | 含义 |
|---|---|
| 条目数组 | 头部字段的键值对集合 |
| 缓存标志 | 是否已解析、是否损坏 |
| 查找接口 | 按名称取值的方法 |

### 5. 典型示例

在源码中定位请求结构：

```bash
grep -rn "class HttpRequest" src/*.h
grep -rn "HttpRequest::" src/HttpRequest.cc | head -20
```

### 6. 版本差异与常见误用

- 老版本用 `request_t` 结构，新版本多用 `HttpRequest` 类，二者在不同版本并存或演进，需核验。
- 头部字段的访问应通过接口方法，不要假设内部数组布局。

### 7. 小结

请求对象是所有处理的输入。下一步 05-03 看缓存条目如何表示。

## 05-03 存储条目与缓存索引结构

### 1. 本篇定位

覆盖 StoreEntry 与 MemObject 等缓存核心对象。存储机制与置换算法见 `06-03`，本篇只讲字段。

### 2. StoreEntry 字段表

| 字段组 | 代表字段 | 含义 | 关联 |
|---|---|---|---|
| 键 | key | 缓存条目的唯一键 | 缓存查找 |
| 状态 | store_status | 条目状态（如 STORE_OK、STORE_PENDING） | 命中判定 |
| 标志 | flags | 可缓存、删除中等标志 | 06-02 |
| 元信息 | MemObject 指针 | 关联的内存对象 | 本篇 |
| 时间戳 | timestamp、expires | 新鲜度计算 | refresh_pattern |
| 引用计数 | lock_count | 生命周期管理 | 淘汰保护 |

### 3. MemObject 字段表

| 字段组 | 含义 |
|---|---|
| 响应头部 | 缓存的 HTTP 响应头 |
| 主体数据 | 内存中的对象内容 |
| 存储链 | 与 StoreEntry 的关联 |
| 大小信息 | 对象长度等 |

### 4. 条目状态说明

| 状态 | 含义 |
|---|---|
| STORE_PENDING | 正在写入，尚未完成 |
| STORE_OK | 完整可用 |
| STORE_ABORTED | 写入中止 |

### 5. 典型示例

```bash
grep -rn "class StoreEntry" src/store/
grep -rn "STORE_OK\|STORE_PENDING" src/ | head -20
```

### 6. 版本差异与常见误用

- 存储子系统在 3.x 到 7.x 之间重构较多，字段命名与关系变化大，以头文件为准。
- 引用计数操作不当会导致条目过早淘汰或内存泄漏，开发中需成对加锁解锁。

### 7. 小结

StoreEntry 是缓存的核心抽象。下一步 05-04 看邻居与转发结构。

## 05-04 对等体与转发结构

### 1. 本篇定位

覆盖 peer、FwdState、Comm::Connection 等转发相关对象。转发路径选择机制见 `06-04`，缓存层级协议见 `06-05`，本篇只讲字段。

### 2. peer 字段表

| 字段组 | 代表字段 | 含义 | 关联 |
|---|---|---|---|
| 身份 | host、name | 邻居地址与名称 | cache_peer 配置 |
| 类型 | type | parent/sibling/originserver | 层级角色 |
| 端口 | http_port、icp_port | 代理与查询端口 | 04-02 |
| 选项 | options | no-query、default 等 | 04-04 相关 |
| 状态 | 存活探测结果 | 邻居可用性 | 06-05 |

### 3. FwdState 字段表

| 字段组 | 含义 |
|---|---|
| 请求指针 | 正在转发的请求 |
| 目标地址 | 选出的目的地址 |
| 重试状态 | 失败重试次数与策略 |
| 邻居选择 | 选中的 peer |

### 4. Comm::Connection 字段表

| 字段组 | 含义 |
|---|---|
| 描述符 | socket 文件描述符 |
| 本地/远端地址 | 连接两端 |
| 事件回调 | 读写完成后的处理 |

### 5. 典型示例

```bash
grep -rn "class peer" src/neighbors/
grep -rn "class FwdState" src/
```

### 6. 版本差异与常见误用

- Comm::Connection 是现代版本的封装，老版本直接用 fd 整数，需核验版本。
- peer 类型与选项决定转发行为，配置与结构体字段要对应理解。

### 7. 小结

转发结构把请求送到正确的目标。下一步 05-05 详解日志字段，这是运维排障的入口。

## 05-05 access.log 日志格式字段详解

### 1. 本篇定位

本篇是日志字段的唯一权威源，逐字段解释原生日志格式。日志配置指令见 `04-06`，日志分析方法见 `08-03`。

### 2. 原生日志格式样例

```text
1700000000.123  456  10.0.0.5 TCP_MISS/200 1234 GET http://example.com/ - DIRECT/93.184.216.34 text/html
```

字段依次为：时间戳、耗时、客户端地址、结果码/状态码、字节数、方法、URL、用户、层级/目的地址、内容类型。

### 3. 字段逐项表

| 序号 | 字段 | 含义 | 排障价值 |
|---|---|---|---|
| 1 | timestamp | 请求完成时间戳（秒.毫秒） | 时序分析 |
| 2 | duration | 处理耗时（毫秒） | 性能定位 |
| 3 | client | 客户端地址 | 定位来源 |
| 4 | result/status | 结果码与 HTTP 状态 | 命中判定 |
| 5 | bytes | 传输字节数 | 流量统计 |
| 6 | method | 请求方法 | 行为分析 |
| 7 | url | 请求 URL | 内容定位 |
| 8 | ident/user | 身份信息 | 认证审计 |
| 9 | hierarchy/destination | 层级与目的地址 | 回源路径 |
| 10 | mime | 内容类型 | 缓存策略验证 |

### 4. 结果码速查

| 结果码 | 含义 |
|---|---|
| TCP_HIT | 命中有效缓存 |
| TCP_MISS | 未命中，回源 |
| TCP_REFRESH_HIT | 校验后仍有效 |
| TCP_REFRESH_MISS | 校验后有更新 |
| TCP_MISS_ABORTED | 传输中止 |
| TCP_CLIENT_REFRESH_MISS | 客户端强制刷新 |
| TCP_DENIED | 被访问控制拒绝 |
| NONE/400 等 | 请求本身错误 |

### 5. 层级码速查

| 层级码 | 含义 |
|---|---|
| DIRECT | 直连源站 |
| FIRSTUP_PARENT | 转发到父级 |
| SIBLING_HIT | 同级命中 |
| NONE | 无（错误或被拒） |

### 6. 典型示例

```bash
# 统计结果码分布
awk '{print $4}' /var/log/squid/access.log | sort | uniq -c | sort -rn
# 找出耗时最长的请求
awk '{print $2, $7}' /var/log/squid/access.log | sort -rn | head -20
```

### 7. 版本差异与常见误用

- 6.x 起放宽了单行长度限制，含超长 URL 的日志记录方式变化，旧解析脚本需适配。
- 自定义 logformat 后字段位置变化，脚本不能写死列号。
- 默认日志含完整 URL 与用户名，涉及隐私合规，需评估留存策略。

### 8. 小结

日志字段是排障的数据基础。字段看不懂时回到本篇查表，分析方法见 `08-03`。
