# Squid 技术资料 · 08 运维、性能基准与排障

## 08-01 性能基准与测试方法学

### 1. 背景与动机

「Squid 能扛多少并发」「命中率多少算正常」这类问题必须有可复现的测量方法，否则调参全凭感觉。本篇讲压测拓扑、核心指标与基线记录方法。

### 2. 核心指标

| 指标 | 含义 | 获取方式 |
|---|---|---|
| 命中率 | 命中请求占比 | manager info / 日志结果码 |
| 吞吐 | 单位时间传输字节 | 压测工具统计 |
| 并发连接 | 同时活跃连接数 | manager / 系统观测 |
| 响应时延 | 请求到响应耗时 | 日志 duration 字段 |
| CPU / 内存 | 资源占用 | 系统工具 |
| 文件描述符 | 已用/上限 | manager info |

### 3. 测试拓扑

压测要区分两种场景：**命中场景**（重复请求同一批可缓存对象，测缓存服务能力与命中率）与**回源场景**（请求各不相同的对象，测转发与源站能力）。两者结论不同，不能混为一谈。

### 4. 方法与基线

- 固定变量：每次只改一个参数，其余保持一致。
- 预热：先跑一段时间让缓存填充，再开始计数。
- 记录基线：把配置版本、编译选项、指标结果一并存档，便于回溯。
- 可复现：保留压测脚本与数据集。

### 5. 陷阱与最佳实践

- 用不可缓存对象测「命中率」，结论毫无意义。
- 压测机自身成为瓶颈，误判为 Squid 能力不足。
- 忽略源站能力，回源场景测出的其实是源站上限。

### 6. 小结

性能基准的前提是场景清晰、变量可控、基线可查。下一步 `08-02` 讲具体调优。

## 08-02 性能调优与监控指标

### 1. 背景与动机

调优是「发现瓶颈 → 调整参数 → 验证效果」的循环。本篇讲常见瓶颈与对应参数，判读方法基于 manager 报告与系统指标；命令用法见 `04-05`、`04-06`。

### 2. 瓶颈与对策

| 瓶颈现象 | 可能原因 | 调整方向 |
|---|---|---|
| 命中率低 | 缓存太小、规则不当、对象不可缓存 | cache_dir/cache_mem、refresh_pattern |
| 延迟高 | DNS 慢、磁盘慢、辅助程序慢 | DNS 配置、存储引擎、辅助程序并发 |
| 连接失败多 | fd 耗尽 | 提高 maxfd 与系统上限 |
| CPU 高 | SSL-Bump、日志级别过高 | 减少解密范围、降低调试级别 |
| 内存高 | workers 多、缓存大 | 容量规划、worker 数 |

### 3. 关键监控指标

| 指标 | 来源 | 关注点 |
|---|---|---|
| 命中率 | manager info | 趋势变化 |
| fd 使用率 | manager info | 接近上限要扩容 |
| 内存占用 | 系统工具 | 是否持续增长（泄漏） |
| 磁盘 I/O | 系统工具 | 是否成为瓶颈 |
| 请求时延 | access.log | 长尾请求定位 |

### 4. 命令示例

```bash
squidclient -m info | grep -Ei 'hit|fd|memory|cpu'
squidclient -m stat | head -40
tail -f /var/log/squid/cache.log
```

判读要点：命中率看百分比与绝对请求数的结合（低流量下百分比易失真）；fd 使用率接近上限要提前扩容；cache.log 的告警往往先于故障出现。

### 5. 陷阱与最佳实践

- 一次性改多个参数，无法归因哪个有效。
- 只看瞬时值不看趋势，漏掉缓慢泄漏。
- 生产环境直接试错，应先灰度。

### 6. 小结

调优靠指标驱动与闭环验证。下一步 `08-03` 讲系统化的故障排查流程。

## 08-03 日志分析与故障排查流程

### 1. 背景与动机

排障最忌讳「东改一下西试一下」。本篇给出一条从现象到根因的决策链，把日志、配置、系统状态串起来。字段含义见 `05-05`，命令用法见 `04-05`。

### 2. 排障决策链

| 步骤 | 动作 | 判断 |
|---|---|---|
| 1 服务状态 | 进程是否存在、端口是否监听 | 确认服务在运行 |
| 2 配置校验 | squid -k parse | 排除配置语法 |
| 3 缓存日志 | 查 cache.log 错误告警 | 找直接报错 |
| 4 访问日志 | 查结果码与状态 | 判断命中/拒绝/回源 |
| 5 manager | 查运行时统计 | 看资源与状态 |
| 6 系统层 |  fd、磁盘、网络、DNS | 排除环境瓶颈 |

### 3. 典型分析命令

```bash
# 结果码分布
awk '{print $4}' /var/log/squid/access.log | sort | uniq -c | sort -rn
# 状态码分布
awk '{print $4}' /var/log/squid/access.log | sed 's#.*/##' | sort | uniq -c | sort -rn
# 慢请求
awk '$2>5000 {print $2, $4, $7}' /var/log/squid/access.log | sort -rn | head
```

### 4. 陷阱与最佳实践

- 先看日志再改配置，避免掩盖真实问题。
- 结果码与状态码要分清：一个是 Squid 缓存结果，一个是 HTTP 状态。
- 时间要对齐，跨设备排查注意时钟同步。

### 5. 小结

排障 = 结构化决策链 + 日志数据支撑。下一步 `08-04` 给具体案例。

## 08-04 常见故障案例库

### 1. 案例一：客户端全部无法上网

- **现象**：浏览器配代理后打不开任何网页。
- **定位**：`squid -k parse` 通过，进程在；access.log 无记录或全是 TCP_DENIED。
- **根因**：http_access 规则顺序错误，deny all 在前；或客户端网段不在 localnet。
- **修复**：调整规则顺序，确认 localnet 覆盖客户端地址（写法见 `04-03`）。

### 2. 案例二：命中率长期接近零

- **现象**：access.log 几乎全是 TCP_MISS。
- **定位**：看响应是否带 no-cache/Set-Cookie；查 refresh_pattern 顺序。
- **根因**：目标内容动态且不可缓存，或兜底规则覆盖具体规则。
- **修复**：对静态资源配长新鲜度规则，动态内容不强求缓存（机制见 `06-02`）。

### 3. 案例三：HTTPS 网站大面积证书告警

- **现象**：启用 SSL-Bump 后客户端报证书不受信任。
- **定位**：查客户端信任库与伪造 CA。
- **根因**：客户端未安装并信任 Squid 的 CA。
- **修复**：分发并信任 CA，明确解密范围与合规（见 `07-02`）。

### 4. 案例四：运行一段时间后连接失败

- **现象**：初期正常，数小时后新连接失败。
- **定位**：manager info 看 fd 使用率，接近上限。
- **根因**：文件描述符耗尽，maxfd 或系统 ulimit 过低。
- **修复**：调高编译选项与系统限制，检查连接泄漏。

### 5. 案例五：升级后配置报错

- **现象**：从旧版本升级后 squid -k parse 报错。
- **定位**：报错行指向已废弃或改名的指令。
- **根因**：版本间指令语法变化（如 SSL 参数名）。
- **修复**：按 `squid.conf.documented` 改写，升级前先 parse（见 `08-05`）。

### 6. 小结

案例的价值在于建立「现象 → 定位 → 根因 → 修复」的反射。遇到新问题也按此结构记录，逐步沉淀为团队知识库。

## 08-05 生产运维 checklist

### 1. 背景与动机

生产上线与日常运维需要清单化的检查项，避免遗漏。本篇给出升级、备份、容量与日常巡检的要点。

### 2. 上线前检查

| 类别 | 检查项 |
|---|---|
| 配置 | squid -k parse 通过；规则顺序正确 |
| 编译 | squid -v 确认必要特性已启用 |
| 目录 | cache_dir 权限与空间正确，已 -z 初始化 |
| 安全 | 非 root 运行；cachemgr 设口令；ACL 精确 |
| 日志 | 日志路径可写，轮转与留存配置 |
| 监控 | manager 与系统指标采集就位 |

### 3. 版本升级

| 步骤 | 动作 |
|---|---|
| 1 | 阅读目标版本发布说明与弃用项 |
| 2 | 用 squid -k parse 校验现有配置 |
| 3 | 灰度升级一台，观察命中率与错误 |
| 4 | 确认无误后批量升级 |
| 5 | 保留回滚方案 |

### 4. 备份与恢复

- 备份 squid.conf 与 include 的子配置。
- 备份 TLS 证书与 CA 私钥（妥善保管）。
- 缓存目录通常不需备份（可重建），但 -z 初始化要纳入恢复流程。

### 5. 日常巡检

| 频率 | 项目 |
|---|---|
| 每日 | 进程存活、命中率、错误日志 |
| 每周 | 磁盘空间、日志增长、证书有效期 |
| 每月 | 版本与安全公告、基线对比 |
