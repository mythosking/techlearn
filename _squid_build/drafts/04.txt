# Squid 技术资料 · 04 配置与命令行

## 04-01 squid.conf 配置体系总览

### 1. 本篇定位与覆盖范围

本篇是配置的入口，讲清语法、生效规则与文件组织，是全册的总索引。逐指令详解在 04-02～04-06，命令行工具在 04-05。本篇不展开任何模块内部原理（原理见 `06`，模块见 `07`）。

### 2. 配置语法骨架

squid.conf 由一条条指令组成，每条指令形如「指令名 参数」。注释以 # 开头。指令大体分四类：

| 类别 | 代表指令 | 作用 |
|---|---|---|
| 网络监听 | http_port、https_port | 定义服务端口与模式 |
| 访问控制 | acl、http_access、cache_peer_access | 定义允许与拒绝规则 |
| 缓存存储 | cache_dir、cache_mem、refresh_pattern | 定义缓存位置与新鲜度 |
| 日志管理 | access_log、cache_log、logformat | 定义日志输出 |

### 3. 生效规则

- **顺序敏感**：`http_access` 从上到下匹配，第一条命中的规则决定结果，因此 deny all 通常放最后。
- **指令前置依赖**：被引用的 acl 必须先定义，协议类型要先启用。
- **include 拆分**：大型配置用 include 指令拆成多文件，便于管理。
- **重载与重启**：多数配置改动可 reload 生效，但 workers 等少数改动必须重启（见 `03-06`）。

### 4. 典型示例

配置文件片段 · squid.conf（结构骨架）：

```text
# 全局
visible_hostname proxy.example.com

# 网络
http_port 3128

# ACL 定义
acl localnet src 10.0.0.0/8
acl SSL_ports port 443

# 访问规则（顺序敏感）
http_access allow localnet
http_access deny all

# 缓存
cache_dir ufs /var/spool/squid 10000 16 256
```

### 5. 速查表

| 想做的事 | 去哪篇 | 关键指令 |
|---|---|---|
| 改端口与模式 | 04-02 | http_port、https_port |
| 配置访问权限 | 04-03 | acl、http_access、auth_param |
| 调缓存大小 | 04-04 | cache_dir、cache_mem、maximum_object_size |
| 用命令行工具 | 04-05 | squid、squidclient |
| 配日志 | 04-06 | access_log、logformat |
| 校验配置 | 04-07 | squid -k parse |

### 6. 常见误用

- 把 deny all 写在 allow 之前，导致全部拒绝。
- 引用未定义的 acl 名，启动时报错。
- 把 include 放最后，导致被包含的覆盖规则顺序错乱。

### 7. 小结

配置体系的核心是「顺序敏感 + 前置依赖 + 分类组织」。逐类指令见后续各篇。

## 04-02 网络与监听指令全集

### 1. 本篇定位

覆盖监听端口与基础网络相关指令，作为查表使用。指令的完整语义以 `src/cf.data.pre` 为准，版本差异处标注核验提示。

### 2. 全参数表

| 指令 | 语法要点 | 作用 | 典型值 | 版本提示 |
|---|---|---|---|---|
| http_port | port [mode] [options] | HTTP 监听端口与模式 | 3128 / 80 accel / intercept | 模式参数随版本演进 |
| https_port | port [options] | TLS 监听端口 | 443 tls-cert=... | 需 TLS 支持 |
| visible_hostname | hostname | 对外显示的主机名 | proxy.example.com | 稳定 |
| unique_hostname | hostname | 多实例唯一标识 | 依实例 | 稳定 |
| tcp_outgoing_address | IP | 指定出向源地址 | 出口 IP | 稳定 |
| tcp_outgoing_tos | tos | 出向服务类型标记 | 依策略 | 稳定 |
| dns_nameservers | IP... | 指定 DNS 服务器 | 8.8.8.8 | 内部 DNS 也常用 |
| ftp_port | port | FTP 监听 | 依场景 | 部分版本移除 |
| http_port 的 intercept | 参数 | 透明拦截模式 | 3129 intercept | 需 netfilter 支持 |
| http_port 的 accel | 参数 | 反向加速模式 | 80 accel | 稳定 |

### 3. 逐项详解

**http_port**：最核心的监听指令。默认模式是正向代理，接受完整 URL 请求。加 accel 变为反向加速，加 intercept 变为透明拦截，加 tproxy 配合透明代理协议。可在同一行多次声明不同端口。

**https_port**：用于 TLS 加密的客户端连接。证书与密钥通过参数指定，具体参数名（如 tls-cert、tls-key）在不同版本有差异，需对照 `squid.conf.documented` 核验。

**dns_nameservers**：指定 Squid 内部 DNS 解析器使用的服务器。Squid 自带 DNS 客户端，不依赖系统解析（原理见 `06-04`）。

### 4. 典型示例

```text
# 配置片段 · squid.conf（多端口监听）
http_port 3128
http_port 3129 intercept
https_port 443 tls-cert=/etc/squid/cert.pem tls-key=/etc/squid/key.pem
dns_nameservers 10.0.0.53 8.8.8.8
```

### 5. 速查表

| 场景 | 指令组合 |
|---|---|
| 纯正向代理 | http_port 3128 |
| 反向加速 | http_port 80 accel defaultsite=... |
| 透明拦截 | http_port 3129 intercept |
| 加密客户端 | https_port 443 tls-cert=... |

### 6. 版本差异与常见误用

- 3.x 中 SSL 相关参数名与 7.x 不同（如 cert= 与 tls-cert=），升级需改写。
- 忘记为 intercept 端口编译 netfilter 支持，配置被忽略。
- 多端口监听时把正向与透明混在同一端口，语义冲突。

### 7. 小结

网络指令决定「Squid 如何被访问」。权限交给 04-03，缓存交给 04-04。

## 04-03 访问控制与认证指令全集

### 1. 本篇定位

覆盖 acl、http_access 与认证相关指令。ACL 的完整类型族与匹配逻辑在模块篇 `07-01`，本篇只列指令用法与写法，不展开实现原理。

### 2. ACL 指令速查表

| ACL 类型 | 写法示例 | 匹配对象 |
|---|---|---|
| src | acl localnet src 10.0.0.0/8 | 客户端源地址 |
| dst | acl target dst 1.2.3.4 | 目的地址 |
| dstdomain | acl site dstdomain .example.com | 目的域名 |
| port | acl SSL_ports port 443 | 目的端口 |
| proto | acl XYZ proto HTTP HTTPS | 协议 |
| method | acl safe method GET POST | 请求方法 |
| time | acl work time MTWHF 9:00-18:00 | 时间 |
| url_regex | acl badurl url_regex -i ads | URL 正则 |
| urlpath_regex | acl badpath urlpath_regex -i \\.exe$ | 路径正则 |
| proxy_auth | acl authuser proxy_auth REQUIRED | 认证用户 |
| maxconn | acl connlimit maxconn 10 | 并发连接数 |
| snmp_community | acl snmp snmp_community public | SNMP 团体字 |

### 3. 访问规则指令表

| 指令 | 作用 | 要点 |
|---|---|---|
| http_access | 控制 HTTP 请求放行 | 顺序敏感，首条命中生效 |
| icp_access | 控制 ICP 查询 | 层级场景使用 |
| cache_peer_access | 控制转发到某邻居 | 配合 cache_peer name |
| http_reply_access | 控制响应放行 | 基于响应属性过滤 |
| acl | 定义命名 ACL | 可被多条规则引用 |

### 4. 认证指令表

| 指令 | 作用 | 说明 |
|---|---|---|
| auth_param | 定义认证方案参数 | basic/digest/negotiate 等 |
| authenticate_cache_garbage_interval | 认证缓存清理间隔 | 性能相关 |
| authenticate_ttl | 认证结果有效期 | 安全与体验平衡 |

### 5. 典型示例

```text
# 配置片段 · squid.conf（访问控制与认证）
acl localnet src 10.0.0.0/8
acl SSL_ports port 443
acl Safe_ports port 80 443 21 1025-65535
acl CONNECT method CONNECT

http_access deny !Safe_ports
http_access deny CONNECT !SSL_ports
http_access allow localnet
http_access deny all

auth_param basic program /usr/lib/squid/basic_ncsa_auth /etc/squid/passwd
acl authenticated proxy_auth REQUIRED
http_access allow authenticated
```

判读要点：先拒绝危险端口与方法，再放行内网，最后 deny all；认证用户规则要放在相应 allow 之前。认证方案的程序路径随发行版不同，需核验。

### 6. 速查表

| 目标 | 指令写法 |
|---|---|
| 只允许内网 | acl + http_access allow/deny |
| 按时间放行 | time 类型 ACL |
| 屏蔽某域名 | dstdomain + http_access deny |
| 要求登录 | auth_param + proxy_auth |
| 限制并发 | maxconn 类型 ACL |

### 7. 版本差异与常见误用

- 认证辅助程序（如 basic_ncsa_auth）在新版本可能改名或独立打包，路径需核验。
- 把 proxy_auth REQUIRED 写成不带 REQUIRED，语义不同。
- ACL 名称区分大小写且有保留名（如 all、localhost），自定义名要避开。

### 8. 小结

访问控制的难点在规则顺序与 ACL 组合逻辑。匹配原理见 `06-07`，类型族详解见 `07-01`。

## 04-04 缓存与存储指令全集

### 1. 本篇定位

覆盖缓存位置、大小、新鲜度与置换相关指令。存储引擎原理见 `06-03`，缓存判定机制见 `06-02`，本篇只列指令。

### 2. 全参数表

| 指令 | 作用 | 典型值 | 要点 |
|---|---|---|---|
| cache_dir | 定义磁盘缓存目录 | ufs /spool 10000 16 256 | 格式：类型 路径 容量MB 一级 二级 |
| cache_mem | 内存缓存上限 | 512 MB | 不含全部内存占用，仅热对象 |
| maximum_object_size | 单对象最大缓存 | 64 MB | 超过不落盘 |
| maximum_object_size_in_memory | 单对象最大内存缓存 | 512 KB | 超过不进内存 |
| minimum_object_size | 单对象最小缓存 | 0 KB | 小于不缓存 |
| refresh_pattern | 定义新鲜度规则 | 见下 | 顺序敏感，支持正则 |
| cache_replacement_policy | 置换策略 | lru / heap GDSF | 依版本 |
| memory_replacement_policy | 内存置换策略 | lru | 依版本 |
| cache_swap_low / high | 缓存清理水位 | 90 / 95 | 达高位触发淘汰 |
| read_ahead_gap | 预读缓冲 | 依场景 | 大对象相关 |
| range_offset_limit | 范围请求处理 | none/大小 | 影响分片缓存 |

### 3. refresh_pattern 详解

refresh_pattern 是缓存新鲜度的核心指令，格式为：

```text
refresh_pattern [-i] regex min percent max [options]
```

| 参数 | 含义 |
|---|---|
| min | 对象至少被视为新鲜的分钟数 |
| percent | 基于 Last-Modified 时间的新鲜度百分比 |
| max | 对象最多被视为新鲜的分钟数 |
| options | override-reload、ignore-reload、reload-into-ims 等 |

### 4. 典型示例

```text
# 配置片段 · squid.conf（缓存与新鲜度）
cache_dir ufs /var/spool/squid 20000 16 256
cache_mem 512 MB
maximum_object_size 64 MB
maximum_object_size_in_memory 512 KB
refresh_pattern -i \.html$ 0 20% 4320 reload-into-ims
refresh_pattern -i \.(gif|jpg|png|css|js)$ 1440 50% 10080 ignore-reload
refresh_pattern . 0 20% 4320
```

判读要点：静态资源给长新鲜度并用 ignore-reload；动态页面给短新鲜度并 reload-into-ims；最后一条兜底。规则顺序敏感，先具体后通用。

### 5. 速查表

| 目标 | 指令 |
|---|---|
| 扩大磁盘缓存 | 调大 cache_dir 容量参数 |
| 提升热点命中 | 调大 cache_mem |
| 缓存大文件 | 调大 maximum_object_size |
| 让某类内容不缓存 | refresh_pattern + 短 max 或 no-cache |
| 强制重新校验 | reload-into-ims 选项 |

### 6. 版本差异与常见误用

- 3.x 中置换策略指令名与取值和 7.x 有差异，核验 `squid.conf.documented`。
- 把 cache_mem 当成总内存上限，实际总占用远高于它（含连接、表项等）。
- refresh_pattern 顺序写反，兜底规则把具体规则覆盖。

### 7. 小结

缓存指令决定「缓存多少、缓存多久、如何淘汰」。机制见 `06-02`、`06-03`。

## 04-05 命令行工具全集

### 1. 本篇定位

覆盖随 Squid 分发的命令行工具，作为手册查表。工具的实现与协议见 `07-08`，本篇只列用法。

### 2. 工具总表

| 工具 | 作用 | 常用参数 |
|---|---|---|
| squid | 主程序与运维入口 | -k、-z、-f、-N、-d、-v |
| squidclient | 客户端请求与管理器查询 | -m、-h、-p、-r |
| cachemgr.cgi | Web 版管理器 | 通过浏览器访问 |
| squid_rotate_logs | 日志轮转 | 配合 cron |
| purger 类工具 | 缓存清除 | 依编译选项 |
| 各类 *_auth | 认证辅助程序 | 依方案 |

### 3. squid 命令详解

| 用法 | 作用 |
|---|---|
| squid -k parse | 校验配置语法 |
| squid -k reconfigure | 重载配置 |
| squid -k rotate | 轮转日志 |
| squid -k shutdown | 优雅停止 |
| squid -z | 初始化缓存目录 |
| squid -f file | 指定配置文件 |
| squid -N | 前台运行 |
| squid -d level | 调试级别 |
| squid -v | 显示版本与编译选项 |

### 4. squidclient 详解

| 用法 | 作用 |
|---|---|
| squidclient -h host -p port URL | 通过代理取 URL |
| squidclient -m info | 查看运行信息 |
| squidclient -m stat | 查看统计 |
| squidclient -m store_queues | 查看存储队列状态 |

### 5. 典型示例

```bash
squid -k parse && squid -k reconfigure
squidclient -h 127.0.0.1 -p 3128 -m info | head -40
squidclient -h 127.0.0.1 -m mgr:storedir
```

判读要点：manager 报告（mgr:xxx）是排障金矿，包含命中率、内存、文件描述符、邻居状态等；`-m info` 的输出中 Squid version 与 Service Times 是关键字段。

### 6. 小结

运维的大部分动作都通过 squid 与 squidclient 完成。输出判读在 `08-02`、`08-03` 展开。

## 04-06 日志与管理指令全集

### 1. 本篇定位

覆盖日志输出与管理接口相关指令。日志字段逐项详解在 `05-05`，管理协议在 `07-05`，本篇只列指令。

### 2. 日志指令表

| 指令 | 作用 | 典型值 |
|---|---|---|
| access_log | 定义访问日志 | /var/log/squid/access.log squid |
| cache_log | 定义缓存/调试日志 | /var/log/squid/cache.log |
| cache_store_log | 存储日志（部分版本） | 依版本 |
| logformat | 自定义日志格式 | 格式串 |
| logfile_rotate | 保留轮转数量 | 10 |
| access_log 的模块名 | 选择日志模块 | squid / stdio / syslog / udp |

### 3. logformat 字段速查

| 字段码 | 含义 |
|---|---|
| %ts | 时间戳（秒） |
| %tt | 完整时间戳 |
| %a | 客户端地址 |
| %ru | 请求 URL |
| %>s | 响应状态码 |
| %Ss | 结果码（如 TCP_HIT） |
| %Bs | 响应字节数 |
| %rm | 请求方法 |
| %un | 用户名 |

### 4. 管理指令表

| 指令 | 作用 |
|---|---|
| cachemgr_passwd | 设置管理器口令 |
| manager 相关 | 控制管理报告访问 |
| snmp_port、snmp_community | SNMP 接口与团体字 |

### 5. 典型示例

```text
# 配置片段 · squid.conf（日志与管理）
logformat myfmt %>a %[ui %[un [%tl] "%rm %ru HTTP/%rv" %>Hs %<st %Ss:%Sh
access_log /var/log/squid/access.log myfmt
cache_log /var/log/squid/cache.log
cachemgr_passwd secret all
```

### 6. 版本差异与常见误用

- 原生日志格式在 6.x 有变化（单行长度限制放宽），旧解析脚本需适配。
- 把敏感信息（用户、URL）写入日志却未做合规评估。
- 忘记给 cachemgr 设口令，管理报告对外暴露。

### 7. 小结

日志是排障的数据源，管理接口是运行时观测入口。字段细节见 `05-05`。

## 04-07 配置排错与速查手册

### 1. 本篇定位

把配置相关的高频问题集中成手册，作为全册速查索引。

### 2. 配置校验流程

| 步骤 | 命令 | 通过标准 |
|---|---|---|
| 语法校验 | squid -k parse | 无错误行 |
| 编译选项确认 | squid -v | 必要特性已启用 |
| 目录检查 | 检查 cache_dir 属主权限 | proxy 用户可写 |
| 重载 | squid -k reconfigure | 日志无报错 |
| 运行观测 | squidclient -m info | 状态正常 |

### 3. 常见错误对照表

| 现象 | 可能原因 | 定位方法 |
|---|---|---|
| 启动失败 | 语法错误/目录缺失 | squid -k parse、看 cache.log |
| 全部拒绝 | http_access 顺序错 | 检查 deny all 是否靠前 |
| 认证不生效 | 辅助程序路径错 | 看 cache.log 认证错误 |
| 命中率为零 | refresh_pattern 或不可缓存 | 看结果码与响应头 |
| 平滑重启无效 | 改动了需重启的指令 | 确认是否 workers 类改动 |

### 4. 指令索引

| 想配置 | 指令 | 篇章 |
|---|---|---|
| 端口 | http_port/https_port | 04-02 |
| 权限 | acl/http_access | 04-03 |
| 缓存 | cache_dir/refresh_pattern | 04-04 |
| 命令工具 | squid/squidclient | 04-05 |
| 日志管理 | access_log/logformat | 04-06 |

### 5. 小结

配置与命令册到此结束。整个 04 是「唯一权威源」，其他册引用指令时都指向这里。下一步进入 `05` 看内部数据结构与日志字段。
