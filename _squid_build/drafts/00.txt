# Squid 技术资料 · 总目录与阅读指南

> **项目**：开源软件 Squid（Squid Web Proxy Cache）技术资料全集
> **版本基准**：Squid 7.x（7.7/7.8，2026），6.x 已于 2025-07 停止维护；不确定的指令名、字段、版本一律标注「需对照实际版本核验」并给出源码定位路径（src/、helpers/）
> **深度标准**：深度技术型，含真实源码路径、数据结构逐字段、调用链、完整配置与命令示例及输出判读
> **图示标准**：全部配图为 Word 原生可编辑形状组（DrawingML）；每张图另附同名 .drawio 源文件；DOCX 内零位图
> **交付形式**：9 个 DOCX（00 总纲 + 8 个维度册），共 65 篇；原 06 技术原理与 07 模块与特性已合并为一册，篇号与图号保持不变；09 统一代理平台架构设计为独立设计蓝图；交付目录不含 .md 文件
> **编号规则**：文件号-篇号（如 06-02）；图号用「文件号-篇号-图序号」（如 06-01-01），与正文引用和图题一致
> **体例来源**：对齐本工作区 VPP 技术资料的 9 册结构与 A/B/C 三类骨架；本套将原理与模块两维度合为一册以便统一修改，篇号体系不变

---

## 1. 为什么这样组织

Squid 是一个「看起来只是一个配置文件、实际上牵动内核、磁盘、TLS、缓存算法和分布式缓存协议」的系统软件。把它们平铺成一本流水账，读者会在「查一个 ACL 写法」和「理解一次缓存命中如何落盘」之间反复跳。因此本套资料按 VPP 已经验证过的思路组织：**先跑起来 → 再懂内核 → 再按模块用起来 → 最后运维**。

这个主线对 Squid 同样成立，但要解决三个真实的结构问题：

| 级别 | 问题 | 具体表现 | 后果 |
|---|---|---|---|
| P1 | 跨册重复 | 同一批指令、字段、机制在 04、06、07、08 中反复出现 | 写作撞车，读者来回跳，约五分之一篇幅冗余 |
| P1 | 骨架一刀切 | 手册型的「配置字典」「字段字典」硬套「背景与动机」「调用链」，非常别扭 | 手册被迫注水，可读性差 |
| P2 | 工具书混在 linear 阅读链里 | 04 配置全集、05 字段字典本质是横向参考手册，却被排成必须顺序读的一章 | 阅读节奏断裂 |

对应的解法就是下面三件事：**唯一权威源去重**、**三类骨架**、**文件号-篇号编号解耦**。

## 2. 唯一权威源（去重铁律）

每一类内容只有一个「说了算」的地方，其他册只引用结论、不重列。

| 内容类型 | 唯一权威源 | 其他册如何处理 |
|---|---|---|
| squid.conf 全指令、命令行工具全集 | 04 全册 | 06 册与 08 只给典型片段并指向 04，不重列指令表 |
| 核心结构体逐字段、access.log 日志字段 | 05 全册 | 06 册写「字段见 05-xx」，不重列表 |
| 机制、调用链、算法原理 | 06 册原理段（06-xx） | 05 及模块段只引用结论，不展开实现 |
| 功能模块与组网行为 | 06 册模块段（07-xx） | 04 只列指令，不讲模块内部原理 |
| 运维判读、压测与故障案例 | 08 全册 | 只讲场景组合与输出判读，不重列命令清单 |

> 交叉引用统一写法：`（配置见 04-02 ｜ 字段见 05-05 ｜ 原理见 06-02 ｜ 模块见 07-02 ｜ 源码见 06-08~06-13 ｜ 能力与方案选型见 06-14~06-22）`。这是本套资料最关键的一条约束，写作时逐篇强制。

## 3. 三类骨架模板

**A 论述型**（01 / 02 / 06 册原理段与模块段 / 08 大部分）
背景与动机 → 核心概念 → 关键结构与源码位置（引用 05，不重列字段）→ 关键流程与调用链（配可编辑架构图）→ 配置/命令/代码示例（引用 04，不重列指令）→ 陷阱与最佳实践 → 小结与延伸阅读。

**B 手册 / 字典型**（04 全册、05 全册）
本篇定位与覆盖范围 → 索引 / 全参数表 → 逐项详解 → 典型示例 → 速查表 → 版本差异 → 常见误用与调试。不写「背景与动机」「调用链」，改「适用场景」「注意事项」。

**C 实战型**（03 全册、08 案例篇）
目标与拓扑（配可编辑拓扑图）→ 前置条件与环境 → 分步操作（每步给命令与预期回显）→ 验证方法与预期结果 → 常见失败与排错 → 小结。

## 6. 各册内容大纲

### 01 基础与概述（4 篇）
- `01-01` Squid 是什么：缓存转发代理概览 — 定位、诞生背景、版本与社区
- `01-02` 正向、反向与透明代理三种形态 — 拓扑对比与选型
- `01-03` 与其他代理 / 缓存软件的架构对比 — Nginx、Varnish、HAProxy、ATS
- `01-04` 整体架构：事件驱动、SMP 与协议栈分层 — 分层架构图

### 02 编译与构建（5 篇）
- `02-01` 编译环境准备：依赖与工具链 — GNU AutoTools、C++、OpenSSL
- `02-02` 从源码完整编译 Squid 实战 — clone → bootstrap → configure → make
- `02-03` configure 选项详解 — 特性开关与依赖探测
- `02-04` 构建系统与源码目录结构 — src/、helpers/、lib/ 分布
- `02-05` 发行版打包与容器镜像 — deb/rpm、Dockerfile 要点

### 03 部署（6 篇，实战型）
- `03-01` 单机部署：目录初始化与最小可用配置 — squid -z、首次启动
- `03-02` 正向代理部署 — 客户端指向与出口缓存
- `03-03` 反向代理加速部署 — accel、vhost 与后端
- `03-04` 透明代理部署 —  iptables/nftables 重定向与拦截
- `03-05` 缓存层级部署 — 父级 / 同级、ICP/HTCP/CARP
- `03-06` 高可用与 SMP 多实例 — workers、进程协作与故障切换

### 04 配置与命令行（7 篇，手册型 · 配置与命令唯一权威源）
- `04-01` squid.conf 配置体系总览 — 语法、include、顺序与生效规则
- `04-02` 网络与监听指令全集 — http_port、https_port、acl 基础
- `04-03` 访问控制与认证指令全集 — acl、http_access、auth_param
- `04-04` 缓存与存储指令全集 — cache_dir、cache_mem、refresh_pattern
- `04-05` 命令行工具全集 — squid、squidclient、cachemgr 等
- `04-06` 日志与管理指令全集 — access_log、logformat、snmp、cachemgr
- `04-07` 配置排错与速查手册 — squid -k parse、错误对照、指令索引

### 05 关键数据结构与日志字段详解（5 篇，手册型 · 字段唯一权威源）
- `05-01` 数据结构总览与阅读方法 — 命名、内存池、头文件定位

- `05-03` 存储条目与缓存索引结构 — StoreEntry、MemObject、store
- `05-04` 对等体与转发结构 — peer、FwdState、Comm::Connection
- `05-05` access.log 日志格式字段详解 — 原生格式逐字段、logformat

### 06 技术原理与模块特性（30 篇，机制与模块唯一权威源）
原 06 与 07 两册已合并为一册，篇号与图号保持不变，交叉引用照旧有效。06-08 起为代码级剖析段，所有文件路径与函数名均对照 Squid 官方源码核实；06-14 起为能力与方案选型段，回答"能做什么、有什么局限、性能如何、能撑多大流量、该怎么选、VPP 能否替代、能否把 Squid 重写为 VPP 插件、HAProxy/mitmproxy 与 Squid 的定位边界，以及出口/SSL-Bump/反向代理的概念辨析"。

原理段：
- `06-01` 事件驱动主循环 — comm、事件调度、异步 I/O
- `06-02` HTTP 缓存机制 — 新鲜度、校验、命中与陈旧

- `06-06` HTTPS 与 SSL-Bump 原理 — peek/splice/bump、证书伪造边界
- `06-07` 认证与访问控制匹配原理 — ACL 组合、认证框架

模块段：
- `07-01` 访问控制与认证模块 — ACL 类型族、basic/digest/negotiate

能力与方案选型段（回答工程选型的九个常见问题）：
- `06-14` 解密之后能做什么 — 三级可见性、能力清单与 `peek` 分流骨架

### 09 统一代理平台架构设计（9 篇，独立设计蓝图）
架构推演而非某软件的能力声明，是 06-18~06-22 选型讨论的收束。核心论点：正向、反向、中间人是同一条数据面上几个决策点的不同取值，单实例可同时承载三角色。
- `09-01` 目标、角色模型与单实例多角色 — 角色属于连接而非进程，多端口共存
- `09-02` 六层数据面架构 — 接入/TLS/HTTP/策略/缓存/上游，横向能力
- `09-03` 三个决策点与角色取值 — 入口、TLS、上游的取值矩阵
- `09-04` 多角色共存的五个硬约束 — 角色标记、双轨证书、ACL 命名空间、缓存池、日志打标
- `09-05` 快路径与慢路径的物理隔离 — 隔离模型、背压降级、bump 比例
- `09-06` 难点排序与风险 — TLS 状态机、协议演进、合规边界
- `09-07` 落地路线与自建判断 — 组合式、轻量插件、全自研三条路线
- `09-08` 与加密隧道类工具的边界 — 可观测与抗观测，Shadowsocks/V2Ray 的定位差异与合规边界
- `09-09` 三类工具的分层边界 — WireGuard（L3 VPN）、应用代理、网关代理的分层、拓扑与合规差异

## 7. 配图、表格与示例约定

### 7.1 配图
每张图在 DOCX 中是一个 Word 形状组，可逐个元素编辑；同名 .drawio 源文件放在 figures/。图题统一为「图 <图号> <图名>（可编辑 · 附 draw.io 源文件）」，正文引用、图题、文件名三者编号一致。

### 7.2 表格
全部为 Word 原生表格。单元格内不塞超长命令；需要完整命令时在表后给代码块，单元格写「见下方示例」。

### 7.3 示例
代码块上方有类型标签（命令示例 · Shell / 配置片段 · squid.conf / 输出示例）。完整示例按「命令/配置 → 典型输出 → 中文判读」三件套组织。不确定的指令语法、字段名、版本不编造，统一写「需对照实际版本核验」并给出可定位路径。

## 8. 状态与边界

本总纲与八册正文（原原理、模块两册已合并，另含 09 统一代理平台架构设计）构成 VPP 体例对齐的完整资料集。Squid 版本差异较大（3.x 到 7.x 指令增删频繁），凡涉及版本敏感处均标注核验提示；本套资料不替代官方 squid.conf.documented 与源码，而是帮助读者建立体系化认知并快速定位。
