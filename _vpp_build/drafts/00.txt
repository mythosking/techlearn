> **项目**：开源软件 VPP（Vector Packet Processing / fd.io）技术资料全集
> **版本基准**：VPP 23.06 / master；不确定的字段名、CLI 语法、版本号一律标注「需对照实际版本核验」并给出源码定位路径
> **深度标准**：深度技术型，含真实源码路径、数据结构逐字段定义、调用链、完整命令示例与输出判读
> **图示标准**：全部配图为 **Word 原生可编辑形状组**（DrawingML）；每张图另附同名 `.drawio` 源文件，可用 draw.io 打开继续编辑；DOCX 内零位图
> **交付形式**：**9 个 DOCX**（00 总纲 + 8 个维度册），共 **72 篇**；交付目录不含 `.md` 文件
> **编号规则**：`文件号-篇号`（如 `06-03`）；图号用 `文件号-篇号-图序号`（如 `06-01-01`），与正文引用和图题一致
> **当前状态**：**已完稿交付** · 72 篇齐全 · 87 张可编辑图（8 册 86 张 + 本册 1 张）· 282 张原生表格 · 229 个带类型标签的示例
> **最后更新**：2026-11-10（交付版）

## 1. 结构评审结论

**结论：主线合理，但需要优化。** 「先跑起来 → 再懂内核 → 再按模块用起来 → 最后运维」这条主线，以及按维度分文件的交付形式，对 VPP 这类系统软件是合适的。但作为一套 70 篇的资料集，v1 存在以下会真实影响写作与阅读的结构性缺陷：

| 级别 | 问题 | 具体表现 | 后果 |
|---|---|---|---|
| **P1 严重** | **跨文件重复** | 见下方「重复对照表」。同一批结构体 / 命令在 04、05、06、07、08 中反复讲 | 写作时必然撞车，读者来回跳；约 1/5 篇幅是冗余 |
| **P1 严重** | **骨架一刀切** | v1 要求全部 70 篇套同一套 7 段式（背景→概念→数据结构→调用链→配置示例→陷阱→小结）。字段字典、命令速查这类**手册型**篇目硬套「调用链」「背景与动机」非常别扭 | 手册类篇目会被迫注水，可读性差 |
| **P2 中等** | **全局连续编号脆弱** | `01–70` 全局编号：中间插一篇或删一篇，后面所有篇号、文件名清单、本文件的表格、正文里的交叉引用全部要改；提纲仍在迭代期 | 每次调整都要全量重排（前两轮已发生两次） |
| **P2 中等** | **工具书混在线性阅读链路里** | `05 字段详解`、`04 命令全集` 本质是**横向参考手册**，却被排成必须顺序阅读的一章；读者刚学完配置命令就要啃 12 篇结构体 | 阅读节奏断裂，容易被劝退 |
| **P3 次要** | **维度缺口** | 缺「控制面 / API 集成」「性能基准与压测方法学」「常见故障案例库」「端到端实战案例」四块 VPP 落地必备内容 | 资料偏「说明」，缺「怎么用与怎么验证」 |

## 2. 优化动作（v1 → v2）

### A1 建立「唯一权威源」去重规则（解决 P1，核心改动）

| 内容类型 | **唯一权威源** | 其他文件如何处理 |
|---|---|---|
| 结构体**逐字段定义** | **05 全册** | 06 / 07 只写「字段含义见 `05-xx`」，**不重列字段表** |
| **CLI 命令与 startup.conf 全参数** | **04 全册** | 07 每篇只给本模块典型配置片段 + 指向 `04-xx`；08 讲命令组合与结果判读，**不重列命令清单** |
| **机制、调用链、流程** | **06 全册** | 05 / 07 只引用结论，不展开实现原理 |
| **功能模块与组网行为** | **07 全册** | 04 只列命令，不讲模块内部原理 |

> 交叉引用统一写法：`（字段见 05-04 ｜ 命令见 04-05 ｜ 原理见 06-09）`。这条规则会写进每个撰写任务，是本次优化最关键的一条。

### A2 骨架分三类（解决 P1）

不再全册强制一套骨架，按篇目性质选用（详见第 6 节）：

- **A 论述型**：原理、概述、模块、方案类 → 沿用 v1 的 7 段式
- **B 手册 / 字典型**：04 全册、05 全册、速查表类 → 「定位 → 索引 / 全参数表 → 逐项详解 → 示例 → 速查 → 版本差异 → 常见误用」
- **C 实战型**：部署、案例、排障实操 → 「目标与拓扑 → 前置条件 → 步骤 → 验证 → 排错 → 小结」

### A3 编号解耦（解决 P2）

`文件号-篇号`，如 `06-03`。插删篇目只影响本文件内部，00 文档只维护「文件 → 篇数」总览，不再维护 70 行连续编号映射。

### A4 05 定位为「工具书」（解决 P2，**位置不变**）

保留已确认的排序（`05` 在技术原理之前），但明确它是**随查手册**：推荐先只读 `05-01 数据结构总览`，其余 11 篇在进入 06 / 07 遇到具体结构体时回查；阅读路径图用虚线标注「回查」，不再是必须顺序读完的一章。

### A5 补齐缺口（解决 P3，净增 2 篇）

- `04-07` 由「VPP API 与配置持久化」扩写为 **「控制面与 API 集成、配置持久化」**，补 govpp / Honeycomb / VCL 编程 / 事件订阅。
- `08` 由 4 篇扩为 6 篇，新增 **`08-01 性能基准与测试方法学`**、**`08-04 常见故障案例库`**。
- **总篇数 70 → 72，文件数仍 8 个**。因 A1 去重，实际总字数不会等比增加。
- 另留一个**可选建议**：新增 `09_端到端实战案例.docx`（约 5 篇），见第 10 节，由用户决定是否要。

## 6. 三类骨架模板

**A 论述型**（01 / 02 部分 / 06 / 07 / 08 部分）
背景与动机 → 核心概念 → 关键数据结构与源码位置（**引用 05，不重列字段**）→ 关键流程与调用链（配可编辑架构 / 流程图）→ 配置 / 命令 / 代码实例（**引用 04，不重列命令；示例含命令 + 预期输出 + 判读**）→ 陷阱与最佳实践 → 小结与延伸阅读。

**B 手册 / 字典型**（04 全册、05 全册）
本篇定位与覆盖范围 → **索引 / 全参数表**（一眼看全）→ 逐项详解 → 典型示例 → 速查表 → 版本差异 → 常见误用与调试。
- 05 的逐项详解统一用字段表：`字段 | 类型 | 含义 | 头文件/位置 | 读写时机 | 关联函数与流程 | 版本差异`
- 04 的逐项详解统一用命令表：`命令 | 语法 | 参数 | 作用 | 对应 API | 示例 | 版本差异`
- 不写「背景与动机」「调用链」，改为「适用场景」「注意事项」

**C 实战型**（03 / 08 案例 / 可选 09）
目标与拓扑（配可编辑拓扑图）→ 前置条件与环境 → 分步操作（每步给出命令与预期回显）→ **验证方法与预期结果** → 常见失败与排错 → 小结。

## 7. 去重与引用约束（撰写时强制）

1. 06 全册、07 全册、08 全册：**禁止**出现完整结构体字段表，改为 `（字段见 05-xx）`。

5. 05 全册：**禁止**展开机制流程，只讲字段含义、内存布局、生命周期、关联函数入口。
6. 所有交叉引用使用 `文件号-篇号`，不使用全局序号；引用目标不存在时在本文件登记，由 00 统一补齐。

## 11. 配图、表格与示例约定（交付版）

### 11.1 配图

- 每张图在 DOCX 中是一个 **Word 形状组**（`msoGroup`）：单击选中整组，再单击一次即可单独选中某个框、连线或标签，直接改文字、拖动位置、改填充色。不是图片，也不含任何位图。
- 每张图在 `figures/` 下有 **一份同名 `.drawio` 源文件**，文件名以图号开头，例如 `06-01-01_xxx.drawio`。需要重排布局、复用图形或导出 SVG / PNG 时，用本机 draw.io 打开该文件即可。
- 图题格式统一为 `图 <图号>  <图名>（可编辑 · 附 draw.io 源文件）`；正文里的引用（如「见图 06-01-01」）、图题、`.drawio` 文件名三者编号一致。
- 图形在版心内自动分层布局：同层节点过多时折行，超宽或超高时整体等比缩放并同步缩小字号（不低于 7pt），保证每张图完整落在单页内。
- 内容源与构建脚本不随交付目录提供；交付目录只放 `.docx` 与 `figures/*.drawio`。

### 11.2 表格

- 全部表格是 Word 原生表格（可增删行列、改列宽、套用表格样式），不是截图。
- 表格单元格里出现的 shell 管道符或命令语法里的「或」，在内容源里写作转义形式，避免被解析成列分隔导致错列。
- 过长的命令串不塞进单元格：表格内给语义化简述，完整命令放在表格后的代码块里，单元格写「见下方命令示例」。

### 11.3 示例

- 每个代码块上方有一行类型标签，如「命令示例 · Shell」「代码片段 · C」「配置片段 · startup.conf」「输出 / 文本示例」「目录结构」。
- 完整示例按三件套组织：**可执行命令 / 代码 → 典型输出 → 中文判读**（关键字段含义、正常值范围、异常特征、排除路径）。
- 不确定的 CLI 语法、生成头文件命名、结构体字段名、LTS 版本清单不编造，统一写「需对照实际版本核验」并给出可定位的源码路径或头文件。
- 交叉引用遵守唯一权威源：结构体字段查 05、配置与命令查 04、机制与调用链查 06、模块功能与组网查 07、运维判读与案例查 08。
